EarthOrbit 1.2.0 Release Notes

Version: 1.2.0
Build: 5d582af5ad3e
Date: 2026-09-16

Release Status

Version 1.2.0 adds a complete command-line interface and a quantitative, scenario-aware console summary. The two force laws, fixed-step integration algorithm, stored trajectory arrays, and plot are unchanged. Students can now perform every parameter-only exercise without editing main.py.

Command-Line Interface

  • Added options for all six run settings: --h0, --uInit, --vInit, --dt, --maxSteps, and --force_law.
  • Documented each setting in the main.py module description and in python main.py --help.
  • The force-law selector explains both alternatives: simplified keeps the acceleration magnitude at 9.8 m/s² and continually redirects it toward Earth's centre; inverse_square uses MU_EARTH/r² and supports Keplerian elements and escape.
  • Audited every defaulted driver argument. return_diagnostics is intentionally not a command-line option because it controls the Python return format rather than the physical run. main.py enables it internally to calculate the console summary.
  • Invalid values are converted to concise EarthOrbit: ... messages instead of Python tracebacks.

Quantitative Console Summary

All reported real numbers are formatted to five significant digits.

  • Trajectories that do not complete a revolution report the fraction of a revolution, total flight time, total angular travel, interpolated maximum altitude, and total path distance.
  • Surface impact is located by intersecting the final straight trajectory segment with the Earth circle. The interpolated point is used for time, angle, and distance without altering the raw arrays or plot.
  • Trajectories completing at least one revolution report the number of full revolutions, total flight time, total angular travel, and—separately for every completed revolution—its interpolated duration, minimum altitude, and maximum altitude.
  • Angular revolution boundaries are linearly interpolated. Interior altitude extrema use a local three-point parabola when its vertex lies inside the surrounding interval.
  • Inverse-square runs report osculating eccentricity and perigee altitude. Bound trajectories also report apogee altitude. An unbound trajectory has no apogee and instead reports its final altitude when maxSteps is reached.
  • When an escape trajectory's final altitude is also its maximum altitude, the output combines them into one line rather than printing the same concept twice.

Documentation Updates

  • Reworked the Help Parameters section around command-line options and identified return_diagnostics as a Python-API-only switch.
  • Expanded the Output section to distinguish impact, incomplete, completed orbit, bound inverse-square, and escape summaries.
  • Converted parameter-only Suggested Experiments to runnable command-line examples. Exercises that compare multiple runs, compute impact coordinates, or inspect energy histories retain Python starter code.
  • Updated the Sample Outputs Guide with Version 1.2.0 commands and console results while preserving figures whose underlying physics and plotted data are unchanged.

Scientific Scope Retained

  • The default simplified model retains the textbook values g = 9.8 m/s² and R_EARTH = 6,378,200 m.
  • The optional inverse_square law retains the JPL DE440 value MU_EARTH = 3.98600435507e14 m³/s².
  • The fixed-step algorithm still evaluates acceleration at the start of each step, advances velocity, and advances position with the old/new velocity average. It is not a symplectic orbit integrator.
  • The ordinary four-array driver return remains unchanged. Direct Python callers can still request aligned time and velocity arrays with return_diagnostics=True.

Regression Coverage

The expanded suite covers the existing physics, validation, integration, plotting, architecture, Python 3.10, and Build-ID contracts plus command-line default synchronization, help text, impact interpolation, exact five-digit formatting, per-revolution reporting, circular osculating elements, escape classification, and final-altitude output. Tests are run from the tests/ directory and locate the adjacent documentation artifact without requiring a flattened copy.

Known Limitations

  • The default constant-magnitude force is a near-surface teaching approximation. Keplerian elements and escape have physical meaning only with --force_law inverse_square.
  • The console's osculating elements are derived from the initial state. The simple numerical integrator can drift away from those ideal two-body values, especially at large dt; the reported per-revolution altitude extrema describe the numerical trajectory actually calculated.
  • Impact interpolation treats the last numerical segment as straight. Angular crossings are linearly interpolated. Both converge as dt is reduced but do not turn the underlying integrator into a high-accuracy orbit solver.
  • Five-significant-digit display supports comparisons and does not imply that the physical model or numerical method is accurate to five significant digits.
  • The red plotted curve deliberately retains the first sample inside Earth after impact even though the console summary stops at the interpolated surface crossing.
  • The simulation is two-dimensional and omits atmosphere, drag, Earth rotation, oblateness, third-body forces, and station-keeping.

EarthOrbit 1.1.1 Release Notes

Version: 1.1.1
Build: 77b768d3a136
Date: 2026-08-30

Release Status

Version 1.1.1 reflects the EarthOrbit kickoff maintenance review followed by three rounds of independent review involving Codex, Copilot, and Gemini. The review process examined the Python implementation, the default constant-magnitude central-gravity model, the optional inverse-square extension, numerical integration, validation and error handling, plotting, Help-file accuracy, Version/Build synchronization, Python 3.10 grammar compatibility, and regression coverage. Audit2 reported no release-blocking executable-code defect, and the Audit3 Copilot review likewise found no release-blocking executable defect. Audit3 identified one definite low-severity Help wording issue and several low-severity test-maintenance items that remain suitable for follow-up maintenance.

Major Improvements in This Release

  • Preserved Schutz's educational EarthOrbit model in which gravity has constant magnitude g while always pointing toward Earth's centre, with acceleration evaluated at the beginning of each step and position advanced using the average of the old and new velocities.
  • Retained an optional inverse_square force law for higher-altitude and Keplerian experiments, using the JPL DE440 Earth gravitational parameter MU_EARTH = 3.98600435507e14 m^3/s^2.
  • Hardened compute_acceleration() for extreme finite positions, invalid inputs, the Earth-centre singularity, non-finite results, and unrepresentably large inverse-square acceleration, including explicit OverflowError-to-ValueError translation.
  • Expanded driver validation for launch parameters, timestep, maxSteps, force-law selection, diagnostic-output selection, impossible allocations, and non-finite integrated states.
  • Added optional diagnostic time and velocity arrays for period, energy, and convergence experiments while preserving the original four-array return interface by default.
  • Hardened plotting so trajectory and Earth-surface coordinates must be numeric, finite, one-dimensional, nonempty, and paired with matching lengths; the plotter also returns its matplotlib Figure and Axes objects.
  • Added reproducible Version/Build identification across the four executable modules. The Help and command-line output identify Version 1.1.1, Build 77b768d3a136.
  • Clarified the Help distinction between the simplified constant-magnitude model and the inverse-square model, including appropriate circular-speed, escape-speed, energy, and higher-altitude guidance.
  • Expanded the Help to ten progressively ranked experiments covering circular speed, launch-speed sensitivity, force-law comparison, impact interpolation, radial velocity, elliptical orbits, geostationary altitude, escape, Kepler's third law, and energy/convergence analysis.
  • Reworked EXP-9 and EXP-10 as explicitly labeled runnable starter code so the supplied blocks execute while leaving the advanced analytical steps to the student.

Test Suite Growth

The regression suite grew from 62 tests at kickoff to 66 tests after the Audit2 response. It defines the four core module filenames and uses find_module_dir(start) so the same test file supports both the canonical tests/ layout and a flattened upload layout beside the program modules.

The suite covers module discovery; Version/Build compatibility; Python 3.10 parsing; architecture boundaries; physical constants; both acceleration laws; invalid, huge, and tiny-radius inputs; driver validation and allocation failures; first-step calculations; legacy default-trajectory behavior; Earth-circle construction; stored-point semantics; diagnostics; force-law forwarding; inverse-square energy convergence; full-period orbital recovery; plotting validation and presentation; command-line execution; and Help-file structure and scientific/documentation contracts. Codex reported all 66 tests passing in both canonical and flattened layouts after the Audit2 changes.

Known Limitations

  • The default force law is a pedagogical near-surface approximation with constant acceleration magnitude g; it is not a realistic global model of terrestrial gravity.
  • The fixed-step averaged-velocity integration method is not velocity Verlet/leapfrog and is not generally symplectic. Numerical error accumulates for position-dependent gravity, so quantitative experiments should be repeated with smaller timesteps to check convergence.
  • Surface impact is detected only after a stored point has moved below the reference Earth radius. The driver does not interpolate the exact surface crossing, so the final plotted point of an impact trajectory may lie slightly inside Earth.
  • maxSteps counts stored trajectory points, including the initial point, and therefore permits at most maxSteps - 1 integration updates.
  • The inverse-square extension models idealized two-dimensional central gravity. The Help notes that the geostationary-altitude experiment reproduces the associated orbital period but does not model Earth's rotation or station-keeping.
  • The Help file loads MathJax from a public CDN. Without access to that resource, the Python program still runs, but Help equations may appear as unrendered TeX.

Known Minor Maintenance Items

  • The Help Output section currently describes the Earth surface as “401 evenly spaced points.” The driver actually stores 400 evenly spaced angular samples and then repeats the first point as coordinate 401 to close the curve. This wording should be corrected in a future documentation update.
  • The tests execute selected Help snippets in fresh namespaces but within the main test process. Subprocess isolation with timeouts would provide stronger protection against future snippets that alter module or library state.
  • The EXP-9 and EXP-10 starter-block assertions could be strengthened with explicit finite-output checks; EXP-9 could additionally verify monotonic accumulated angular travel for its first-2π-crossing exercise.
  • The full-period regression comment describes its numerical tolerance as a “cross-platform margin,” although the supplied review evidence records a margin above the Version 1.1.1 baseline rather than measurements across multiple platforms.
  • The full-period test combines convergence-order checks with Version 1.1.1 absolute-error baselines. Separating those concerns would make future failures easier to diagnose.
  • Claims about Orbit, RelativisticOrbit, Binary, and Atmosphere in Related Programs remain awaiting independent cross-module verification because those companion artifacts were not included in the EarthOrbit audit package.
