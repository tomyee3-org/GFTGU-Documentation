CannonTrajectory 1.1.0 Release Notes

Version: 1.1.0
Build: b96e71693112
Date: 2026-08-30

Release Status

Version 1.1.0 concludes a kickoff scientific review followed by three rounds of independent adversarial review involving Codex, Copilot, and Gemini. Reviewers verified the projectile-motion equations, Euler and improved-Euler integrators, input validation, numerical-overflow handling, plotting behavior, Help-file accuracy, Version/Build synchronization, flattened-layout execution, and regression coverage. All Audit2 findings were corrected, both Audit3 reviewers reported no remaining defects, and no release-blocking issue remains. CannonTrajectory is cleared for release as an instructional implementation of constant-gravity projectile motion.

Major Improvements in This Release

  • Updated the gravitational constant from the textbook-rounded g = 9.8 m/s² to the conventional standard value g = 9.80665 m/s², with corresponding updates to all documented analytic results and examples.
  • Preserved Schutz's original constant-gravity, no-drag projectile model while adding a direct comparison between forward Euler and improved Euler (Heun) integration.
  • Added robust validation for invalid parameter types and values, including nonnumeric inputs, invalid launch angles, invalid timesteps, invalid methods, and insufficient max_steps values.
  • Added controlled handling for extreme finite Real inputs that cannot be represented as Python floating-point values, producing explanatory exceptions instead of uncaught conversion failures.
  • Added numerical overflow and invalid-state detection so trajectories containing non-finite values raise a descriptive FloatingPointError rather than returning corrupted results.
  • Replaced trajectory preallocation with append-only storage, ensuring that max_steps functions as a true safety ceiling rather than an implicit memory-allocation request.
  • Retained Schutz's pedagogically useful first-below-ground-point behavior, allowing students to investigate timestep effects and landing-point interpolation.
  • Added plot_cannon_overlay(), allowing multiple trajectories to be displayed on one figure for launch-angle comparison experiments while preserving the existing single-trajectory plotting interface.
  • Hardened plotting against malformed overlay input and ensured that partially constructed figures are cleaned up automatically if plotting fails.
  • Expanded and clarified the Help documentation, including improved discussion of integration error versus sampling error, trajectory overlays, interpolation of ground crossings, and exact-ground landing behavior.
  • Added reproducible BUILD_ID generation covering exactly the four executable core modules: physics_cannon.py, driver_cannon.py, main.py, and plot_cannon.py. The Build identifier is synchronized across runtime output, source code, documentation, and regression tests.

Test Suite Growth

A new regression suite was created during kickoff and expanded through three audit rounds. The final suite contains 63 automated tests. The suite defines the four executable module filenames explicitly and uses find_module_dir(start) to locate the nearest directory containing the core modules, allowing the same tests to operate from either the canonical tests/ layout or a flattened upload layout.

The final suite verifies physics constants and analytic solutions; Euler and improved-Euler integration behavior; numerical convergence; trajectory structure and landing behavior; interpolation accuracy; complementary launch angles; speed-squared range scaling; parameter validation; overflow detection; large finite-Real edge cases; plotting behavior; overlay plotting; malformed input cleanup; Help-file structure and synchronization; Version/Build consistency; Python 3.10 grammar compatibility; flattened-layout execution; and independent BUILD_ID reproduction. All 63 tests pass.

Known Limitations

  • The model assumes constant gravitational acceleration and neglects air resistance. It is intended for introductory numerical experiments rather than high-accuracy ballistic prediction.
  • The trajectory terminates at the first sampled point below ground rather than the exact landing point. Accurate range estimates should use interpolation between the final non-negative and first negative height samples.
  • Because the simulation uses a fixed timestep, the reported landing position depends partially on sampling resolution. Smaller timesteps reduce this sampling error.
  • The improved-Euler method reproduces the analytic sampled solution for this special constant-acceleration problem. Its exceptional accuracy here should not be interpreted as representative of all differential-equation systems.
  • The program models launches from ground level only. It does not currently include an adjustable initial height.
  • The Help file loads MathJax from a public CDN. When offline, documentation remains readable but mathematical expressions are displayed as raw TeX source rather than rendered equations.

Known Minor Maintenance Items

  • The BUILD_ID intentionally excludes documentation and regression tests. Documentation or test-only updates therefore do not alter the executable build identifier.
  • Help-file synchronization relies on structural regression tests that compare documented defaults, experiment metadata, and Version/Build identifiers against the executable program. Future documentation edits should preserve this synchronization.
  • The overlay plotting interface currently accepts trajectories using the documented (label, xs, hs) format. Future plotting extensions should maintain compatibility with existing experiments and tests.
