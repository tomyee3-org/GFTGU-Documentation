All figures were generated by this build using an 8000 accepted-step excerpt. Run the listed commands from the Multiple directory; omitting --max_steps restores the 60000-step default. The five images are embedded in this file.

Figure 1 — Three-body trajectories in COM display

python main.py --max_steps 8000 --output_type trajectories

Input coordinates determine all dynamics. The plot subtracts the instantaneous center of mass only to draw the paths. The title identifies the COM display frame. Maximum fractional energy drift: 3.2235e-04.

Figure 2 — Bulk velocity, user versus COM display

python main.py --max_steps 8000 --output_type trajectories --display_frame user --velocities_init '100000,0,0;100000,-30000,0;70000,0,0'
python main.py --max_steps 8000 --output_type trajectories --display_frame com --velocities_init '100000,0,0;100000,-30000,0;70000,0,0'

Each body receives a 100000 m/s boost in x. Left: original input coordinates; right: COM display of the same relative orbits. Initial scaled P = (2.7000e+05, -3.0000e+04, 0) m/s; the original state already had nonzero momentum. E_internal removes translational kinetic energy.

Figure 3 — Accepted-step energy drift

python main.py --max_steps 8000 --output_type trajectories --show_energy_diagnostic

This chart uses accepted integration states. Reducing the maximum timestep is useful for checking close-encounter numerical error.

Figure 4 — Animation still

python main.py --max_steps 8000 --output_type animation --animation_mode trails --display_frame com

The title identifies the COM display frame; the image shows simulated time, frame number, and the body legend. Press F to toggle COM and user display; the title updates. The eleven console samples below use dense accepted-step diagnostics, independent of animation frame spacing.

Figure 5 — Out-of-plane xz projection

python main.py --max_steps 8000 --output_type trajectories --projection xz --velocities_init '0,0,0;0,-30000,0;-30000,0,5000'

A 5000 m/s z component on the third body produces visible vertical motion. COM display preserves relative separation while moving the plotted origin.

Model boundaries

The solver treats stars as Newtonian point masses without collision radii, tides, gas, or relativity. COM only affects what is drawn. A short run or a changed set of parameters alone cannot determine binary hardening or reproduce another program's prescribed-orbit physics.
