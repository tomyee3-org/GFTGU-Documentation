Representative Sample Outputs

Version 1.4.0  |  Build 412f37f02fdc  |  Updated 24 September 2026

Purpose. One figure for each Beat of the Multiple Beats Help, in Beat order, for an instructor reading alongside it. Each section gives the exact command, the plot it produces, and the values the program prints. No external image files are required.

In every trajectory figure, each colored line is one body's path and the matching marker (where shown) is a body's current position. Coordinates are heliocentric-style metres in the requested display frame; both axes use the same scale. Figures 4 and 9 show the fractional total-energy drift (E−E0)/|E0| against simulated time instead of a spatial path.

Figure 1 — Beat 0 · Many bodies, one force law

python main.py --max_steps 8000 --output_type trajectories

The default three-body scenario, in COM display: three roughly solar-mass stars spend most of the run drifting apart, then two of them pass close to each other late in the run.

What it shows

  • Three trajectories (Body 1 red, Body 2 green, Body 3 blue) trace increasingly curved paths as gravity pulls all three together.
  • The plot subtracts the instantaneous center of mass only for display; the title names the COM frame explicitly.
  • Near the end of the run, two bodies swing unusually close to one another — the tight loop that Beats 3, 6 and 8 all return to.

Headline values

  • Multiple 1.4.0 (build 412f37f02fdc) — accepted steps: 8000; simulated time: 1.8094e+01 days
  • Initial and final E: −4.6226e+09 m2/s2 (agree to four printed digits)
  • Maximum conservation drift: energy=3.2235e-04, momentum=6.8454e-14, angular momentum=3.7074e-06

Figure 2 — Beat 1 · Every body answers to every other

Unequal masses (2, 1 and 0.5 solar masses) make the heaviest body move the least and the lightest move the most, over a shorter 2000-step run.

  • This run ends at 2000 accepted steps, before reaching the deep encounter Beat 0's longer run reaches (Beat 6 returns to this point).
  • Evaluating Eq. 2 directly at the launch positions gives each body's initial acceleration, independent of the plotted path.

Figure 3 — Beat 2 · Momentum, boosts, and two display frames

python main.py --velocities_init "100000,0,0;100000,-30000,0;70000,0,0" --max_steps 2000 --output_type trajectories --display_frame user

In the user (input-coordinate) display frame, a large constant total momentum carries the whole three-body system across the plot as it evolves.

What it shows

  • All three bodies drift together toward the upper right; the same run's --display_frame com counterpart would show only the relative motion, without this bulk drift.
  • Total momentum P=(2.7000e+05, -3.0000e+04, 0.0000e+00) m/s is large and unchanged, to machine precision, from start to end.
  • Total energy E is dominated by this bulk kinetic energy and differs sharply from the boost-independent E_internal.

Headline values

  • Multiple 1.4.0 (build 412f37f02fdc) — accepted steps: 2000; simulated time: 1.5410e+01 days
  • E=7.3774e+09 m2/s2 versus E_internal=-4.9226e+09 m2/s2
  • Maximum conservation drift: energy=4.4468e-06, momentum=2.5717e-15, angular momentum=5.2362e-06

Figure 4 — Beat 3 · Energy, internal energy, and angular momentum

python main.py --max_steps 8000 --output_type trajectories --show_energy_diagnostic

The same default run as Figure 1, with --show_energy_diagnostic added: the fractional total-energy drift stays tiny for most of the run, then spikes during the close encounter near day 17.5.

What it shows

  • The line is essentially flat and near zero until roughly day 13, then swings sharply up and down around the close encounter, settling back down before the run ends.
  • The printed initial and final E and E_internal agree to four digits despite this real mid-run excursion, because neither endpoint falls near the spike.
  • Angular momentum L stays fixed at the digits shown throughout, unaffected by the frame or the encounter.

Headline values

  • Initial/final E=-4.6226e+09, E_internal=-4.9226e+09 m2/s2 (agree to four digits)
  • Maximum conservation drift: energy=3.2235e-04 — the spike visible in the figure
  • L=(0.0000e+00, 0.0000e+00, 2.7600e+15) m2/s, constant to the digits shown

Figure 5 — Beat 4 · When a conserved total is (almost) exactly zero

python main.py --n_bodies 2 --masses_solar 1,1 --positions_init "5e10,0,0;-5e10,0,0" --velocities_init "0,25760,0;0,-25760,0" --max_steps 3000 --output_type trajectories

Two equal-mass bodies launched with exactly opposite momenta trace a near-perfectly circular two-body orbit, with total momentum exactly zero by construction.

What it shows

  • Body 1 (red) and Body 2 (green) trace matching circular arcs on opposite sides of the shared center of mass.
  • Total momentum P=(0,0,0) m/s exactly, both initial and final, because the two launch momenta exactly cancel.
  • Because the initial total momentum is exactly zero, the drift-normalization scale falls back to the run's characteristic momentum rather than dividing by zero.

Headline values

  • Multiple 1.4.0 (build 412f37f02fdc) — accepted steps: 3000; simulated time: 6.9444e+01 days
  • Maximum conservation drift: energy=7.3867e-11, momentum=0.0000e+00, angular momentum=3.6934e-11
  • momentum_drift_normalization=characteristic_scale (51520.0); angular_momentum_drift_normalization=initial_norm (2576000000000000.0)

Figure 6 — Beat 5 · The predictor–corrector, body by body

python main.py --max_steps 8000 --output_type trajectories --eps2 1e-10

Tightening the corrector tolerance eps2 by three orders of magnitude from its default leaves this plot visually identical to Figure 1's default-tolerance run.

What it shows

  • The path is the same default three-body scenario as Figures 1 and 4; at this scale, an eps2 three orders of magnitude tighter than the default changes nothing visible.
  • The reported maximum energy drift barely moves between eps2=1e-10 (this figure) and the default eps2=1e-7 (Figure 1): both round to 3.2235e-04.
  • Loosening eps2 instead, to 0.004, raises the maximum only slightly, to 3.2339e-04 — eps2 is not the limiting factor at any of these settings.

Headline values

  • eps2=1e-10: Maximum conservation drift: energy=3.2235e-04, momentum=6.3150e-14, angular momentum=3.7074e-06
  • eps2=0.004 (looser, not pictured): energy=3.2339e-04, momentum=4.5558e-14, angular momentum=3.7125e-06
  • Default eps2=1e-7 (Figure 1): energy=3.2235e-04

Figure 7 — Beat 6 · The adaptive timestep, worst body first

The same default scenario as Figure 1, cut off at 6000 accepted steps — already enough to reach the close encounter that collapses the adaptive step from 2000 s toward 0.2285 s.

What it shows

  • The path already shows the same tightening loop as Figure 1's close encounter, reached well before this run's 6000-step limit.
  • For the first 425 accepted steps, every step uses the full 2000 s ceiling; by step 5247 (within this run) the working step has collapsed to 0.2285 s.
  • Cut short at 6000 steps rather than 8000, this run's printed final E differs from its initial value in the last printed digit, unlike Figure 1's full run.

Figure 8 — Beat 7 · Trajectories, animation, and uniform time

The last of 31 uniformly time-spaced animation frames from the same two-body orbit as Figure 5, captured as a still image since a playing animation cannot be embedded here.

What it shows

  • Requesting a shorter run of this same setup changes the frame count roughly in proportion: 600 steps gives 7 frames (0.35 s playback); 2000 steps gives 21 frames (1.05 s); this 3000-step run gives 31 frames (1.55 s).

Figure 9 — Beat 8 · How far to trust it

python main.py --dt 1000 --max_steps 4000 --output_type trajectories --show_energy_diagnostic

The coarser of Beat 8's two main comparison runs (dt=1000 s): its own reported maximum drift is much smaller than the dt=500 s run's, but only because this run stops earlier, before the sharpest part of the encounter.

What it shows

  • This run's drift climbs gently through most of the plot and is still rising, not yet spiking, when the run ends at day 17.559 — short of the sharp close pass near day 17.593 that a longer run reaches.
  • Compared over the first 17.5 days both this run and a finer dt=500 s run actually share, the two settings agree closely: 7.0649e-6 against 7.1182e-6.
  • Extending this same dt=1000 s run by 2000 more accepted steps (not pictured) reaches the same close pass and matches the finer run's own peak to within two parts in a thousand.

Headline values

  • Multiple 1.4.0 (build 412f37f02fdc) — accepted steps: 4000; simulated time: 1.7559e+01 days
  • Maximum conservation drift: energy=1.7950e-05 — this run's own maximum, the figure's visible peak
  • Common 17.5-day window: 7.0649e-6 (dt=1000, this run) versus 7.1182e-6 (dt=500, not pictured)

Notes for evaluation

  • Display frames: display_frame='com' (the default; every figure except Figure 3) subtracts the instantaneous center of mass for display only; 'user' (Figure 3) plots the input coordinates directly. Neither choice changes the printed E, P, or L, which are always computed in the user-input inertial frame.
  • Conservation drift is a fraction of a characteristic scale, not of the literal initial value, when that value is itself close to zero (Figure 5's exactly-zero momentum, and any near-cancelling energy or angular momentum).
  • Integrator: an adaptive predictor–corrector. The same close encounter, shown from different angles in Figures 1, 4, 6 and 9, collapses the working step by up to four orders of magnitude and recovers it by 10% per accepted step afterward; this is expected, not a defect.
  • Precision: printed totals use five significant digits, which does not mean the model or method is that accurate; the true mid-run drift can be, and in Figure 4's case is, larger than the last printed digit of the initial/final totals.
  • Animation: Figure 8 is a single still frame from a playing animation; running the command shown plays all 31 frames interactively, with Space/Left/Right/Home/End/F keyboard controls.

Image and source provenance

All nine figures were regenerated for this guide from Multiple version 1.4.0, build 412f37f02fdc, on 24 September 2026; no earlier images were reused. Each was produced by running the command shown with Matplotlib's non-interactive Agg backend and saving the figure that plot_trajectories, plot_energy_drift, or animate_multiple would otherwise display (100 dpi), using on_key with an “end” key event to freeze Figure 8's animation on its final frame before saving. The headline values are the console output of the same runs.
