Start here

Run each command from the GFTGU-Programs/Multiple folder. Open GFTGU-Documentation/Multiple/SampleOutputs/Multiple-SampleOutputs_Guide.html beside this page when you want a pictured checkpoint. The companion extended tutorial offers fuller derivations and worked exercises for the same program and source build.

Start with python main.py --help or python main.py --version. Close a plot window to let a command finish. For every new command, omitted options return to defaults; use double quotes around semicolon-separated triples on Windows or Unix-like shells.

Beat 0 · Many bodies, one force law

Start in the program directory. Three equal solar masses occupy the corners of a right triangle. The default display recenters the plotted bodies on their moving centre of mass; the integration still uses the input inertial coordinates.

python main.py --max_steps 8000 --output_type trajectories

Read: 8000 accepted steps span 18.094 days. Follow the red, green and blue curves into the close encounter. The initial momentum is (−30000, −30000, 0) m/s, while the energy and angular-momentum totals remain approximately conserved.

Try 1: rerun at --max_steps 2000. Describe the geometry before the close encounter. Compare the two simulated durations: accepted-step count is not elapsed time when the timestep adapts.

Why: each body feels every other body. The pairwise gravitational acceleration is proportional to the other body's mass and inversely proportional to separation squared; there is no fixed central mass.

Beat 1 · Change the masses

python main.py --masses_solar 2,1,0.5 --max_steps 2000 --output_type trajectories

Read: the three paths differ because all three masses now affect the forces. The initial acceleration magnitudes computed from the starting geometry are 0.028972, 0.043871 and 0.070121 m/s² for bodies 1–3. The heaviest body's path is the smallest in this particular configuration.

Try 2: switch the order of the three masses with --masses_solar 0.5,1,2. Predict which initial acceleration changes and then compare the shapes. Each command starts from the defaults unless you specify another option.

Why: acceleration of body i is \(\mathbf a_i=G M_\odot\sum_{j\ne i}m_j(\mathbf r_j-\mathbf r_i)/|\mathbf r_j-\mathbf r_i|^3\), with m in solar masses. The body's own mass cancels from its acceleration but affects the others.

Beat 2 · Move the viewing frame

Add 100000 m/s in the x direction to each default velocity, then compare both displays:

python main.py --velocities_init "100000,0,0;100000,-30000,0;70000,0,0" --max_steps 2000 --output_type trajectories --display_frame user
python main.py --velocities_init "100000,0,0;100000,-30000,0;70000,0,0" --max_steps 2000 --output_type trajectories --display_frame com

Read: the user-frame plot carries the system across the axes; The centre-of-mass (COM) view subtracts the instantaneous centre-of-mass position from the plotted positions. The printed energy, momentum and angular momentum in both commands use the input coordinates. Total momentum after a common boost \(\mathbf u\) increases by \(M\mathbf u\) in the mass-scaled units.

Try 3: compare the two printed initial momentum vectors, then compare the two plots. Which feature changes only because of the display choice?

Beat 3 · Read conserved totals

python main.py --max_steps 8000 --output_type trajectories --show_energy_diagnostic

Read: eleven console samples cover fractions 0.0 through 1.0 of the elapsed time. E includes kinetic and gravitational potential energy; K is kinetic energy alone. E_internal subtracts the bulk centre-of-mass kinetic energy. P and L are the total linear and angular momentum in user coordinates.

Try 4: locate the largest sampled kinetic energy, then compare the maximum energy drift line and graph with just the start and end totals. The maximum can occur between printed rows; agreement of rounded endpoints does not bound it.

Why: pairwise forces conserve momentum and angular momentum analytically; an isolated Newtonian system conserves total energy. The displayed drift diagnoses numerical error, rather than a new physical force.

Beat 4 · A vanishing reference total

python main.py --n_bodies 2 --masses_solar 1,1 --positions_init "5e10,0,0;-5e10,0,0" --velocities_init "0,25760,0;0,-25760,0" --max_steps 3000 --output_type trajectories

Read: equal and opposite initial momenta cancel. A fractional error divided by the initial momentum norm would divide by zero. The code instead normalizes against the sum of individual initial momentum magnitudes when the total nearly cancels; the initial-scale value is 51520 m/s for this example.

Try 5: change only the second body's y velocity to −25759 m/s. Compare the reported momentum drift with the exact-cancellation run. The scale-aware fallback also applies near cancellation, not only at exact zero.

Try 6: change --projection yz on the original two-body command. Why does a face-on circle collapse to a nearly straight trace? Return to xy for the rest of the evening.

Beat 5 · Predict, correct, repeat

Keep the same initial state and accepted-step ceiling while changing the corrector threshold:

python main.py --max_steps 8000 --output_type trajectories --eps2 1e-10
python main.py --max_steps 8000 --output_type trajectories --eps2 0.004

Read: the corrector revises the predictor's new velocity using accelerations evaluated at trial positions. eps2 sets a velocity-increment stopping criterion; eps1 controls predictor acceleration change. These are algorithm thresholds, not promised fractional errors in the final path.

Try 7: compare elapsed days and maximum conservation drifts with Beat 0. Eight thousand accepted steps at different settings need not cover the same physical interval. For a convergence claim, compare at a common simulated time and check positions as well as drift.

Beat 6 · Follow the adaptive step

python main.py --max_steps 6000 --output_type trajectories
python main.py --max_steps 8000 --output_type trajectories

Read: the late close encounter forces a smaller working timestep, so 2000 additional accepted steps can cover much less time than the earlier 2000. The requested --dt 2000 is a ceiling. Rejected trials are halved; after acceptance the working timestep may grow by 10% toward the ceiling.

Try 8: compare simulated days for the two commands and calculate the time gained per added accepted step. Would a fixed 2000-second step have resolved the deepest encounter equally well?

Beat 7 · Make evenly spaced frames

python main.py --n_bodies 2 --masses_solar 1,1 --positions_init "5e10,0,0;-5e10,0,0" --velocities_init "0,25760,0;0,-25760,0" --max_steps 3000 --output_type animation --frame_time 2e5
python main.py --n_bodies 2 --masses_solar 1,1 --positions_init "5e10,0,0;-5e10,0,0" --velocities_init "0,25760,0;0,-25760,0" --max_steps 3000 --output_type animation --frame_time 4e5 --animation_mode current_positions

Read: animation requests regular simulated times, interpolating positions and velocities between accepted states using a cubic Hermite curve. Use Space to pause, arrows to step, Home/End to jump, and F to toggle the display frame. The second command has a coarser frame interval and omits trails.

Try 9: compare the frame counts. A short frame_time can yield more stored frames than accepted states; a long one can yield fewer. Both modes also retain a conservation record for every accepted step. The animation guard limits requested frames to one million, not that conservation history.

Beat 8 · Test the limits

A smaller timestep is useful only when the two runs can be compared over the same physical interval:

python main.py --dt 1000 --max_steps 4000 --output_type trajectories --show_energy_diagnostic
python main.py --dt 500 --max_steps 8000 --output_type trajectories --show_energy_diagnostic

Read: the first reaches day 17.559. Compare the drift curves over their shared time span. Each run's printed maximum is over its own complete duration, so do not use those two maxima alone as a matched-time convergence measure.

Try 10: predict what happens if two point masses approach an exact collision without any collision radius or softening. First run the shorter case, then the longer one:

python main.py --n_bodies 2 --masses_solar 1e11,1e11 --positions_init "-7.7e20,0,0;7.7e20,0,0" --velocities_init "50000,0,0;-50000,0,0" --dt 1e12 --max_steps 17500 --output_type trajectories
python main.py --n_bodies 2 --masses_solar 1e11,1e11 --positions_init "-7.7e20,0,0;7.7e20,0,0" --velocities_init "50000,0,0;-50000,0,0" --dt 1e12 --max_steps 17800 --output_type trajectories

The longer command stops when the adaptive step can no longer advance floating-point time. That limit is a property of this unsoftened point-mass model and integrator, not evidence of a physical merger.

Parameters

Supply only options you want to change. The default run is a three-body animation; the Beat commands request static trajectories when they need a complete path or an energy graph. Each initial-state list must have one entry per body.

Command-line flagDefaultUnitDescription
--n_bodies3—Number of point masses, at least two.
--masses_solar1,1,1M☉One positive mass per body.
--positions_initsee main.pymOne Cartesian position triple per body.
--velocities_initsee main.pym/sOne velocity triple per body.
--dt2000sMaximum adaptive integration timestep.
--max_steps60000—Maximum accepted integration steps.
--eps10.005—Per-body acceleration-change threshold (0 to 1).
--eps21.0e-7—Corrector velocity-increment threshold (0 to eps1).
--output_typeanimation—'trajectories' or 'animation'.
--animation_modetrails—current_positions or trails.
--frame_time2.0e5sSimulated seconds between animation frames.
--frame_interval_ms50msReal milliseconds between animation frames.
--trail_time6.0e5sRecent trajectory duration shown in animation.
--projectionxy—'xy', 'xz', or 'yz'.
--axis_modefixed—'fixed' full-frame limits, or 'auto' zoom.
--display_framecom—'com' (Beat 2 default) or 'user'.
--show_energy_diagnosticoff—Add an energy-drift graph with --output_type trajectories.

The default initial coordinates and velocities are printed in main.py. For matrix inputs, quote the whole semicolon-separated list. --no-show_energy_diagnostic reverses the boolean flag.

Reading output

The first line gives version, build, accepted steps and simulated days. Initial and final E, E_internal, P, L are expressed per solar mass in input coordinates. The maximum drift line scans the accepted history, not just the endpoints. Eleven time-fraction samples show E, E_internal, K, P, L. The display-frame line describes plotting only.

For the force law, numerical method, equations 1–16, and the experiment answer checks, see the companion extended tutorial. The two guides use the same executable files and tests.

Program files

main.py parses command-line options and prints the summary; physics_multiple.py evaluates Newtonian forces and conservation totals; driver_multiple.py integrates and samples the run; plot_multiple.py draws static paths, drift graphs and animation. tests/test_physics_multiple.py exercises code and both tutorial files together.

Related programs
