Multiple 1.2.2 Release Notes

Version: 1.2.2
Build: e29d630e7cf0
Date: 2026-09-11

Release Status

Version 1.2.2 follows Kickoff2 (COM display frame, printed conservation totals, exercise ratings) and Audit2-1 review by Codex and Claude. High-priority documentation errors in the boosted-momentum exercise and the display-versus-diagnostic-frame wording are corrected. The COM display remains a viewing translation; the integrator and the printed E, P, and L stay in the user-supplied inertial frame. The regression suite now contains 99 tests, all passing.

Major Improvements Since 1.1.2

  • Added display_frame='com'|'user', default 'com'. Plots and animations subtract the instantaneous all-body center of mass for display only.
  • Animation key F toggles the display frame without re-integrating and rewrites a discrete boxed note to Switched — Display frame: ....
  • Console output now prints initial and final user-frame scaled totals: total energy E=K+U, internal energy E_internal=E-|P|^2/(2M), linear momentum components, and angular-momentum components, plus the existing maximum-drift line.
  • Suggested scenarios carry Introductory / Intermediate / Advanced badges. The COM, cluster, and MercPert exercises no longer require hand subtraction of R_CM and V_CM merely to plot the motion.
  • Help file distinguishes COM display from a zero-momentum integration/diagnostic frame. Changing display_frame does not alter conservation diagnostics.
  • Legacy result dictionaries that omit both display_frame and masses_solar are labeled and drawn as user-frame data rather than being mislabeled COM.

Audit2-1 Corrections in 1.2.2

  • The Center-of-mass-frame exercise now uses P_new = P_old + M u. For the shipped state and u=(1.0e5,0,0) m/s the expected printed momentum is (2.7e5, -3.0e4, 0) m/s, not 3.0e5.
  • Animation E/P/L overlay is a multiline boxed block that no longer collides with the legend or runs off the default figure.
  • Overlay values are labeled interpolated-frame totals. The accepted-step drift line remains authoritative.
  • Terminology: V_CM is the center-of-mass velocity. The frame moving at V_CM is the center-of-momentum (zero-momentum) frame.
  • Small-star-cluster and galaxy-collision exercises now state crossing times and give usable dt/max_steps pairs, plus a warning that they are point-mass toys.
  • Galaxy companions at 10 kpc around a 1e11 M_sun core are assigned ~200 km/s for a bound shell; ~300 km/s is documented as marginally bound.
  • Help notes that the shipped default itself has nonzero net momentum, and that the same bulk-motion caveat applies to angular momentum about the origin.

Test Suite

The suite grew from 87 tests in 1.1.2 to 93 after Kickoff2 and to 99 in this Audit2-1 response. New tests cover Galilean momentum addition on the shipped state, COM-displayed relative trajectories before and after a uniform boost, F-key frame toggling and the switched note, legacy user-frame labeling, explicit COM-without-masses rejection, console E/E_internal formatting, and one-badge-per-scenario Help parsing.

Known Limitations

  • Intended for education rather than research-grade N-body work.
  • Bodies are Newtonian point masses: no finite radii, collisions, tides, gas, radiation, or relativity.
  • The predictor-corrector is not symplectic. Close encounters require conservation checks and convergence tests.
  • Direct pairwise forces scale as O(N2).
  • Fractional energy drift remains less informative when bulk kinetic energy dominates |E|. Use E_internal or subtract V_CM from the initial velocities; do not expect display_frame='com' to change the diagnostic.
  • Cluster and galaxy scenarios need the longer timesteps documented in the Help file; the shipped 60,000-step ceiling is intended for the default three-body encounter.
  • The Help file loads MathJax from a CDN. Offline, equations appear as raw LaTeX.

Multiple 1.1.2 Release Notes

Version: 1.1.2
Build: bb853c24c69e
Date: 2026-08-28

Release Status

Version 1.1.2 concludes a kickoff maintenance review followed by three rounds of independent review involving Codex, Copilot, and Gemini. The reviewers compared the Python implementation with Bernard Schutz's original Triana/Java Multiple program, verified the Newtonian N-body equations and conservation diagnostics, examined adaptive predictor-corrector behavior, animation-frame generation, public API validation, Help-file accuracy, Version/Build synchronization, and regression coverage. No release-blocking defect remains. The program is approved as a release candidate and is sufficiently robust and accurate for student use within the educational scope and limitations described below.

Major Improvements in This Release

  • Corrected the adaptive corrector convergence test so convergence is measured using velocity increments rather than absolute coordinate velocities, making the convergence decision Galilean invariant.
  • Improved the shipped numerical defaults from the original 40,000-step, eps1=0.05, eps2=1.0e-4 configuration to the current 60,000-step, eps1=0.005, eps2=1.0e-7 configuration, reducing default-run energy drift by several orders of magnitude.
  • Added comprehensive validation to the public physics layer, including validation of shapes, numeric types, finite values, positive masses, coincident-body singularities, and floating-point range failures.
  • Added defensive runtime checks for non-finite positions, velocities, accelerations, conservation diagnostics, timestep underflow, corrector exhaustion, and animation memory limits.
  • Implemented scale-aware energy-drift normalization for near-cancellation systems using the characteristic energy scale K0 + |U0| when the initial total energy is numerically indistinguishable from zero.
  • Added explicit energy-drift normalization metadata and scale metadata so plots and external code can correctly interpret reported conservation diagnostics.
  • Corrected conservation-vector drift calculations by replacing overflow-prone Euclidean norms with overflow-resistant hypot reductions and by rejecting non-finite diagnostics before they can be silently ignored.
  • Added neutral momentum- and angular-momentum-drift result keys together with normalization metadata and backward-compatible aliases for older callers.
  • Improved plotting validation by adding explicit projection validation, energy-history validation, normalization validation, and actionable public error messages.
  • Changed animation-frame scheduling from cumulative floating-point addition to integer-index multiplication, eliminating long-run timestamp accumulation drift while preserving uniform physical-time movie playback.
  • Added explicit accepted-step interpolation-bracket verification before cubic-Hermite frame generation, ensuring that animation interpolation never occurs outside the accepted-step interval.
  • Added BUILD_ID provenance across the four core program modules and synchronized the Version/Build information with the Help file, runtime output, and independent regression verification.
  • Corrected and expanded the Help file documentation, including energy equations, Galilean-invariant convergence explanations, conservation-drift normalization descriptions, output terminology, Build-ID coverage, default parameters, and educational exercises.

Test Suite Growth

A new regression suite containing 76 automated tests was created during the kickoff review. The suite expanded to 82 tests during Audit1 and to 87 tests during Audit2. Audit3 confirmed that all 87 tests pass and that no additional medium- or high-severity defects remain.

The final suite verifies analytical force calculations, conservation diagnostics, inverse-square behavior, translational and rotational invariance, permutation symmetry, parameter validation, floating-point range handling, Galilean invariance, adaptive timestep reduction and recovery, animation frame generation, cubic-Hermite interpolation, plotting behavior, Build-ID reproduction, Python-version compatibility, command-line version reporting, Help-file synchronization, and documentation integrity. The suite passes in both the canonical tests/ layout and a flattened upload layout.

Known Limitations

  • Intended for education and conceptual exploration rather than research-grade N-body simulations.
  • Bodies are Newtonian mathematical point masses. The model does not include finite radii, physical collisions, mergers, tidal effects, gas dynamics, radiation, dissipative processes, or relativity.
  • Exact coincidence of two bodies remains physically singular and terminates with a documented error condition.
  • The predictor-corrector integrator is not symplectic. Long integrations, especially those involving close encounters, should always be accompanied by conservation-diagnostic checks and convergence testing.
  • Chaotic N-body systems can exhibit trajectory divergence even when separate integrations are individually accurate and satisfy conservation diagnostics.
  • Direct pairwise force evaluation scales as O(N²) and is intended for modest educational particle counts rather than very large astrophysical systems.
  • Fractional energy drift may be less informative in frames dominated by very large center-of-mass kinetic energy. The Help file recommends center-of-mass coordinates when diagnostics are intended to assess relative-motion accuracy.
  • Only six plotting colors are supplied by default, so colors repeat for simulations containing more than six bodies.
  • The Help file loads MathJax from a public CDN. Offline, the documentation remains readable, but equations are displayed as raw LaTeX rather than typeset mathematics.

Known Minor Maintenance Items

  • Audit3 identified that nearly cancelling but nonzero initial momentum or angular-momentum vectors still use exact-zero detection rather than a scale-aware near-cancellation criterion. This affects diagnostic interpretation only and is not a numerical-integrator defect.
  • Audit3 identified that plot_trajectories() and animate_multiple() still assume structurally valid result dictionaries and could benefit from the same level of public-input validation already implemented for plot_energy_drift().
  • The source and regression suite are verified against Python 3.10 grammar and were executed during review using Python 3.12.13. Running the complete suite under a native Python 3.10 environment remains a desirable non-blocking release check.
  • Future releases may optionally expand plotting-result validation and add scale-aware normalization for nearly cancelling conservation vectors.
