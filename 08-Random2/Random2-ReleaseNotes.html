Random2 1.1.0 Release Notes

Version: 1.1.0
Build: 10144b08a600
Date: 2026-09-10

Release Status

Version 1.1.0 is a focused visualization release on top of the reviewed 1.0.2 program. The scaled-distance log-log plot now uses equal decade lengths on the horizontal and vertical axes, so the theoretical slope of 1/2 can be judged by eye instead of being stretched by the output-panel aspect ratio. Physics, drivers, defaults, and the 2D star display are unchanged. Help, release notes, and the sample-outputs guide are synchronized to this version and build.

Changes in 1.1.0

  • In plot_scaled_distance, the log-log axes now call ax.set_aspect("equal", adjustable="box") after the data are drawn. One decade has the same plotted length on both axes regardless of the figure or window shape.
  • A slope of 1/2 is therefore readable as a rise of one vertical decade over a run of two horizontal decades. Previously the (8, 6) figure and any later panel resize made that slope look arbitrarily steep or shallow.
  • plt.tight_layout() is applied to the scaled-distance figure, matching the existing walk display.
  • The plotting regression test now checks that the scaled-distance axes are logarithmic and have equal box-adjustable aspect.
  • Help Program Output, Experiment 1, and the plot-module card describe the equal-decade scaling. The sample-outputs guide regenerates the two log-log figures with the new aspect.
  • MODEL_VERSION is 1.1.0. BUILD_ID is recomputed over the four executable core modules.

Inherited from 1.0.2

Version 1.0.2 concluded a kickoff maintenance review followed by two rounds of independent review involving Codex, Copilot, and Gemini. That release preserved Schutz's three-dimensional scaled-distance experiment; added the Gaussian-component comparison and the isotropic 2D star visualization; hardened circle-intersection geometry and input validation; and introduced a reproducible BUILD_ID synchronized across source, Help, runtime version output, and simulation-result metadata.

The regression suite remains the 1.0.2 suite plus the new scaled-plot aspect assertions. Statistical tests still use private deterministic random-number generators. Core sources continue to parse under the Python 3.10 grammar.

Known Limitations

  • Random2 is intended for education and conceptual exploration, not research-grade stellar transport, opacity modeling, or quantitative solar diffusion-time prediction.
  • The scaled_distance mode uses three-dimensional vectors uniformly distributed within a cube. Its direction distribution is therefore anisotropic, although its independent zero-mean finite-variance components still produce the intended √N scaling.
  • Equal log-axis aspect makes the numerical slope readable; it does not make a slope of 1/2 appear as a 45° line. A 45° line on these axes would be a slope of 1.
  • The walk2d mode is a planar visualization. Its qualitative scaling is instructive, but its first-passage distribution should not be interpreted as the corresponding three-dimensional stellar result.
  • The default star radius is a selected multiple of the root-mean-square diffusion distance associated with reference_steps. That parameter sizes the schematic drawing; it is not the maximum walk length.
  • Monte Carlo output varies between runs. Small values of nTrials or n_walks produce substantial statistical scatter and should not be used to infer precise coefficients or escape-time distributions.
  • A walk that has not escaped when step_cap is reached is censored. Quantitative escape-time experiments must use a sufficiently high cap and confirm that nearly all sampled walks escape.
  • Very large maxSteps, nTrials, n_walks, or step_cap values can make the program intentionally computation- or memory-intensive.
  • The Help file loads MathJax from a public CDN. Offline, its prose and unrendered TeX source remain available, but equations are not typeset.

Known Minor Maintenance Items

  • Ordinary experiment parameters are edited in main.py; only --version is currently exposed on the command line. Optional command-line parameters may be useful in a future usability release but are not required for the textbook's edit-and-rerun workflow.
  • random2_plot.py imports the result dataclasses from random2_driver.py. If additional consumers or result types are introduced, shared immutable model types may be worth moving to a small neutral module.
  • The physics and plotting layers each contain small private numeric-validation helpers. This limited duplication keeps the plotter independent of physics-layer implementation details; a public shared validation module may become worthwhile if the validation surface grows.
  • The statistical regressions intentionally gate the expected physical behavior using deterministic seeds and generous scientific tolerances. If Python's random-number algorithms change substantially in a future runtime, the sampled tolerances should be reassessed rather than replaced with exact sequence assertions.
  • Additional end-to-end subprocess tests for both display modes could supplement the existing driver and plotting integration coverage in a future test-maintenance round.
