Overview

Random2 explores the square-root law of random walks and uses it to picture how radiation leaks out of a star. Energy released in the Sun's core does not stream outwards; it is absorbed and re-emitted so often that its path is a random walk, and a random walk covers distance very slowly. After \(N\) independent steps the typical distance from the start grows as \(\sqrt N\), not \(N\).

The program has two displays. scaled_distance runs many three-dimensional random walks of different lengths and prints and plots their average distance from the start. walk2d draws a few fixed-length, equally-likely-in-every-direction walks from the centre of a circle, a schematic star, and counts the steps each one takes to reach the edge. Every run prints a summary of the numbers before it opens its plot.

The spine of the lesson is one sentence: random steps add up so that the distance travelled grows only as the square root of the number of steps, whatever the shape of the step distribution, so escaping from a region of radius \(R\) takes about \((R/\lambda)^2\) steps of length \(\lambda\), and the printed standard errors are how you tell how far to trust an average made from a finite number of random trials. Each numbered section below is one beat: a short argument, a command whose printed summary or figure illustrates that argument, and then the equation that the printed numbers follow from.

Scope: Random2 is about the statistics of random walks. Star models the structure of a star, and Neutron the structure of a neutron star; neither follows individual photons. Random2's circle is a picture of diffusion, not a model of the Sun.
What this program is, and what it does not model. Random2 is a teaching model of random walks. It does not model the Sun's changing density, opacity or photon mean free path, it has no convection zone, and the star display is two-dimensional, so the spread of its escape times is not that of a three-dimensional star. In the real Sun, radiation diffuses through the core and radiative zone, and convection carries the energy through the outer 30% or so of the radius. Every result is a Monte Carlo estimate: it comes from random numbers, differs from run to run, and carries a statistical uncertainty that the summary prints. Use the program to see how random walks scale and how to judge a random estimate; Beats 1, 7 and 8 show where the numbers stop being trustworthy.

The equations on this page are rendered by MathJax, loaded from a public CDN, so an internet connection is needed to see them typeset; with no connection, the raw TeX source (e.g. \(\sqrt{N}\)) will show as plain text instead of a formula. How to read this page

Each numbered section below is one beat: a short argument in words, a command whose output illustrates it, and then the equation that the output follows from. Do them in order the first time. After that, any beat can be opened on its own.

The program's output is a consequence of its random numbers and its equations, so what a beat shows is the equations at work, not independent evidence that they are right. The outside checks the program offers are the predictions it prints beside its averages: the large-\(N\) ratio to \(\sqrt N\) in scaled_distance, and \((R/\lambda)^2\) in walk2d. Beats 1, 2, 4 and 5 compare the averages with them.

The commands of Beats 0 to 7 include --seed 12; Beat 8 compares a run with --seed 28 and a run with no seed. A seed fixes the sequence of random numbers, so your run prints exactly the numbers quoted here. Seed 12 is not special: it gives a typical example of these experiments. Another seed gives a new random sample; how far its numbers may differ from these is judged with the combined standard error of Beat 8, and occasionally a difference of more than two combined standard errors is expected. Leave the seed out and every run is different; that is the normal way to use the program once you know what to look for, and Beat 8 shows what changes.

Every beat uses the same program and the same kind of summary. Beats 0 to 2 use the three-dimensional scaled_distance display: Beat 0 runs the default, Beat 1 changes the number of trials, and Beat 2 changes the step distribution. Beats 3 to 7 use the two-dimensional walk2d display: Beat 3 runs its default, Beat 4 counts escape steps over many walks, Beat 5 halves the radius, Beat 6 changes the step length, and Beat 7 limits the number of steps. Beat 8 changes the seed and shows what the program rejects.

Run every command from the program's folder. Each run prints a summary and then opens a plot window; close the window to end the program. Each beat names the lines of the summary to look at. Distances in scaled_distance are in units of the mean step length; distances in walk2d are in the same arbitrary units as --mean_free_path.

What kind of statement is each equation? Each displayed equation in the beats carries a tag. A red MODEL tag marks an assumption the model makes about the steps and does not derive: that they are independent, with no preferred direction on average. Eqs. (1) and (12) are the only ones. A grey DEFINITION tag marks a quantity that is defined by a formula. A blue DERIVED tag marks a result that follows from the equations already stated. A violet ALGORITHM tag marks a rule of the calculation, which is a choice made by the program rather than a property of random walks: Eqs. (8), (15) and (19). An orange PRESCRIPTION tag marks a convenience the program adopts, here only the default star radius, Eq. (14). The tags are there so that an assumption, a definition and a rule of the program are never mistaken for one another. Twenty equations are numbered; a few unnumbered ones appear where they are needed.

Beat 0 · Random steps add up as √N

A walker takes steps in three dimensions, each one in a random direction and of random length, with no memory of the steps before. The program sends out 100 such walkers for each of twelve walk lengths, from 2 steps to 4096, and averages how far they end up from where they started.

python main.py --seed 12

Look at the table in the summary: the column N, the column mean scaled distance, and the column ratio to sqrt(N). Look also at the last line, fitted log-log slope, and at the plot. Ignore the standard error column until Beat 1.

Three tasks, in order. First, read the last row. After 4096 steps the walkers are on average only 63.0073 step lengths from the start, not 4096. Then compare rows four steps apart in N. From 1024 to 4096 steps the distance goes from 30.6802 to 63.0073, a factor of 2.05, and from 256 to 1024 it goes from 14.9520 to 30.6802, a factor of 2.05 again; four times as many steps take the walker only about twice as far. Then read the last column. Every value lies between 0.9074 and 1.0237, although N changes by a factor of 2048, and the fitted slope of the plot is 0.4964. Say what law connects the distance with the number of steps, and why the plot, which has equal decades on both axes, rises one decade for every two it runs.

Then the assumption behind those numbers. The steps are independent of one another and point, on average, nowhere.

(1)
Independent steps with zero mean MODEL
\[ \mathbf s_1,\mathbf s_2,\dots,\mathbf s_N\ \text{independent and identically distributed}, \qquad \langle\mathbf s_i\rangle=\mathbf 0 . \]

This is the whole physical content of a random walk: a photon that is absorbed and re-emitted forgets the direction it came from. By default each step's three components are drawn separately and uniformly.

(2)
Uniform step components DEFINITION
\[ \Delta x_i=2U_{x,i}-1,\qquad \Delta y_i=2U_{y,i}-1,\qquad \Delta z_i=2U_{z,i}-1, \qquad U\sim\mathrm{Uniform}(0,1). \]

These steps fill a cube, so diagonal directions are a little more common than directions along the axes; that does not matter for the law below, which uses only Eq. (1). The program adds the steps and divides the distance reached by the walk's own mean step length, so that walks with different kinds of steps can be compared.

(3)
Net distance and scaled distance DEFINITION
\[ \mathbf R_N=\sum_{i=1}^{N}\mathbf s_i,\qquad r_N=\lvert\mathbf R_N\rvert, \qquad \bar\ell=\frac1N\sum_{i=1}^{N}\lvert\mathbf s_i\rvert, \qquad d=\frac{r_N}{\bar\ell}. \]

The column mean scaled distance is \(d\) averaged over the trials. Squaring \(\mathbf R_N\) gives \(N\) squared step lengths and \(N(N-1)\) cross terms \(\mathbf s_i\cdot\mathbf s_j\). By Eq. (1) every cross term averages to zero, because the two steps are independent and each averages to nothing. Only the squares survive.

(4)
The mean square distance DERIVED
\[ \langle r_N^{2}\rangle=\sum_{i=1}^{N}\langle\lvert\mathbf s_i\rvert^{2}\rangle+\sum_{i\neq j}\langle\mathbf s_i\rangle\cdot\langle\mathbf s_j\rangle =N\,\langle\lvert\mathbf s\rvert^{2}\rangle . \]

For the uniform steps of Eq. (2) each component has mean square 1/3, so \(\langle\lvert\mathbf s\rvert^2\rangle=1\) and the root-mean-square distance is exactly \(\sqrt N\) in these units. Eq. (4) is exact for every \(N\). The printed quantity is different: it is the mean of \(r_N\), not of \(r_N^2\), and each walk is divided by its own mean step length. For large \(N\) it grows in the same way.

(5)
The square-root law, for large N DERIVED
\[ \langle d\rangle\approx C\sqrt N, \qquad \log\langle d\rangle\approx\tfrac12\log N+\log C . \]

Eq. (5) is a large-\(N\) result, so the ratio \(\langle d\rangle/\sqrt N\) in the last column approaches a constant \(C\) as \(N\) grows, and on log-log axes the points approach a line of slope 1/2, which the fitted slope measures. For a few steps the ratio is a little larger than \(C\); Beat 1 returns to this. Beat 1 asks how much of the scatter in that column is real.

Beat 1 · How far to trust an average

An average of random numbers is itself random. Run the same experiment with a quarter as many trials, and then with ten times as many.

python main.py --seed 12 --n_trials 25
python main.py --seed 12 --n_trials 1000

Look, in each run, at the standard error column, at the ratio to sqrt(N) column, at the line large-N prediction for ratio to sqrt(N), and at fitted log-log slope. Compare them with the 100-trial run of Beat 0.

Three tasks, in order. First, read the standard error of the last row: 4.2617 with 25 trials, 2.3473 with 100 (Beat 0) and 0.8231 with 1000. Four times as many trials divide it by 1.82, and ten times as many by 2.85. Then read the ratio column against the prediction, 0.9591. With 25 trials the ratios run from 0.8211 to 1.0326; with 1000 trials, from row 16 onwards, they lie between 0.9521 and 0.9667, all within 0.008 of the prediction. Then look down the standard-error column of the 1000-trial run: 0.0501 at 16 steps and 0.8231 at 4096, 16.4 times larger for 256 times as many steps. Say how the standard error should depend on the number of trials and on \(N\), and why the three fitted slopes, 0.4998, 0.4964 and 0.4969, hardly change.

Then what the standard error is. Each row averages \(n\) independent values of \(d\), where \(n\) is --n_trials. Their spread is measured by the sample standard deviation \(s\), and the uncertainty of their average by the standard error.

(6)
Standard error of a mean DEFINITION
\[ s^{2}=\frac{1}{n-1}\sum_{k=1}^{n}\bigl(d_k-\langle d\rangle\bigr)^{2}, \qquad \mathrm{SE}=\frac{s}{\sqrt n}. \]
(7)
How the standard error scales DERIVED
\[ \mathrm{SE}\approx\frac{0.42\,C\sqrt N}{\sqrt n}. \]

The spread \(s\) of \(d\) grows like \(d\) itself, as \(\sqrt N\); for a large-\(N\) walk it is 0.42 of the mean. Dividing by \(\sqrt n\) is the square-root law again, applied to the trials instead of the steps: averaging \(n\) random numbers narrows their spread only by \(\sqrt n\). So ten times as many trials should shrink the standard error by \(\sqrt{10}=3.16\), and 256 times as many steps should grow it by 16. The printed 2.85 and 1.82 are not exactly 3.16 and 2 because \(s\) is itself estimated from the same random trials. About two rows in three should lie within one standard error of the prediction, and nearly all within two. The fitted slope comes from all twelve rows at once.

(8)
The fitted log-log slope ALGORITHM
\[ \alpha=\frac{\sum_j(\log N_j-\overline{\log N})(\log\langle d\rangle_j-\overline{\log\langle d\rangle})} {\sum_j(\log N_j-\overline{\log N})^{2}} . \]

This is an ordinary least-squares line through the plotted points, computed by fitted_loglog_slope() in random2_physics.py and also written on the plot. Every row counts equally, and every row has about the same relative uncertainty, 0.42 divided by \(\sqrt n\), so the fit averages twelve independent errors spread over more than three decades of \(N\). Its own uncertainty is therefore small, about 0.01 with 25 trials and 0.002 with 1000, which is why the three slopes agree. There is also a small bias: the shortest walks have ratios a little above the large-\(N\) prediction, because two or four steps are too few for the central limit theorem of Beat 2, and that lowers the expected slope over these twelve rows slightly, to about 0.498. The standard error of a single row is the better guide to how well any one average is known. Beat 2 changes the step distribution and asks what happens to the constant \(C\).

Beat 2 · Only the variance matters

The uniform steps of Beat 0 are one choice among many. Replace them with steps whose components follow the bell-shaped Gaussian distribution, which gives some very long steps and many short ones.

python main.py --seed 12 --step_distribution gaussian

Look at step components, at the ratio to sqrt(N) column, at large-N prediction for ratio to sqrt(N) and at fitted log-log slope, and compare them with Beat 0.

Three tasks, in order. First, read the slope: 0.4986, against 0.4964 for uniform steps. The exponent has not changed. Then read the prediction. It is now 1.0000 where it was 0.9591, and the ratio column scatters about it: from row 64 onwards the ratios lie between 0.9408 and 1.0502. Then compare the last rows: 65.1655 with standard error 3.2761 here, against 63.0073 with standard error 2.3473 for uniform steps. The difference, 2.16, is 0.54 of the two standard errors combined, so these two rows cannot tell the distributions apart; the prediction says they should differ by 4%. Say what property of the step distribution the square-root law depends on, and what property sets the constant \(C\).

Then the Gaussian step.

(9)
Gaussian step components DEFINITION
\[ \Delta x_i,\ \Delta y_i,\ \Delta z_i\ \sim\ \mathcal N(0,\sigma^{2}),\qquad \sigma=1 . \]

Eq. (4) used only independence and zero mean, so it holds for Gaussian steps too: the law is \(\sqrt N\) for any step distribution with a finite variance. The constant needs one more fact. The sum of many independent steps is close to a Gaussian in each coordinate, with variance \(N\sigma^2\), whatever the steps were (the central limit theorem). The distance from the origin of such a three-dimensional Gaussian point has a known mean.

(10)
Mean distance after many steps DERIVED
\[ \langle r_N\rangle\approx\sigma\sqrt{\frac{8N}{\pi}},\qquad \sigma^{2}=\tfrac13\ \text{(uniform)},\quad \sigma^{2}=1\ \text{(Gaussian)} . \]

Dividing by the mean step length gives the constant \(C\) of Eq. (5), which the program prints as the large-\(N\) prediction. For Gaussian steps the mean step length is \(\sigma\sqrt{8/\pi}\), the same expression with \(N=1\), so \(C=1\) exactly. For uniform steps the mean step length is the mean distance from the centre of the cube \([-1,1]^3\) to a random point in it.

(11)
The constant C for the two distributions DERIVED
\[ C_{\rm uniform}=\frac{\sqrt{8/(3\pi)}}{\langle\ell\rangle}=\frac{0.92132}{0.96059}=0.9591, \qquad \langle\ell\rangle=\frac{\sqrt3}{4}+\frac{\ln(2+\sqrt3)}{2}-\frac{\pi}{24}, \qquad C_{\rm gaussian}=1 . \]

The exponent 1/2 depends only on the steps being independent with finite variance. The constant depends on the shape of the distribution. For these two distributions it differs by only about 4%, and dividing by the mean step length makes it close to 1 for both; a distribution with mostly very short steps and a few very long ones would have a much larger \(C\), because its mean step length is small compared with its root-mean-square step length. The values are large_n_scaled_distance_ratio() and UNIFORM_MEAN_STEP_LENGTH in random2_physics.py. Eq. (10) is a large-\(N\) result; for 2 or 4 steps the central limit theorem has not yet taken hold, so those rows need not match it. Beat 3 turns from three-dimensional statistics to a picture.

Beat 3 · A photon in a schematic star

Now picture the walk. A photon starts at the centre of a circle, the schematic star, and takes steps of one fixed length in directions chosen with no preference, until it crosses the edge. The program draws four such walks.

python main.py --display walk2d --seed 12

Look at the plot, and at the summary lines star radius R, (R / mean free path)^2, the four walk lines, and escape steps.

Three tasks, in order. First, read the geometry. The star radius is 89.4427 and every step has length 1 (the mean free path), so the photon needs at least 90 steps to get out if it walks straight; (R / mean free path)^2 is 8000.0. Then read the walks. They escape after 11564, 7519, 8246 and 2479 steps, a factor of 4.66 between the slowest and the fastest; the mean is 7452.0 with a standard error of 1876.9. Then look at the plot. Each path is a tangle that revisits the same region many times before it happens to reach the edge, and each ends in a short straight ray outside the circle. Say how many steps a photon should need, on average, to escape from a star of radius \(R\), given Beat 0, and why four walks cannot tell you that number to better than about 25%.

Then the steps. In this display every step has exactly the length \(\lambda\), the option --mean_free_path, and a direction that is equally likely to be any angle.

(12)
Isotropic steps of fixed length MODEL
\[ \theta_i\sim\mathrm{Uniform}(0,2\pi),\qquad \mathbf s_i=\lambda\,(\cos\theta_i,\ \sin\theta_i),\qquad \lvert\mathbf s_i\rvert=\lambda . \]

These steps satisfy Eq. (1), and each has \(\lvert\mathbf s\rvert^2=\lambda^2\) exactly, so Eq. (4) gives the root-mean-square distance after \(N\) steps directly.

(13)
Root-mean-square distance of the display walk DERIVED
\[ D_{\rm rms}=\sqrt{\langle r_N^{2}\rangle}=\lambda\sqrt N . \]

The display is two-dimensional so that the paths can be seen; Eq. (13) holds in any number of dimensions. The default radius is chosen from Eq. (13): it is a multiple \(f\) of the distance a walk of \(N_{\rm ref}\) steps typically covers.

(14)
Default star radius PRESCRIPTION
\[ R=f\,\lambda\sqrt{N_{\rm ref}},\qquad f=2,\quad N_{\rm ref}=2000 . \]

Here \(f\) is --radius_factor and \(N_{\rm ref}\) is --reference_steps, with their defaults. So \(R=2\sqrt{2000}=89.4427\) and \((R/\lambda)^2=f^2N_{\rm ref}=8000\). This is a choice of drawing size, made by default_radius() in random2_physics.py, not a physical property; --radius overrides it, and reference_steps is not a limit on the walk. The walk stops at the step that crosses the circle.

(15)
Escape test and exact exit point ALGORITHM
\[ \lvert\mathbf p_k\rvert\ge R\ \Rightarrow\ \text{escaped after }k\text{ steps};\qquad \lvert\mathbf p_{k-1}+t(\mathbf p_k-\mathbf p_{k-1})\rvert=R,\quad 0<t\le1 . \]

The second equation is a quadratic in \(t\); circle_crossing_fraction() solves it in a form that stays accurate when the walk ends just outside the circle, and the drawn path stops at that exit point. The ray beyond it, of length --ray_length_factor times \(R\) in the direction of the last step, is only a picture of the photon leaving; the model says nothing about what happens outside. Beat 4 answers the question of how many steps escape takes.

Beat 4 · Escape takes (R/λ)² steps

Four walks are too few. Use a smaller star, so that each walk is quick, and send 200 photons out of it.

python main.py --display walk2d --radius 30 --n_walks 200 --seed 12

Look at (R / mean free path)^2, escaped walks, escape steps and mean escape steps / (R / mean free path)^2. With more than 12 walks the summary does not list them one by one.

Three tasks, in order. First, read the prediction: (R / mean free path)^2 is 900.0. Then read the mean: all 200 walks escape, with a mean of 902.7 steps and a standard error of 44.7, so the mean is 1.0030 times the prediction, well within one standard error. Then read the spread: the median is 742.5, the fastest walk escapes in 132 steps and the slowest takes 3797. Say why the mean is larger than the median, and what that says about the shape of the distribution of escape times.

Then why the prediction is \((R/\lambda)^2\). By Eq. (4), each step adds \(\lambda^2\) on average to the square of the distance from the centre, whatever the walk has done before. So the quantity \(r_k^2-k\lambda^2\) stays at zero on average at every step, and stays at zero on average also when it is looked at at the moment of escape. At that moment the photon is between \(R\) and \(R+\lambda\) from the centre, because it was inside one step earlier.

(16)
Mean number of steps to escape DERIVED
\[ \Bigl(\frac{R}{\lambda}\Bigr)^{2}\ \le\ \langle N_{\rm escape}\rangle\ <\ \Bigl(\frac{R}{\lambda}+1\Bigr)^{2}. \]

For \(R=30\) the mean must lie between 900 and 961, and the printed 902.7 ± 44.7 is consistent with it. The argument uses only Eq. (4), so the same mean holds for a walk in three dimensions, although the spread of escape times is different there. The distribution is broad and has a long tail: most photons escape in fewer steps than the mean, and a few take several times longer, which pulls the mean above the median. This is the diffusion result behind the long time radiation takes to leave a star: to cross a distance \(R\) in steps of \(\lambda\) takes \((R/\lambda)^2\) steps, not \(R/\lambda\). The statistics are computed by escape_statistics() in random2_driver.py. Beat 5 tests the square.

Beat 5 · Twice the radius, four times the steps

Run the 200 walks of Beat 4 again in a star of half the radius.

python main.py --display walk2d --radius 15 --n_walks 200 --seed 12
python main.py --display walk2d --radius 30 --n_walks 200 --seed 12

Look at escape steps and mean escape steps / (R / mean free path)^2 in both runs. The second run is the run of Beat 4.

Three tasks, in order. First, read the small star: all 200 walks escape, with a mean of 227.8 steps and a standard error of 10.5, against a prediction of 225.0. Then divide: the mean for \(R=30\) is 902.7, and 902.7/227.8 = 3.96. The medians, 742.5 and 186.0, give 3.99. Then find the uncertainty of that ratio. The relative standard errors are 44.7/902.7 = 0.050 and 10.5/227.8 = 0.046, so the ratio is uncertain by about \(\sqrt{0.050^2+0.046^2}=0.068\) of itself, or 0.27. Say whether the ratio agrees with 4, and what ratio you would expect if escape took a number of steps proportional to \(R\).

Then the ratio from Eq. (16).

(17)
Doubling the radius DERIVED
\[ \frac{\langle N_{\rm escape}(2R)\rangle}{\langle N_{\rm escape}(R)\rangle}\ \longrightarrow\ 4 \quad\text{as }R/\lambda\to\infty;\qquad \frac{900}{256}=3.52\ \le\ \frac{\langle N(30)\rangle}{\langle N(15)\rangle}\ \le\ \frac{961}{225}=4.27 . \]

For a large star the one-step allowance in Eq. (16) does not matter and the ratio is 4. For these small stars Eq. (16) only confines it between 3.52 and 4.27, and the measured 3.96 ± 0.27 lies inside. A photon that went straight out would take twice as many steps, not four times. Beat 6 asks whether the answer depends on the step length or only on the ratio \(R/\lambda\).

Beat 6 · Only R/λ matters

Change the step length and leave the radius to the default rule of Beat 3, which scales it with the step length.

python main.py --display walk2d --mean_free_path 0.5 --seed 12
python main.py --display walk2d --mean_free_path 2 --seed 12

Look at star radius R, mean free path, (R / mean free path)^2 and the four walk lines, and compare them with Beat 3, which used a step length of 1. Compare the plots too, including the numbers on their axes.

Three tasks, in order. First, read the radii: 44.7214 for a step of 0.5, 89.4427 for 1 (Beat 3) and 178.8854 for 2, while (R / mean free path)^2 is 8000.0 in all three. Then read the walks: they escape after 11564, 7519, 8246 and 2479 steps in all three runs, the very same numbers. Then compare the plots: the pictures are the same, and only the scale on the axes differs by a factor of 2. Say why changing the step length changed nothing that is measured in steps.

Then the reason. Divide every position by \(\lambda\): by Eq. (12) the walk becomes a sum of unit vectors \((\cos\theta_i,\sin\theta_i)\), and the escape test of Eq. (15) becomes \(\lvert\mathbf p_k\rvert/\lambda\ge R/\lambda\).

(18)
The walk in units of the step length DERIVED
\[ \frac{\mathbf p_k}{\lambda}=\sum_{i=1}^{k}(\cos\theta_i,\ \sin\theta_i), \qquad \text{escape when}\ \ \frac{\lvert\mathbf p_k\rvert}{\lambda}\ \ge\ \frac{R}{\lambda}=f\sqrt{N_{\rm ref}} . \]

The step length has dropped out; only the dimensionless radius \(R/\lambda\) is left, and the default rule of Eq. (14) keeps it at \(2\sqrt{2000}\) whatever \(\lambda\) is. With the same seed the angles \(\theta_i\) are the same, so the walks are the same walks drawn at a different scale. The counts agree exactly here because multiplying by 0.5 or 2 is exact in the computer's binary arithmetic; for other factors a walk that ends within a rounding error of the edge could, in principle, differ by a step. In a star the photon's mean free path is therefore not needed by itself, only its ratio to the size of the star. Beat 7 turns to a limit the program imposes on its own.

Beat 7 · The step cap

A walk could in principle go on for ever, so the program stops any walk that has not escaped after --step_cap steps (200000 by default). Set the cap to the mean escape time of Beat 4, and then to three times it.

python main.py --display walk2d --radius 30 --n_walks 200 --step_cap 900 --seed 12
python main.py --display walk2d --radius 30 --n_walks 200 --step_cap 3000 --seed 12

Look at step cap, escaped walks, escape steps and mean escape steps / (R / mean free path)^2, and compare them with Beat 4. On the plot, a walk stopped by the cap ends in an x and has no ray.

Three tasks, in order. First, read the cap of 900: only 130 of the 200 walks escape, and their mean is 515.7 steps, 0.5730 of the prediction, where Beat 4 found 902.7; the slowest escape counted is 897. Then read the cap of 3000: 196 of 200 escape, with a mean of 837.5, 0.9305 of the prediction. Then compare with Beat 4, where no walk came near the default cap and the mean was 1.0030 of the prediction. Say why the mean of the escaped walks is too small whenever some walks are stopped, even though every number in it is a correct escape count.

Then the rule.

(19)
The step cap, and the mean it leaves ALGORITHM
\[ k\le k_{\rm cap};\qquad \text{printed mean}=\langle N_{\rm escape}\,\vert\,N_{\rm escape}\le k_{\rm cap}\rangle\ \le\ \langle N_{\rm escape}\rangle . \]

Here \(k_{\rm cap}\) is --step_cap. A walk stopped by the cap is not an escape, so the program leaves it out of the escape statistics and reports it separately. What is left is the mean over the walks that happened to be quick, which is biased low; it is a censored sample. The long tail seen in Beat 4 is exactly what the cap cuts off, and even a cap of 3000, more than three times the mean, stops four walks and brings the mean down to 0.9305 of the prediction. The run also changes in a second way: a stopped walk uses fewer random numbers than it would have, so the walks after it are not the same walks as in Beat 4. The escape count of a quantitative experiment is trustworthy only if escaped walks reads 200 of 200, or very nearly. Beat 8 changes the seed.

Beat 8 · Seeds and the hard cases

Every beat so far used --seed 12. Run the default experiment of Beat 0 with another seed, then with none, and then try a walk too short to have a length. The last command is rejected; the message says why.

python main.py --seed 28
python main.py
python main.py --max_steps 1

Look at the last row of the table and at fitted log-log slope in the first run, and compare them with Beat 0. In the second run, look at the line seed, and run the same command a second time.

Three tasks, in order. First, compare the seeds. With seed 28 the last row is 62.2140 with standard error 2.5542; with seed 12 it was 63.0073 with standard error 2.3473. The difference is 0.79, and the two standard errors combined are \(\sqrt{2.5542^2+2.3473^2}=3.47\), so the difference is 0.23 of that. The slopes are 0.4974 and 0.4964. Then read the unseeded run: its seed line reads none (results differ from run to run), and a second run prints different numbers. Then read the error of the third command: max_steps must be at least 2, because the smallest walk has 2 steps. Say how large a difference between two runs with different seeds would make you suspect a mistake rather than chance.

Then the rule for comparing two random estimates.

(20)
Uncertainty of a difference DERIVED
\[ \mathrm{SE}\bigl(\langle d\rangle_1-\langle d\rangle_2\bigr)=\sqrt{\mathrm{SE}_1^{2}+\mathrm{SE}_2^{2}} . \]

Two independent estimates differ by less than one combined standard error about two times in three and by more than two about one time in twenty, so a difference of three or more combined standard errors is a reason to look for a mistake. Eq. (20) is the same addition of independent squares as Eq. (4). A seed is a starting point for the generator of random numbers, set by seed_generator() in random2_physics.py; it makes a run repeatable, which is how this page can quote numbers, but it makes no run more correct than another. The table's step counts are found by halving --max_steps until the next value would be 1, so a run needs at least 2 steps; the smallest accepted value, --max_steps 2, gives a table of one row, and the program then prints fitted log-log slope: n/a (only one step count). Other rejected inputs are listed under Parameters.

Experiments that go with this beat: Experiment 2 and Experiment 11 in Suggested Experiments.

Algorithm

This section collects in one place the rules of the calculation that the beats introduced one at a time.

Scaled-distance display

  1. If --seed is given, seed the random-number generator with it.
  2. Start with \(N\) = --max_steps. For this \(N\), run --n_trials independent walks of \(N\) steps with the step components of Eq. (2) or Eq. (9), and for each record the scaled distance \(d\) of Eq. (3).
  3. Record the mean of the \(d\) values and its standard error, Eq. (6). The standard error is n/a for a single trial.
  4. Halve \(N\), discarding any remainder, and repeat from step 2 until the next value would be 1.
  5. Order the rows from the shortest walk to the longest, print them with their ratio to \(\sqrt N\), the large-\(N\) prediction of Eq. (11) and the fitted slope of Eq. (8), and draw the log-log plot.

Star display

  1. If --seed is given, seed the random-number generator with it. Take the radius from --radius, or from Eq. (14) if it is omitted.
  2. For each of --n_walks walks, start at the centre and add steps of Eq. (12) one at a time.
  3. After each step, apply the escape test of Eq. (15). If the walk has escaped, cut its last segment at the exact exit point, record the step count, and add a ray in the direction of the last step.
  4. If the walk has taken --step_cap steps without escaping, stop it and record it as not escaped, Eq. (19).
  5. Print the escape statistics of the escaped walks and draw the star, the paths, the rays and an x at the end of each stopped walk.

Random numbers and repeatability

Both displays draw their random numbers from Python's standard generator. A run with --seed repeats exactly on the same computer and program version. A different computer normally gives the same numbers too, but its mathematical library could in principle round a sine or a square root differently in the last digit, which could move the end of a walk that finishes within a rounding error of the edge by one step. Without --seed, every run is different, and the standard errors in the summary say how different to expect.

Tip: Before trusting an average, read its standard error. Before trusting an escape-step mean, check that escaped walks says that all the walks, or nearly all, escaped. Before trusting a difference between two runs, compare it with the combined standard error of Eq. (20).

Program Files

main.py
Entry Point & Configuration

Defines and describes every command-line option in build_parser(), seeds the generator, runs the selected display, prints its summary (see Printed Summary) with scaled_distance_summary() or walk2d_summary(), and passes the results to the plotter.

random2_physics.py
Physics Layer

Contains the two step generators, generate_component_step() and generate_isotropic_step(); default_radius(); the exit-point geometry circle_crossing_fraction() and point_at(); large_n_scaled_distance_ratio(); fitted_loglog_slope(); seed_generator(); the input checks shared by the other modules; and the version and build identifier.

random2_driver.py
Driver Layer

Defines run_scaled_distance_statistics(), which returns a ScaledDistanceResult (step counts, averages and standard errors, as tuples); run_scaled_distance_experiment(), which returns just the step counts and averages as two lists; run_walk2d(), which returns a Walk2DResult holding one WalkPath per walk; and escape_statistics(). The result types are frozen, so they cannot be changed after they are returned.

random2_plot.py
Visualisation

Provides plot_scaled_distance(lengths, avg_dist), the log-log plot with equal decades and the fitted slope, and plot_walk2d(result, corner="upper right"), the star with its walks and an annotation box; see Plots.

Quick Start

Requirements

Python 3.10 or later with matplotlib:

pip install "matplotlib>=3.5"

Running the Program

Clone or download the repository, then open a terminal in the folder that contains main.py:

cd GFTGU-Programs/Random2
python main.py
python main.py --display walk2d
python main.py --help

To display the program version and build identifier without running a calculation, use python main.py --version. Options omitted from a command keep their defaults.

# More trials and Gaussian rather than uniform step components
python main.py --display scaled_distance --max_steps 8192 --n_trials 500 --step_distribution gaussian

# Move the annotation and suppress the outgoing rays
python main.py --display walk2d --corner lower_left --ray_length_factor 0

The corner selector accepts upper_right, upper_left, lower_right and lower_left; the underscores map to the spaced names the plotter uses. The former spellings --maxSteps and --nTrials are still accepted.

Plots

scaled_distance draws the mean scaled distance against the number of steps on log-log axes, with one decade the same length on both axes, so that a slope of 1/2 rises one decade over two. The fitted slope of Eq. (8) is written in the upper-left corner. The points scatter about a straight line by an amount set by the standard errors in the summary.

walk2d draws the star as a filled circle with its centre marked, each walk in its own colour, a straight ray beyond the edge for each escaped walk, and an x at the end of each walk stopped by the step cap. The annotation box repeats the radius, the mean free path, the reference step count (or, when --radius is given, (given) after the radius instead, since the reference count is then unused), the number of escaped walks and the median escape step count. The axes always leave room for the longest ray.

Suggested Experiments

The experiments are ranked from introductory to advanced, and each is cited by the beat it extends. Each command is run from the program's folder. Leave out --seed to see how much the results change from run to run.

1 · Verify the √N Law — Introductory

Run the default experiment several times without a seed. Check that the ratio column stays near the large-\(N\) prediction, and that the plotted points lie close to a line of slope 1/2, one vertical decade for two horizontal decades.

python main.py --display scaled_distance --max_steps 4096 --n_trials 100

2 · Reduce Statistical Scatter — Introductory

Repeat the calculation with more and more trials. Record the standard error of the last row each time and check that it falls roughly as one over the square root of the number of trials. Notice the trade-off between precision and run time.

python main.py --n_trials 25
python main.py --n_trials 100
python main.py --n_trials 500
python main.py --n_trials 1000

3 · Measure the Log-Log Slope by Hand — Introductory to Intermediate

Take two well-separated rows of the table and compute the exponent \(\alpha\) in \(\langle d\rangle\propto N^\alpha\) from them, as \(\log(d_2/d_1)/\log(N_2/N_1)\). Compare it with the printed fitted slope, which uses all the rows, and repeat with more trials.

python main.py --max_steps 4096 --n_trials 500

4 · Change the Step Distribution — Intermediate

Compare uniform and Gaussian step components with the same seed. The exponent stays at 1/2 and only the constant changes, from 0.9591 to 1. This is one of Schutz's suggested modifications.

python main.py --step_distribution uniform --seed 12
python main.py --step_distribution gaussian --seed 12

5 · Change the Definition of Scaled Distance — Intermediate Programming

Test whether the square-root law depends on dividing by each walk's mean step length. In a separate copy of the program, average net_distance instead of net_distance / mean_step in _perform_trials_3d_with_error(). The constant changes, to 0.9213 for uniform and 1.5958 for Gaussian steps by Eq. (10), but the exponent stays near 1/2.

6 · Mean Free Path and Geometric Scaling — Intermediate

Leave --radius out and change --mean_free_path. With a seed, the escape step counts do not change at all (Beat 6); without one, compare the statistics of many walks.

python main.py --display walk2d --mean_free_path 0.5
python main.py --display walk2d --mean_free_path 1.0
python main.py --display walk2d --mean_free_path 2.0

7 · Individual Walks and Statistical Variety — Intermediate

Display a few walks at a time and compare their shapes and escape step counts. Individual paths look very different although they follow the same rules. Keep the number small enough that the paths can be told apart.

python main.py --display walk2d --n_walks 4
python main.py --display walk2d --n_walks 6
python main.py --display walk2d --n_walks 10

8 · Explore the Escape-Time Distribution — Intermediate to Advanced

Run many walks in a small star and compare the mean, median, minimum and maximum escape step counts. Then lower the step cap until some walks are stopped, and watch the mean of the escaped walks fall (Beat 7).

python main.py --display walk2d --radius 20 --n_walks 500
python main.py --display walk2d --radius 20 --n_walks 500 --step_cap 400

9 · Verify Escape Steps ∝ R² — Advanced

Hold the mean free path fixed and use several radii. For each, divide the mean escape step count by \((R/\lambda)^2\), which the summary prints as mean escape steps / (R / mean free path)^2. Eq. (16) says the result lies between 1 and \((1+\lambda/R)^2\); check it, using the standard error, and check that every walk escaped. Then repeat one radius with --mean_free_path 2: only \(R/\lambda\) matters (Beat 6).

python main.py --display walk2d --radius 30 --mean_free_path 1 --n_walks 100
python main.py --display walk2d --radius 40 --mean_free_path 1 --n_walks 100
python main.py --display walk2d --radius 50 --mean_free_path 1 --n_walks 100
python main.py --display walk2d --radius 60 --mean_free_path 1 --n_walks 100
python main.py --display walk2d --radius 60 --mean_free_path 2 --n_walks 100

10 · A Photon's Escape from the Sun — Advanced

Use Eq. (16), which holds in three dimensions as well as two, for an order-of-magnitude estimate. Take a solar radius of \(7\times10^{8}\) m and suppose, very roughly, that the photon mean free path were 1 cm everywhere. How many steps would escape take, and how long would that be if each step took \(\lambda/c\)? Then say which assumptions of the estimate are the weakest, using the limitations in the Overview: the mean free path changes enormously with depth, and the outer part of the Sun carries its energy by convection. Treat the answer only as an order of magnitude.

11 · Read the Result Objects — Advanced Programming

Every number in the summary is available from the driver's results. Run this script from the program's folder, compare its numbers with the last row of the table in Beat 0 and the mean in Beat 4, and then extend it, for example to make a histogram of the escape step counts.

import random2_physics as physics
from random2_driver import run_scaled_distance_statistics, run_walk2d, escape_statistics

physics.seed_generator(12)
table = run_scaled_distance_statistics(4096, 100, "uniform")
print(table.lengths[-1], table.averages[-1], table.standard_errors[-1])

physics.seed_generator(12)
star = run_walk2d(n_walks=200, radius=30.0)
steps = [walk.steps_taken for walk in star.walks if walk.escaped]
print(len(steps), escape_statistics(star).mean)
