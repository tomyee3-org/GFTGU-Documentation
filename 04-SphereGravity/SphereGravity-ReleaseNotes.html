SphereGravity 1.3.0 Release Notes

Version: 1.3.0
Build: 018f4d9c843c
Date: 16 September 2026

Release summary

Version 1.3.0 adds a complete command-line interface and a numerical console report for the shell mass and the seven requested field-comparison radii. The profile physics, plotting behavior, and transparent textbook midpoint implementation remain compatible with version 1.2.0.

Command-line inputs

  • Added --nDiv N for the positive angular-division count, with the existing safety limit of 100,000.
  • Added --outputType acceleration and --outputType relative_difference. The underscore form is safe as one command-line token and maps to the legacy internal selector relative difference.
  • Added --epsilon VALUE, exposing the driver’s previously unreferenced optional mass-scale input. Values must be positive and finite.
  • Retained --version and added defaults to the live --help output.
  • Expanded the main.py module description with the meaning, accepted values, and tradeoffs of every input.

New printed results

  • Every run prints the numerical midpoint shell mass, the exact continuum mass 4π ε R2, and their signed relative difference.
  • Every run prints predicted numerical acceleration and exact continuum acceleration at r = 0.5, 0.995, 1.005, 2, 3, 4, and 5.
  • Exterior rows include the signed relative difference from the continuum result. At the two interior radii, where the exact field is zero and a relative difference is undefined, the report says undefined and supplies the mass-normalized residual g/M.
  • The requested r = 5 value is evaluated directly even though the standard plot grid ends at 4.995.
  • Console numerical results are formatted to five significant figures.

Physics and implementation additions

  • Added compute_continuum_shell_mass() for the exact thin-shell mass.
  • Added compute_acceleration_at_radii(), a validated direct midpoint evaluator for arbitrary nonsurface radii. It follows the same visible latitude-ring calculation as the textbook profile function.
  • Kept the profile’s existing relative-difference definition: the exterior plot uses the finite numerical mass to isolate field-integration error, whereas the new console comparison uses the continuum mass as the expected physical value.

Documentation

  • Reworked Quick Start and parameter tables around command-line examples following the StellarEvolutionTracks documentation pattern.
  • Documented both selector choices, their physical meanings, and the command-line underscore convention.
  • Added a Printed Results section explaining the mass comparison, all seven fixed radii, five-significant-figure formatting, and the zero-denominator issue inside the shell.
  • Updated non-programming exercises to use command-line parameters while retaining exercises that genuinely require code changes.
  • Updated the Sample Outputs Guide with current commands and the complete default console transcript.

Verification

The regression suite now contains 74 tests. New coverage checks all driver inputs at the command line, selector mapping, invalid legacy selector spelling, the continuum mass helper, arbitrary-radius validation, independent reference values at every requested radius, the printed report, and portable Help-file discovery. The four core Python files also continue to parse as Python 3.10 source.

Known limitations

  • The ideal thin-shell field is discontinuous at r = 1, so that exact point remains omitted and the returned profile retains its compatibility placeholder.
  • Finite angular tiling is least accurate immediately beside the shell; the 0.995 and 1.005 report rows deliberately expose this resolution effect.
  • A conventional relative difference cannot be defined inside the shell because the continuum expected acceleration is zero.
  • The default implementation favors instructional clarity over speed. The optional bounded-vectorized implementation remains available for performance experiments.
  • The Help file uses MathJax from a public CDN; offline, formulas remain readable as TeX source but are not typeset.
