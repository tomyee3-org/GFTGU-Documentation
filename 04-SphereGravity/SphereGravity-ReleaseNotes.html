SphereGravity 1.3.0 Release Notes

Version: 1.3.0
Build: 018f4d9c843c
Date: 16 September 2026

Release summary

Version 1.3.0 adds a complete command-line interface and a numerical console report for the shell mass and the seven requested field-comparison radii. The profile physics, plotting behavior, and transparent textbook midpoint implementation remain compatible with version 1.2.0.

Command-line inputs

  • Added --nDiv N for the positive angular-division count, with the existing safety limit of 100,000.
  • Added --outputType acceleration and --outputType relative_difference. The underscore form is safe as one command-line token and maps to the legacy internal selector relative difference.
  • Added --epsilon VALUE, exposing the driver’s previously unreferenced optional mass-scale input. Values must be positive and finite.
  • Retained --version and added defaults to the live --help output.
  • Expanded the main.py module description with the meaning, accepted values, and tradeoffs of every input.

New printed results

  • Every run prints the numerical midpoint shell mass, the exact continuum mass 4π ε R2, and their signed relative difference.
  • Every run prints predicted numerical acceleration and exact continuum acceleration at r = 0.5, 0.995, 1.005, 2, 3, 4, and 5.
  • Exterior rows include the signed relative difference from the continuum result. At the two interior radii, where the exact field is zero and a relative difference is undefined, the report says undefined and supplies the mass-normalized residual g/M.
  • The requested r = 5 value is evaluated directly even though the standard plot grid ends at 4.995.
  • Console numerical results are formatted to five significant figures.

Physics and implementation additions

  • Added compute_continuum_shell_mass() for the exact thin-shell mass.
  • Added compute_acceleration_at_radii(), a validated direct midpoint evaluator for arbitrary nonsurface radii. It follows the same visible latitude-ring calculation as the textbook profile function.
  • Kept the profile’s existing relative-difference definition: the exterior plot uses the finite numerical mass to isolate field-integration error, whereas the new console comparison uses the continuum mass as the expected physical value.

Documentation

  • Reworked Quick Start and parameter tables around command-line examples following the StellarEvolutionTracks documentation pattern.
  • Documented both selector choices, their physical meanings, and the command-line underscore convention.
  • Added a Printed Results section explaining the mass comparison, all seven fixed radii, five-significant-figure formatting, and the zero-denominator issue inside the shell.
  • Updated non-programming exercises to use command-line parameters while retaining exercises that genuinely require code changes.
  • Updated the Sample Outputs Guide with current commands and the complete default console transcript.

Verification

The regression suite now contains 74 tests. New coverage checks all driver inputs at the command line, selector mapping, invalid legacy selector spelling, the continuum mass helper, arbitrary-radius validation, independent reference values at every requested radius, the printed report, and portable Help-file discovery. The four core Python files also continue to parse as Python 3.10 source.

Known limitations

  • The ideal thin-shell field is discontinuous at r = 1, so that exact point remains omitted and the returned profile retains its compatibility placeholder.
  • Finite angular tiling is least accurate immediately beside the shell; the 0.995 and 1.005 report rows deliberately expose this resolution effect.
  • A conventional relative difference cannot be defined inside the shell because the continuum expected acceleration is zero.
  • The default implementation favors instructional clarity over speed. The optional bounded-vectorized implementation remains available for performance experiments.
  • The Help file uses MathJax from a public CDN; offline, formulas remain readable as TeX source but are not typeset.

SphereGravity 1.2.0 Release Notes

Version: 1.2.0
Build: 35c1d2c0dd16
Date: 2026-08-29

Release Status

Version 1.2.0 concludes the kickoff review, Audit1 review cycle, and Audit2 verification process. The program was reviewed by Codex, Microsoft Copilot, and Gemini. Reviewers verified the numerical implementation of Newton's shell theorem, the Java-to-Python translation, Help-file accuracy, plotting behavior, version/build synchronization, input validation, and regression-test coverage. All identified release issues were addressed before final review. Audit2 concluded with release recommendations from both Copilot and Gemini and no remaining release-blocking defects.

Major Improvements in This Release

  • Restored the transparent textbook midpoint-integration implementation as the default execution path so students can directly follow the numerical method developed in Schutz's Investigation 4.3.
  • Added an optional optimized implementation using bounded NumPy vectorization for performance comparisons while preserving identical physics, signatures, and return values.
  • Introduced reusable ring-geometry precomputation for the optimized implementation, eliminating repeated trigonometric evaluation and ring-mass construction.
  • Achieved approximately 46.5× speedup at nDiv = 1000 in relative-difference mode while maintaining numerical agreement to floating-point precision.
  • Added a resource-safety limit of 100,000 angular divisions and corresponding validation, Help documentation, and regression protection.
  • Preserved the legacy surface placeholder value at r = 1 in returned data while introducing a plotting-only NaN gap so the graph correctly displays the shell-surface discontinuity.
  • Strengthened plot validation by rejecting negative, duplicate, and non-monotonic radii in addition to existing shape, type, and finiteness checks.
  • Added reproducible BUILD_ID generation with controlled-fixture verification, universal-newline normalization tests, and explicit fallback testing for damaged or unavailable source files.
  • Added independent shell-theorem validation against the analytical continuum solution in addition to Java-reference consistency tests.
  • Expanded the Help file with clarified sign conventions, improved discussion of the shell-surface omission, documentation of the optimized implementation, and a new advanced vectorization exercise.

Test Suite Growth

The original regression suite was expanded from 47 automated tests to 65 automated tests. The suite now verifies textbook and optimized implementation equivalence; BUILD_ID generation and fallback behavior; shell-mass convergence; analytical shell-theorem agreement; NumPy scalar validation; plotting-domain constraints; plotting discontinuity handling; Help-file structure; local navigation targets; MathJax integration; command-line execution; version reporting; and headless end-to-end execution.

The final suite verifies that the textbook implementation remains the selected default behavior, confirms numerical agreement between textbook and optimized algorithms in both output modes, and includes a high-resolution nDiv = 10,000 regression using the optimized implementation. The final reported audit run completed with all 65 tests passing.

Known Limitations

  • SphereGravity is intended for education and conceptual exploration of Newton's shell theorem rather than research-grade gravitational modeling.
  • The shell is represented by a midpoint-rule angular tiling. Numerical errors decrease with increasing angular resolution but do not vanish completely at finite nDiv.
  • The exact shell surface at r = 1 is intentionally omitted because the idealized thin-shell field is discontinuous there. Returned arrays contain a compatibility placeholder at that radius.
  • The default implementation prioritizes transparency and pedagogical value over execution speed.
  • The optimized implementation is available for performance comparison but is not the default instructional pathway.
  • The program evaluates 1000 radial sample locations from r = 0 to r = 4.995 and is not intended to provide arbitrary radial sampling.
  • The Help file loads MathJax from a public CDN. When offline, equations remain visible as TeX source but are not typeset.

Known Minor Maintenance Items

  • The plotting API intentionally owns display behavior and does not return matplotlib figure or axis objects.
  • Runtime type annotations remain intentionally conservative because the validated interface accepts both Python numeric types and NumPy scalar types.
  • Repository-level validation of related-program documentation links remains outside the scope of the module-local regression suite.
  • The textbook implementation still contains deliberately explicit computations that could be further optimized; maintaining instructional clarity remains the higher priority.
