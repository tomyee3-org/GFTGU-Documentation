Star 1.1.0 Release Notes

Version: 1.1.0
Build: 35c2e676d666
Date: 2026-09-16

Release Summary

Star 1.1.0 adds a complete command-line interface and a five-significant-digit stellar-structure summary. The underlying Newtonian polytropic integration, default physical model, surface treatment, and plots retain their established behavior.

Command-Line Interface

  • --p_c, --T_c, --mu, and --gamma set the physical inputs. The parser requires positive finite values and requires gamma > 1.2.
  • --max_points and --steps_per_scale expose both driver controls, including the defaults that were previously assigned only in main.py.
  • --output_type selects pressure, density, temperature, or mass; each alternative and its units are described in main.py and Help.
  • --log_y requests a logarithmic vertical axis. The entry point rejects its use with mass because enclosed mass is zero at the center.
  • --help prints descriptions and defaults, while --version prints the synchronized version and reproducible Build ID.

Printed Structure Summary

  • Every run prints the modeled surface radius and total mass in SI units.
  • Pressure, density, temperature, and mass enclosed are printed at 0%, 25%, 50%, 75%, and 90% of the modeled surface radius.
  • Checkpoint values are evaluated by linear interpolation between adjacent stored radial points rather than choosing a nearby grid point.
  • All reported numerical values use five significant figures. The selected plot does not change the printed structure summary because every integration computes all four profiles.

Documentation and Verification

  • The Help file now includes a command-line quick start, full option table, selector explanations, and commands for all parameter-only suggested experiments.
  • The multi-region equation-of-state exercise remains explicitly identified as a programming extension that cannot be completed by changing command-line inputs alone.
  • The Sample Outputs Guide includes the complete default console summary and command-line equivalents for all four embedded figures.
  • The regression suite now contains 74 tests covering command defaults and forwarding, input rejection, all output selectors, log-axis behavior, checkpoint locations and interpolation, five-significant-digit output, Help synchronization, numerical physics, and Build-ID reproduction.
  • The packaged-layout Help lookup now supports the documented sibling 08-Star directory as well as a flattened upload.

Example Commands

python main.py
python main.py --output_type density --log_y
python main.py --T_c 2.4893e7 --steps_per_scale 800 --max_points 4000
python main.py --mu 1 --gamma 2 --p_c 1.9888e34 --T_c 1.1188e12 \
    --max_points 5000 --output_type mass

Known Limitations

  • Star is intended for education and conceptual exploration, not research-grade stellar modeling.
  • The model is Newtonian, spherically symmetric, and governed by one polytropic equation of state. It omits energy generation and transport, composition gradients, rotation, magnetic fields, and relativistic gravity.
  • The default parameters reproduce approximately the Sun's total mass and radius but do not constitute a high-accuracy solar-interior model.
  • The forward-Euler integrator has first-order global accuracy. Increasing --max_points does not refine an already successful run; refinement requires increasing --steps_per_scale while preventing a restart.
  • The step-doubling restart increases radial coverage at the cost of resolution and is not an error-controlled adaptive integrator.
  • The modeled surface and the newly reported interior checkpoints use linear interpolation. The fractional surface shell retains the forward-Euler left-endpoint density and is first-order accurate.
  • The red-giant and neutron-star exercises are schematic. Real neutron-star calculations require dense-matter equations of state and general relativity.
  • The Help file uses MathJax from a public CDN for typeset equations; prose and raw equation source remain readable offline.

The reviewers compared the Python implementation with Bernard Schutz's original Java source; verified the ideal-gas normalization, polytropic equation of state, Newtonian hydrostatic-equilibrium and mass-continuity equations, central initialization, numerical integration, surface handling, input validation, floating-point behavior, plotting, Help-file accuracy, Version/Build synchronization, and regression coverage; and tested both canonical and flattened upload layouts. Copilot and Gemini both give final, unconditional approval for release, and the program is sufficiently robust, accurate, and clear for student use within the tutorial scope and limitations described below.

Major Improvements in This Release

  • Verified that the Python program preserves Schutz's Newtonian stellar model: central density from the ideal-gas relation, a single normalized polytropic equation of state, hydrostatic equilibrium, enclosed-mass continuity, and regularized initialization near the stellar center.
  • Confirmed point-for-point agreement with an independent transcription of the complete positive-pressure prefix produced by the supplied Java recurrence, with five frozen numerical anchors from the first nonzero point through the final positive-pressure point.
  • Added an independent analytic benchmark for the n = 1 Lane–Emden polytrope and verified that radius and mass errors decrease under radial refinement as expected for the documented first-order method.
  • Improved the Java stopping behavior by linearly interpolating the final pressure crossing and returning an explicit modeled surface with p = ρ = T = 0.
  • Documented that the fractional final shell retains the forward-Euler left-endpoint density and therefore slightly overestimates that small shell's mass at first order.
  • Added systematic validation for non-finite and nonpositive central inputs, invalid polytropic exponents, malformed numerical controls, unsupported output modes, non-finite derived quantities, and genuinely unrepresentable floating-point results.
  • Added range-aware central-density arithmetic that avoids both demonstrated intermediate overflow and intermediate underflow while preserving the exact default calculation.
  • Bounded the step-doubling restart mechanism and added regression coverage proving that a model which never reaches zero pressure terminates with an explanatory error rather than looping indefinitely.
  • Derived the runtime output choices from one Literal definition, centralized the zero-temperature surface convention in the physics layer, and retained all four profiles—pressure, density, temperature, and enclosed mass—in every result.
  • Made plot_star_structure() return its Matplotlib figure and axes while preserving normal screen display; added strict boolean validation for log_y; and ensured rejected plot requests do not leak unused figures.
  • Corrected the advanced scaling exercise to distinguish fixed-γ parameter variations from a genuinely fixed-K Lane–Emden sequence, including the correct co-variation of central temperature and pressure and the corresponding radius and mass exponents.
  • Structurally synchronized the student-editable literal assignments in main.py with the named defaults in the Help parameter table by parsing Python syntax and HTML structure rather than relying on substring matches.
  • Added a reproducible core BUILD_ID across the four executable modules, with universal-newline normalization, independent hash reproduction, a controlled damaged-source fallback, and synchronization across source, Help, command-line output, and result metadata.

Test Suite Growth

A new 54-test regression suite was created at kickoff and expanded to 70 automated tests during the audit process. The suite defines the four core module filenames and uses find_module_dir(start) to locate the nearest directory containing all four, so the same test file works from the canonical tests/ directory or when flattened beside the program modules.

The final suite verifies physical constants and equations; input domains and derived-value failures; central and surface conditions; array consistency and profile monotonicity; the ordinary Euler recurrences; all four output modes; successful and exhausted restarts; documented pressure, temperature, molecular-weight, and fixed-K scalings; the analytic n = 1 Lane–Emden solution and convergence; complete source-based Java recurrence agreement and frozen numeric anchors; extreme central-density range cases; plotting labels, logarithmic behavior, strict booleans, returned figure/axes objects, and figure-leak prevention; command-line execution; structural synchronization of main.py defaults with the Help table; Help scientific content; Python 3.10 grammar compatibility; and independent Build-ID reproduction and failure behavior. All 70 tests pass under CPython 3.12.13, and the four core files parse successfully when restricted to CPython 3.10 grammar.

Known Limitations

  • Intended for education and conceptual exploration rather than research-grade stellar modeling.
  • The model is Newtonian, spherically symmetric, and governed by one polytropic equation of state. It omits nuclear energy generation, radiative and convective energy transport, composition gradients, rotation, magnetic fields, and relativistic gravity.
  • The default parameters reproduce approximately the Sun's total mass and radius but do not constitute a high-accuracy solar-interior model. The default central temperature, central density, and effective molecular-weight parameter differ substantially from realistic solar-core values.
  • The forward-Euler integrator has first-order global accuracy. Increasing max_points does not refine an already successful run; convergence studies must increase steps_per_scale while keeping restart_count at zero.
  • The step-doubling restart increases radial coverage at the cost of resolution and is not an error-controlled adaptive integrator.
  • The modeled surface radius is obtained by linear interpolation along the final Euler pressure segment. The fractional surface-shell mass uses the left-endpoint density and is only first-order accurate.
  • The program requires γ > 6/5 so the mathematical polytrope has an ordinary finite zero-pressure radius. The discussion of γ = 4/3 stability is deliberately qualified and should not be applied as a universal classification of real stars.
  • The red-giant and neutron-star exercises are schematic polytropic experiments. Real red giants have differentiated interiors, and realistic neutron-star calculations require non-ideal dense-matter equations of state and general relativity.
  • Finite-range checks are selective safeguards at important stages. The supported domain is physically meaningful teaching inputs, not every arbitrary combination of extreme finite binary64 values throughout the Euler pipeline.
  • The Help file loads MathJax from a public CDN. Offline, its prose and unrendered TeX source remain available, but equations are not typeset.
