Overview

Multiple simulates the Newtonian gravitational motion of two or more point masses in three dimensions. Every body is integrated dynamically and exerts gravity on every other body.

The user supplies masses in solar-mass units, three-dimensional initial positions and velocities, and numerical controls. Output can be either a static trajectory plot through all accepted integration states or a precomputed animation sampled at uniform intervals of physical simulation time.

The default example is a planar three-body encounter in the spirit of Schutz's example: three equal-mass stars approach one another, exchange energy and angular momentum, and can form a temporary or long-lived binary while the third body moves onto a much wider trajectory. Longer integrations reveal repeated encounters and binary hardening.

Scope: Bodies are Newtonian mathematical point masses. The program does not model finite stellar radii, physical collisions, tides, relativity, gas, or dissipative processes. Exact coincidence of two point masses is singular and terminates with an error.

Quick Start

Requirements

Python 3.10 or later with numpy and matplotlib. You may run the program from a terminal or from the run command of any Python IDE:

pip install numpy matplotlib

Running the Program

cd GFTGU-Programs/Multiple
python main.py

The default calculation contains three \(1\,M_\odot\) bodies at \((4.6\times10^{10},0,0)\) m, \((-4.6\times10^{10},0,0)\) m, and \((0,4.6\times10^{10},0)\) m. Their initial velocities are \((0,0,0)\), \((0,-3.0\times10^4,0)\), and \((-3.0\times10^4,0,0)\) m s\(^{-1}\), so the default encounter is initially planar.

The default output is an animation with short trails. The integrator may reduce its timestep below the 2000-s maximum during close encounters, but animation frames remain uniformly separated by physical simulation time.

The shipped 60,000-step run uses eps1=0.005 and eps2=1.0e-7. On the reference calculation used for this release, it reached approximately \(1.878\times10^7\) s with maximum fractional energy drift about \(3.23\times10^{-4}\). Results can vary after students change the initial conditions, so the printed diagnostics must still be checked for every experiment.

Check numerical reliability: close encounters can make a point-mass calculation difficult. Watch the conservation-drift values printed in the console. If the energy drift becomes large, repeat the run with a smaller dt and/or tighter tolerances before interpreting the later trajectory physically.

Customising the Simulation

  • n_bodies — number of point masses
  • masses_solar — one mass per body, in solar units
  • positions_init — one [x,y,z] position per body, in metres
  • velocities_init — one [vx,vy,vz] velocity per body, in m/s
  • dt — maximum adaptive timestep
  • max_steps — maximum accepted integration steps
  • eps1, eps2 — timestep and corrector tolerances
  • output_type — 'trajectories' or 'animation'
  • animation controls — mode, frame spacing, trail duration, projection, and axis behavior
For first experiments: change only masses_solar, positions_init, velocities_init, max_steps, output_type, projection, and animation_mode. Leave eps1 and eps2 unchanged until you try the numerical-convergence exercise.
Memory usage: 'trajectories' stores every accepted position and velocity state. 'animation' stores only uniformly timed movie frames, so its memory use depends mainly on the number of frames rather than on the number of adaptive integration steps.

Program Files

main.py
Entry Point & Configuration

Contains all ordinary user settings: masses, initial states, adaptive integration controls, output mode, animation controls, projection, and the optional energy-drift plot.

physics_multiple.py
Physics & Diagnostics

Computes all pairwise Newtonian accelerations using the nominal solar mass parameter \(GM_\odot\), and provides scaled total energy, linear momentum, and angular momentum for conservation checks.

driver_multiple.py
Adaptive Integration

Uses a predictor and iterated trapezoidal corrector. Each body's acceleration and corrector convergence are tested independently; a failed attempt is retried with half the timestep, while successful steps allow gradual recovery toward the user-specified maximum. Animation frames are sampled by cubic-Hermite interpolation at uniform physical times.

plot_multiple.py
Plots & Animation

Provides static trajectory plots, an optional energy-drift plot, and the interactive animation with current-position or trail display, three orthogonal projections, fixed or automatic equal-scale axes, and keyboard playback controls.

N-Body Problem

The Newtonian \(N\)-body problem follows \(N\) mutually gravitating point masses. Unlike MercPert, no primary orbit is prescribed and no body is dynamically privileged: every body's motion responds to all the others.

The state of body \(A\) is its position \(\mathbf r_A=(x_A,y_A,z_A)\) and velocity \(\mathbf v_A=(v_{x,A},v_{y,A},v_{z,A})\).

All positions and velocities must be expressed in one common inertial Cartesian frame. A center-of-mass frame is often the clearest choice because it removes an uninformative overall drift from the display.

Visualisation: The calculation is fully three-dimensional. Static plots and animations can display the xy, xz, or yz projection without changing the physical initial conditions.

Equations of Motion

The gravitational acceleration on body \(A\) due to body \(B\) is given by Newton's law of universal gravitation, directed from \(A\) toward \(B\):

(1) \[ \mathbf{a}_{A \leftarrow B} \;=\; \frac{G\,m_B}{r_{AB}^3}\,\bigl(\mathbf{r}_B - \mathbf{r}_A\bigr) \]

where \(r_{AB} = |\mathbf{r}_A - \mathbf{r}_B|\) is the scalar separation between the two bodies. The total acceleration on body \(A\) is the vector sum over all other bodies:

(2) \[ \ddot{\mathbf{r}}_A \;=\; \sum_{\substack{B=0 \\ B \neq A}}^{N-1} \frac{G\,m_B}{r_{AB}^3}\,\bigl(\mathbf{r}_B - \mathbf{r}_A\bigr) \]

In the code, masses are stored in solar-mass units and the constant \(k = G\,M_\odot\) is factored out, so the acceleration on \(A\) due to \(B\) is written as:

(3) \[ \mathbf{a}_{A \leftarrow B} \;=\; \frac{k\,\tilde{m}_B}{r_{AB}^3}\,\bigl(\mathbf{r}_B - \mathbf{r}_A\bigr) \]

where \(\tilde{m}_B\) is the mass of body \(B\) in solar-mass units and the program uses the IAU nominal solar mass parameter \(GM_\odot = 1.3271244\times10^{20}\,\mathrm{m^3\,s^{-2}}\).

Pair-Loop Acceleration

Each unordered pair \(A,B\) is evaluated once. With \(\boldsymbol{\Delta}_{AB}=\mathbf r_B-\mathbf r_A\),

(4) \[ \mathbf F_{A\leftarrow B}=-\mathbf F_{B\leftarrow A}, \]

but the accelerations are generally not equal and opposite when the masses differ:

(5) \[ m_A\mathbf a_{A\leftarrow B} =-m_B\mathbf a_{B\leftarrow A}. \]

Using masses \(\tilde m\) in solar-mass units and the nominal solar mass parameter \(GM_\odot\), the pair contributions are

(6) \[ \mathbf a_A \mathrel{+}= \frac{GM_\odot\,\tilde m_B}{r_{AB}^3}\boldsymbol{\Delta}_{AB}, \qquad \mathbf a_B \mathrel{-}= \frac{GM_\odot\,\tilde m_A}{r_{AB}^3}\boldsymbol{\Delta}_{AB}. \]

There are \(N(N-1)/2\) unique pairs per force evaluation, giving direct all-pairs force calculation its familiar \(\mathcal O(N^2)\) scaling.

Conservation Diagnostics

The exact isolated Newtonian point-mass problem conserves total mechanical energy, total linear momentum, and total angular momentum. Multiple tracks all three as numerical diagnostics.

(7) \[ E = \frac12\sum_A m_A v_A^2 -\sum_{A<B}\frac{Gm_A m_B}{r_{AB}} . \]
(8) \[ \mathbf P=\sum_A m_A\mathbf v_A, \qquad \mathbf L=\sum_A m_A\,\mathbf r_A\times\mathbf v_A . \]

Because input masses are given in solar units, the program omits one common solar-mass factor from energy, momentum, and angular momentum. This does not affect conservation tests. The console reports the maximum drift in all three quantities. If the initial energy is exactly zero, or if a conserved vector's initial norm is exactly zero, its reported drift is an absolute scaled drift rather than a fractional one. The energy-drift plot labels that zero-energy case explicitly. In 'trajectories' mode, the complete histories are returned and plot_energy_drift() can display the energy error versus time.

Negative total energy: \(E<0\) means the system as a whole has negative mechanical energy; it does not require every body to remain bound. A tightly bound negative-energy binary can coexist with an escaping third body.

Computational Scaling

Every acceleration evaluation requires \(N(N-1)/2\) pair calculations. The number of force evaluations is larger than the number of accepted steps because rejected timestep attempts and corrector iterations require additional evaluations. Thus runtime is approximately proportional to

(9) \[ \text{force evaluations}\times\frac{N(N-1)}{2}. \]

Predictor–Corrector

For each attempted timestep, an explicit predictor first estimates the endpoint:

(10) \[ \tilde{\mathbf r} =\mathbf r^n+\mathbf v^n\Delta t +\tfrac12\mathbf a^n\Delta t^2, \qquad \tilde{\mathbf v} =\mathbf v^n+\mathbf a^n\Delta t . \]

If the acceleration-change test passes, the endpoint is refined by an iterated trapezoidal corrector:

(11) \[ \mathbf v^{n+1} =\mathbf v^n+\frac{\mathbf a^n+\mathbf a^{n+1}}2\Delta t, \qquad \mathbf r^{n+1} =\mathbf r^n+\frac{\mathbf v^n+\mathbf v^{n+1}}2\Delta t . \]

The endpoint acceleration is recomputed from the refined positions and the correction is iterated up to ten times. If convergence is still not achieved, the timestep is halved and the entire step is retried.

Adaptive Timestep

The preliminary eps1 test is performed separately for every body:

(12) \[ \delta_{a,A}= \frac{\|\tilde{\mathbf a}_A-\mathbf a_A\|} {\max(\|\tilde{\mathbf a}_A\|,\|\mathbf a_A\|)} . \]

If the largest value over all bodies exceeds eps1, the attempted step is rejected and \(\Delta t\) is halved. Testing bodies individually prevents one violent close encounter from being diluted by the quieter accelerations of many unrelated bodies.

An accepted step is an attempted adaptive timestep that passes both the predictor and corrector tests and is actually used to update the system. After an accepted step, the working timestep grows by 10% toward the user-specified maximum dt. A close encounter can therefore demand short steps temporarily without forcing the entire remainder of the simulation to crawl at that resolution.

Convergence Criteria

eps2 controls convergence of the iterated corrector. For each body the program compares successive estimates of the velocity increment over the attempted step,

(13) \[ \delta_{v,A}= \frac{\|\Delta\mathbf v_{A,\mathrm{new}}- \Delta\mathbf v_{A,\mathrm{old}}\|} {\max(\|\Delta\mathbf v_{A,\mathrm{new}}\|, \|\Delta\mathbf v_{A,\mathrm{old}}\|)} . \]

The corrector has converged only when the largest \(\delta_{v,A}\) is below eps2. Using increments rather than absolute coordinate velocities makes this convergence test unchanged by adding a uniform velocity to the whole system. The program requires \(0<\varepsilon_2<\varepsilon_1<1\).

Output Modes

'trajectories' stores every accepted position and velocity state and plots the complete paths. 'animation' precomputes uniformly timed movie frames and therefore uses memory according mainly to the number of frames rather than the integration-step count.

Uniform Physical-Time Frames

With frame_time = 2.0e5, requested frames occur at \(t=0,\;2\times10^5,\;4\times10^5,\ldots\) s. The accepted adaptive integration states rarely land exactly on these times, so the display positions are obtained by cubic Hermite interpolation using the positions and velocities at both ends of the bracketing accepted step. Adaptive timestep reductions therefore increase calculation work without changing the apparent movie speed.

Current Positions and Trails

animation_mode='current positions' shows only the moving body markers. 'trails' additionally displays each body's recent path for the preceding trail_time seconds of simulated time.

Projection and Axes

projection selects 'xy', 'xz', or 'yz'. axis_mode='fixed' calculates one viewing window from all movie frames. 'auto' follows the currently visible bodies and trails, but always uses the same numerical span on both axes so the spatial scale remains 1:1 rather than stretching the picture.

Keyboard Controls

Space pauses or resumes from the currently displayed frame. Left/Right pause and step one frame. Home pauses at the first frame and End pauses at the last frame. Pressing Space while the final frame is displayed replays the movie from the beginning.

Suggested Scenarios

All of these experiments can be performed by editing main.py.

Two-body sanity check
Before exploring chaotic three-body motion, test a familiar binary. For two equal one-solar-mass bodies separated by \(1.0\times10^{11}\) m, put them at \((\pm5.0\times10^{10},0,0)\) m and give them opposite tangential speeds of about \(2.576\times10^4\) m/s. The center of mass should remain fixed while the bodies follow nearly circular paths. Check the reported energy and angular-momentum drift.
Default three-body encounter
Run the planar shipped example first. Record which two bodies make the closest sustained pair, whether the third makes a wide excursion, and the reported conservation drift. Extend max_steps if you want to watch later encounters, but do not expect a short run to reveal a unique final fate.
Change the masses
Keep the default positions and velocities but reassign the three masses. How often does a close encounter produce a bound pair? Which body is most often left on the widest orbit? This is a simple way to explore the sensitivity of three-body outcomes without changing the geometry.
Out-of-plane encounter
Add a modest \(z\)-velocity to one body and compare the 'xy' and 'xz' projections. Try (1\) km/s first and then (5\) km/s. Choose the vertical speed so that the bodies' \(z\)-separations near closest approach are comparable to their in-plane separations. If the vertical speed is too large, the bodies may simply miss one another and the interesting encounter disappears.
Numerical convergence
Repeat the same physical initial conditions with dt, dt/2, and dt/4; then repeat with tighter eps1 and eps2. Compare finite-time trajectories and the reported conservation drift. For sensitive three-body motion, long-term trajectories can eventually separate even when both integrations are individually accurate.
Center-of-mass frame
First add the same velocity vector to every body and observe the overall drift across the plot. Then calculate \(\mathbf R_{\rm CM}=\sum_A m_A\mathbf r_A/\sum_A m_A\) and \(\mathbf V_{\rm CM}=\sum_A m_A\mathbf v_A/\sum_A m_A\), and subtract them from all initial positions and velocities. Confirm that the relative motion is unchanged while the center of mass remains at rest, and relate this result to conservation of total momentum.
Binary hardening
In a run where two bodies form a persistent close pair, track all three pair separations to identify the binary rather than relying only on the plot. Compare the third body's distance from that pair's center of mass before and after later encounters. Does the binary shrink or widen, and where does the corresponding orbital energy go?
Small star cluster
Place 5–10 solar-mass stars within about 0.1 pc. Contrast sub-km/s to roughly 1 km/s starting speeds with several-km/s speeds. For a cleaner display, subtract the initial center-of-mass position and velocity from all bodies. Compare total energy, expansion of the cluster, and any ejections; then try adding one or two more massive bodies.
Compare with MercPert — advanced
Recreate the same physical Sun–perturber–test-particle configuration, but express every body's initial state in one inertial frame for Multiple. A convenient choice is the center-of-mass frame: translate positions if desired and give the Sun the small compensating velocity required to make total momentum zero. Give the test particle a very small nonzero mass. Agreement should be approximate, because MercPert prescribes its primary orbit whereas Multiple integrates all masses mutually; simply copying Sun-relative coordinates is not an exact frame conversion.
Galaxy collision — optional toy model
A concrete starting experiment is two \(10^{11}\,M_\odot\) core particles about 50 kpc apart and approaching at about 100 km/s, each surrounded by several orbiting particles roughly 10 kpc out with speeds of order 300 km/s. First make the orbiting particles negligible in mass: the two cores cannot lose orbital energy to them and tend to pass through. Then give the surrounding particles substantial masses, of order \(10^{10}\,M_\odot\), so orbital energy can be redistributed among many bodies and merger-like behavior can occur. This remains a deliberately crude model: there is no gas, friction, radiation, or other true dissipative physics.

Restoring Default Parameter Values

If you edit main.py or another program file while experimenting, you can restore the original program files using any of the following methods:

  • Same session: Press Ctrl+Z (Windows) or Cmd+Z (macOS) repeatedly in your editor to undo your edits.
  • If you are using PyCharm: Right-click the edited file in the Project panel → Local History → Show History → select a version from before your changes → click Revert.
  • Full reset: Re-download the ZIP from github.com/tomyee3-org/GFTGU-Programs and replace this program's folder with the fresh copy.

For additional ways to restore program files, see the corresponding recovery instructions in the GFTGU Python Setup Guide.
