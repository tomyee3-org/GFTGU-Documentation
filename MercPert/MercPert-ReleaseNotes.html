MercPert 1.1.0 Release Notes

Version: 1.1.0
Build: 9852baf113f7
Date: 2026-09-16

New in This Release

  • Masses, binary separation, test-particle initial conditions, integrator controls, collision radii, plotting units and annotation corner are command-line options; Sun-relative distances also accept AU. --show_jacobi_diagnostic enables the second plot.
  • The printed summary reports circular Sun–companion period, test-particle integration time, sampled Sun-distance limits, maximum fractional Jacobi drift and accepted adaptive controller timestep range to five significant figures.
  • The Help exercises use executable command examples, and the Sample Outputs include the current default console summary and commands for each plot.

Try python main.py --m_planet_solar 9.5e-4 --vy_init 54400 to compare a Jupiter-mass companion with the default low-mass star.

Interpretation

The Sun and companion follow prescribed circular orbits; only the test particle is integrated. The Sun-distance limits are sampled at accepted states. The controller timestep range excludes rejected trial steps and is measured before a collision can shorten the final elapsed step. If no step is accepted there is no timestep range. Fractional Jacobi drift is undefined when the initial Jacobi constant is zero. A collision event is estimated by linear interpolation across an accepted step; the model does not determine long-term stability or escape automatically.

Model Scope

This planar circular restricted three-body model omits the test particle's back-reaction, gas dynamics, relativity and impact physics. Close encounters merit smaller timesteps and tighter convergence settings.

MercPert 1.0.2 Release Notes

Version: 1.0.2
Build: 9ae1fff767c9
Date: 2026-08-28

Release Status

Version 1.0.2 concludes a kickoff maintenance review followed by two rounds of independent review involving Codex, Copilot, and Gemini. The reviewers examined the Python port against Schutz's original Java implementation, the planar circular restricted three-body physics, numerical behavior, validation and error handling, Help-file accuracy, Version/Build synchronization, plotting, and regression coverage. The reviews reported no unresolved scientific or release-blocking defect. The program is suitable as a release candidate for student use within the tutorial model and limitations described below.

Major Improvements in This Release

  • Verified the prescribed barycentric circular motion of the two massive bodies, the Sun-relative input convention for Mercury, conversion to barycentric inertial coordinates, and the simultaneous Newtonian acceleration from both primaries.
  • Retained the adaptive Euler-predictor and iterated trapezoidal-corrector method while replacing componentwise change tests with rotation-invariant vector-relative measures.
  • Added gradual timestep recovery after difficult encounters, growing the accepted working timestep toward the configured maximum.
  • Added validation for Boolean, non-real, non-finite, non-positive, singular, overflow-prone, and underflow-prone inputs and derived values.
  • Added clear failures for corrector exhaustion and timesteps too small to advance floating-point time.
  • Added optional finite-radius collision surfaces, whole-segment moving-boundary detection, termination reporting, and a dedicated collision marker.
  • Added the Jacobi constant and an optional fractional-drift diagnostic for monitoring numerical accuracy.
  • Improved orbit plots with explicit barycentric axis labels, selectable meter or AU units, Sun-relative initial-condition annotation, and one-period reference tracks for the massive bodies.
  • Added executable-core version/build identification across physics_mercpert.py, driver_mercpert.py, main.py, and plot_mercpert.py, synchronized with the Help file and runtime output.
  • Expanded and clarified the Help file, including model limits, collision-event accuracy, finite-time interpretation of orbital outcomes, and a difficulty-ordered set of eight exercises.

Regression Testing

A 61-test regression suite was created and verified in both the canonical tests/ layout and a flattened upload layout. All 61 tests pass in both layouts.

The suite covers program discovery, Build-ID reproduction, Python 3.10 grammar, Help-file structure and synchronization, numeric validation, binary geometry, coordinate conversion, force calculations, singularities, Jacobi behavior, collision geometry, integration invariants, timestep convergence, plotting, command-line version output, and a complete default subprocess run.

An independent SciPy DOP853 comparison over 2,000,000 seconds showed approximately fourfold reductions in position and velocity endpoint error when the timestep was halved from 2000 to 1000 to 500 seconds, consistent with second-order convergence. The 10,000-step default run reached 20,000,000 seconds with a reported maximum fractional Jacobi drift of approximately 1.23e-6.

Known Limitations

  • MercPert is intended for education and conceptual exploration, not precision orbit prediction or research-grade celestial mechanics.
  • The model is planar, circular, and restricted. Mercury has negligible mass and does not affect the two massive bodies.
  • The model does not include gas, disk hydrodynamics, migration, pressure, shocks, planet formation, tides, relativity, accretion, or physical impact evolution.
  • Collision radii are numerical termination surfaces, not models of impact physics. A radius of zero disables the corresponding collision test.
  • Collision times, positions, and velocities are estimated by linear interpolation along the accepted particle and primary segments. Smaller accepted timesteps improve these estimates.
  • The companion can represent different physical objects, so the program does not infer a companion radius from its mass. Users must select a physically appropriate positive radius when collision stopping is required.
  • The program does not automatically classify trajectories as stable or ejected. Such conclusions require explicit distance criteria and a finite observation interval.
  • Severe encounters can produce substantial Jacobi drift under loose settings. Quantitative work should be repeated with smaller timesteps and tighter tolerances.
  • The executable-core BUILD_ID intentionally covers only the four Python program modules. Help-only and test-only edits do not change it, while regression tests verify that the Help file displays the Version/Build pair of the core it documents.
