Major Improvements in This Release

  • Help. Added a Beats-format tutorial Help file, MercPert-claude.html (ten numbered beats, ten governing equations, eight Suggested Experiments), alongside the existing classic Help. No core module changed.
  • Classic Help fix. Experiment 7's example command used a Sun-relative launch speed of 30,000 m/s, only 8,939 m/s in the barycentric frame the orbit is actually measured in, far below the roughly 29,785 m/s a circumbinary orbit at that distance needs; Mercury fell into the binary instead of orbiting outside it. The command now reads --vy_init 50846 --max_steps 40000, with a new paragraph explaining the Sun-relative-versus-barycentric distinction.
  • Terminology. Both Help files now describe the second body as a user-selectable companion throughout; "Jupiter" appears only as a mass reference (for example, "about 100 Jupiter masses").

Known Limitations

  • MercPert is intended for education and conceptual exploration, not precision orbit prediction or research-grade celestial mechanics.
  • The model is planar, circular, and restricted. Mercury has negligible mass and does not affect the two massive bodies.
  • The model does not include gas, disk hydrodynamics, migration, pressure, shocks, planet formation, tides, relativity, accretion, or physical impact evolution.
  • Collision radii are numerical termination surfaces, not models of impact physics. A radius of zero disables the corresponding collision test, and the companion's default radius is zero: for example, the default system's test particle passes within 11,504 km of the companion's centre near day 1448.8 of a 100,000-step run, with fractional Jacobi drift already 0.090 by then, without triggering a stop.
  • Collision times, positions, and velocities are estimated by linear interpolation along the accepted particle and primary segments; smaller accepted timesteps improve these estimates. In a run that ends in a collision, the printed maximum fractional Jacobi drift includes this interpolated endpoint and so can be larger than the integrator's own drift over its accepted steps.
  • The companion can represent different physical objects, so the program does not infer a companion radius from its mass. Users must select a physically appropriate positive radius when collision stopping is required.
  • The program does not automatically classify trajectories as stable or ejected. Such conclusions require an explicit distance-and-energy criterion and a finite observation interval.
  • Severe encounters can produce substantial Jacobi drift under loose settings. Quantitative work should be repeated with smaller timesteps and tighter tolerances.
  • An initial position exactly at the Sun's centre raises a singular-force error rather than a defined result.
  • The executable-core BUILD_ID intentionally covers only the four Python program modules. Help-only and test-only edits do not change it, while regression tests verify that each Help file displays the Version/Build pair of the core it documents.

  • Optional 1.1.1 code changes, not made this release: an initial position exactly at the Sun's centre could take the documented zero-step collision path instead of raising an error; the drift maximum could be computed over accepted integration steps only, excluding an interpolated collision endpoint; a mass-based default companion collision radius, only if Prof. Schutz wants that behavior change.
