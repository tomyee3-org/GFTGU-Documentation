Description

Binary simulates two point masses interacting only through Newtonian gravity. The masses, initial positions, and initial velocities are all editable, so the same program can represent bound binaries, extreme mass-ratio systems, and unbound gravitational encounters.

The spine of the lesson is one sentence: One force law accelerates both bodies; exact motion under it conserves energy; the printed energy is how you tell how far to trust a step-by-step calculation of that motion.

What this program is not. No tides, collisions, relativity, or third body. The integrator is an Euler predictor plus an iterated trapezoidal corrector; error is largest at close approach. A head-on plunge can hit the timestep floor and stop with an error. The one-revolution stop is a geometric rule about the angle swept by the line joining the bodies, not a proof that the path has closed.

Before the first run

Unpack the program zip so you have a folder named Binary that contains main.py. Open a terminal in that folder. You need Python 3.10 or newer with NumPy and Matplotlib. If you do not already have that environment, follow the project-wide GFTGU Python Setup Guide. Then:

python main.py --version
python main.py

Lengths are metres, speeds metres per second, energies joules. Times in the summary are days. Following the code, \(v=\dot x\) and \(u=\dot y\).

Output

Every run prints a summary at the terminal and then opens a plot.

The printed energy table always uses the input (user) frame. With --frame com, the plot title identifies the centre-of-mass view; its kinetic and total energies can differ from the printed ones.

In the summary, the first line gives version and build, accepted steps, how it stopped, total revolutions and time, sampled min/max separation, the Keplerian classification of the starting data, a centre-of-mass block for each body, and an energy table at tenths of the run. A plot window then opens. Close it to end the program. The Keplerian block is not the integrated orbit; compare the two when you want a check.

Beat 0 · Two bodies, one force

Two solar-mass bodies start \(9.2\times 10^{10}\,\mathrm{m}\) apart. Each is given 13 km s\(^{-1}\) sideways, in opposite directions.

python main.py --MA 2e+30 --MB 2e+30 --xInitA 46000000000 --xInitB -46000000000 --yInitA 0 --yInitB 0 \
  --vInitA 0 --vInitB 0 --uInitA 13000 --uInitB -13000 --dt 2000 --eps1 0.05 --eps2 0.0001

Look at the orbits plot and at the six summary lines from Accepted steps to Maximum separation (sampled). The maximum separation is the starting separation, so they begin as far apart as they ever get. The minimum is a fraction of that, so the paths are not circles. The two curves are mirror images through the origin. Termination: one relative revolution is the geometric stop. Write one sentence about how the pull should change if you doubled the separation.

Newton’s law of gravitation
\[ F=\frac{GM_A M_B}{r^2}, \qquad r=\sqrt{(x_A-x_B)^2+(y_A-y_B)^2}. \]

The program uses \(G=6.67430\times 10^{-11}\,\mathrm{m^3\,kg^{-1}\,s^{-2}}\). The force is attractive, acts along the joining line, and is equally strong on both bodies. Doubling \(r\) cuts it to a quarter. That is the whole physical model.

Beat 1 · Who moves, and how much

The force on A equals the force on B. The accelerations do not. Make A twice B and start them circling a common point.

For comparison, the default settings are --MA 2e+30, --MB 2e+30.

python main.py --MA 2e30 --MB 1e30 --xInitA 3.0666666667e10 --xInitB -6.1333333333e10 \
  --uInitA 15550.5265 --uInitB -31101.053

Read the two Body A/B about centre of mass blocks. The semi-major axes should sit in the inverse mass ratio. The periods should match. The plot is two circles about the origin: the centre of mass.

Equations of motion — integrated
\[ \ddot x_A=-\frac{G M_B\,\Delta x}{r^3},\quad \ddot y_A=-\frac{G M_B\,\Delta y}{r^3}, \] \[ \ddot x_B=+\frac{G M_A\,\Delta x}{r^3},\quad \ddot y_B=+\frac{G M_A\,\Delta y}{r^3}. \]

Each body accelerates in proportion to the other mass. Adding \(M_A\mathbf a_A+M_B\mathbf a_B\) gives zero, so the centre of mass moves without acceleration. Measured from it, A sits the fraction \(M_B/(M_A+M_B)\) of the separation away. Equal masses alone do not force \(\mathbf v_A=-\mathbf v_B\); that also needs a centre of mass at rest.

Beat 2 · Only the separation matters

The force depends on the two positions only through \(r\). Give both bodies the same extra velocity, 60 km/s along \(x\), and look at the same run three ways.

For comparison, the default settings are --vInitA 0, --vInitB 0, --xInitA 46000000000, --xInitB -46000000000, --yInitA 0, --yInitB 0.

python main.py --vInitA 60000 --vInitB 60000 --frame user --output_type orbits --xInitA 46000000000 \
  --xInitB -46000000000 --yInitA 0 --yInitB 0
python main.py --vInitA 60000 --vInitB 60000 --frame com --output_type orbits --xInitA 46000000000 \
  --xInitB -46000000000 --yInitA 0 --yInitB 0
python main.py --vInitA 60000 --vInitB 60000 --frame com --output_type energy_vs_time --xInitA 46000000000 \
  --xInitB -46000000000 --yInitA 0 --yInitB 0

Look at the first two plots and at the summary lines from Accepted steps to the two Body A/B about centre of mass blocks. The first plot uses the input frame (--frame user): the centre of mass drifts about \(2.7\times10^{11}\) m to the right during the run, and the bodies trace drifting tracks. The second view follows the centre of mass (COM), the frame in which the total momentum is zero. The Beat 0 ellipses return, each with one focus at the origin. In this Newtonian model the centre-of-mass and centre-of-momentum frames are the same. The subscripts CM in the equations also mean centre of mass.

All three printed summaries are identical. The orbital diagnostics match Beat 0 to the printed figures, but the energy table does not. Row 0.0 shows kinetic energy larger by \(\tfrac12(M_A+M_B)V_{\mathrm{CM}}^2=7.2\times10^{39}\) J and positive total energy, \(E=+4.6361\times10^{39}\) J. Look at the third plot: its total energy is negative, about \(-2.564\times10^{39}\) J, as in Beat 0. Which energy tells you that the pair is bound? Explain why changing the observer's velocity cannot unbind the pair.

This is Galilean relativity: observers moving at constant velocity describe different tracks but the same motion of the bodies relative to one another. The COM view subtracts the mass-weighted centre and velocity, \(\mathbf r'_i=\mathbf r_i-\mathbf R_{\mathrm{CM}}\) and \(\mathbf v'_i=\mathbf v_i-\mathbf V_{\mathrm{CM}}\). The option --frame applies to all seven plots, including energy. It leaves the integration and printed summary in the input frame, so the boosted run still prints positive total energy while its COM energy plot shows negative internal energy.

Shift the start instead. Both commands use the same shifted start; the second views it with --frame com. Compare their plots with Beat 0.

python main.py --xInitA 5e10 --xInitB -4.2e10 --yInitA 1e10 --yInitB 1e10 --vInitA 0 --vInitB 0 --frame user \
  --output_type orbits
python main.py --xInitA 5e10 --xInitB -4.2e10 --yInitA 1e10 --yInitB 1e10 --frame com --vInitA 0 --vInitB 0 \
  --output_type orbits

In the input frame the pair's centre of mass is at \((4\times10^9,1\times10^{10})\) m, and the ellipses move with it. In the COM view that shift disappears. What has changed in the picture, and what has stayed the same in the orbital diagnostics?

A numerical caveat, not a new law. A large boost changes the speeds the corrector compares to, so the two relative paths agree only to the accuracy of the integrator, not to rounding error. A modest boost agrees far more closely.

Beat 3 · Energy separates bound from unbound

Three starting speeds, same masses and same separation. Plot energy against time. Unbound runs never complete a turn, so the one-revolution stop has to come off.

python main.py --output_type energy_vs_time --uInitA 13000 --uInitB -13000 --stop_after_one_orbit \
  --max_steps 10000
python main.py --uInitA 38091.14 --uInitB -38091.14 --no-stop_after_one_orbit --max_steps 1000 --output_type energy_vs_time
python main.py --uInitA 60000 --uInitB -60000 --no-stop_after_one_orbit --max_steps 1000 --output_type energy_vs_time

Read row 0.0 of the energy table and the Initial Keplerian orbit line. \(U\) is the same in all three runs. \(K\) is not. For non-radial motion, negative, zero or positive \(E=K+U\) in the centre-of-mass frame means an elliptic, parabolic or hyperbolic orbit. These equal-and-opposite starts already have zero total momentum, so their input-frame energies are also their internal energies. The middle speed is escape rounded to seven digits; treat the printed eccentricity of 1 as “that rounding.”

Mechanical energy
\[ K=\tfrac12 M_A(v_A^2+u_A^2)+\tfrac12 M_B(v_B^2+u_B^2), \qquad U=-\frac{G M_A M_B}{r}, \qquad E=K+U. \]

The plot of \(E\) looks flat; the column (E-E0)/|E0| is the diagnostic. That column is misleading when \(E_0\) is nearly zero: compare the change in \(E\) with \(K\) instead.

Experiments that go with this beat: Experiment 4 in Suggested Experiments.

Beat 4 · Reading the shape of an orbit

Before any step is taken, the program computes the exact two-body orbit of the starting data and prints it as the Keplerian block. That block is the outside check. Compare a near-circle with the default ellipse, in velocity space.

python main.py --uInitA 26934.5 --uInitB -26934.5 --output_type velocity_space
python main.py --output_type velocity_space --uInitA 13000 --uInitB -13000

On a circle the sampled min and max separations agree. On the default ellipse they do not, and \(r_p v_p=r_a v_a\) at the two apsides. The Keplerian period should match Total time to the figures printed. In velocity space a bound orbit with the centre of mass at rest is a circle whose origin sits inside it; \(e=(v_p-v_a)/(v_p+v_a)\).

Kepler III, and the hodograph
\[ T=2\pi\sqrt{\frac{a^3}{G(M_A+M_B)}},\qquad a=a_A+a_B, \] \[ e=\frac{v_p-v_a}{v_p+v_a}. \]

Total revolutions is the signed angle swept by \(\mathbf r_A-\mathbf r_B\), divided by \(2\pi\). The run stops at the first accepted step that reaches a full turn, so it can overshoot by up to one dt. That is geometry, not closure of the path.

The origin-inside-circle test uses velocities relative to the centre of mass. For the boosted start of Beat 2, add --output_type velocity_space to its first two commands: the origin lies outside both circles in the input-frame view and inside them with --frame com. The pair remains bound in both views.

Beat 5 · The corrector

Two point masses have an exact conic-section solution about the centre of mass. The program integrates anyway, so you can see a method that still works when there is no such solution. Each step is an Euler predictor plus an iterated trapezoidal corrector. --eps2 decides when to stop iterating. It is not the step size.

For comparison, the default settings are --eps2 0.0001.

python main.py --eps2 1e-8 --dt 2000
python main.py --eps2 0.5 --dt 2000

Compare Accepted steps and rows 0.5 and 1.0 of (E-E0)/|E0| with the default eps2=1e-4. Row 0.5 sits at or near closest approach on these apoapsis-start runs. The dip there moves far less than the end-of-orbit residual does when you change eps2. What does move is how completely the energy returns at the end of the orbit. A corrector that actually solves the trapezoid is time-symmetric; an orbit that starts at apoapsis then undoes on the way out much of the error it made on the way in.

Predictor, then trapezoidal corrector — algorithm
\[ \tilde{\mathbf r}=\mathbf r^n+\mathbf v^n\Delta t,\qquad \tilde{\mathbf v}=\mathbf v^n+\mathbf a^n\Delta t, \] \[ \mathbf v^{n+1}=\mathbf v^n+\tfrac12(\mathbf a^n+\mathbf a^{n+1})\Delta t,\qquad \mathbf r^{n+1}=\mathbf r^n+\tfrac12(\mathbf v^n+\mathbf v^{n+1})\Delta t. \]

The end acceleration depends on the end position, so the corrector repeats, at most ten times, until both bodies’ velocities have changed by less than eps2 between passes. If ten passes fail, the step is halved and retried.

Experiments that go with this beat: Experiment 7 in Suggested Experiments.

Beat 6 · The step control

No accepted step is longer than --dt. A step is shortened when the acceleration changes too much across the trial. With the default 2000 s that never happens on this orbit. Make dt ten times larger and watch the controller work.

For comparison, the default settings are --dt 2000.

python main.py --dt 20000 --eps1 0.05
python main.py --dt 20000 --eps1 0.5

The first run takes more steps than \(T/\Delta t\) because many steps around periapsis are shorter than 20,000 s. The second run takes steps of exactly 20,000 s; the dip in row 0.5 and the error in the sampled minimum separation both get worse.

Acceleration-change test — algorithm
\[ \Delta_a=\frac{\lVert\tilde{\mathbf a}_A-\mathbf a_A^n\rVert} {\max(\lVert\tilde{\mathbf a}_A\rVert,\lVert\mathbf a_A^n\rVert)}. \]

If \(\Delta_a>\varepsilon_1\), the trial is rejected and \(\Delta t\) is halved. After an accepted step the working step may grow 10 per cent toward the ceiling dt. Forty halvings in a row hit a floor of \(\mathrm{dt}\times 10^{-12}\) and the run stops with an error. Testing body A is enough: the two accelerations are proportional.

Experiments that go with this beat: Experiment 7 in Suggested Experiments.

Beat 7 · How far to trust it

Halve dt, then tighten eps2 as well. Watch the number you care about, not the tolerance.

For comparison, the default settings are --dt 2000, --eps2 0.0001.

python main.py --dt 1000 --eps2 0.0001
python main.py --dt 500 --eps2 0.0001
python main.py --dt 1000 --eps2 1e-8

The dip at closest approach (row 0.5) falls roughly as \((\Delta t)^2\). The leftover at the end of the orbit (row 1.0) follows eps2 more than dt on this ellipse. A tolerance is not an error bound. Choose the setting by the question: shorter dt for the picture at periapsis, tighter eps2 for what remains in \(E\) after many turns.

The default eccentricity 0.767 is a mild test. An orbit with \(e\approx 0.999\) at the default settings finishes early and drops a few parts in a thousand of its energy at periapsis. A head-on start, --uInitA 0 --uInitB 0, hits the timestep floor.

Experiments that go with this beat: Experiment 7 and Experiment 8 in Suggested Experiments.

Suggested Experiments

1 · Not a circle — Introductory

From the default summary, what fraction of the starting separation is the closest approach? Why does that already rule out a circular orbit?

2 · Who circles whom — Beginner

Run Beat 1. Confirm that \(a_A/a_B=M_B/M_A\) and that the two periods agree. Where is the origin on the plot?

3 · A boost is not unbinding — Beginner

Run the boosted energy view below and compare its negative total energy with row 0.0 of the printed table. Why is the printed total energy positive while the Keplerian line still says elliptic? Which term disappears from the energy in the centre-of-mass frame?

python main.py --vInitA 60000 --vInitB 60000 --frame com --output_type energy_vs_time

Use the orbit and velocity-space views to check the same conclusion visually.

4 · Escape — Intermediate

From Beat 3, compute the relative escape speed \(v_{\mathrm{rel,esc}}=\sqrt{2G(M_A+M_B)/r}\). In the centre-of-mass frame with equal masses each body has half of that. How close is 38091.14 m s\(^{-1}\)? For unequal masses the two speeds relative to the centre of mass split the same relative speed in the inverse-mass ratio; do not substitute a single mass for \(M_A+M_B\).

5 · The hodograph — Intermediate

On the default velocity-space plot, estimate \(e\) from the radius and offset of one body’s circle. Compare with the printed eccentricity.

6 · Fixed star — Intermediate

Give body B a hundred times A’s mass and park it at the origin. Start A at \(4.6\times 10^{10}\,\mathrm{m}\). Give the pair opposite sideways speeds that keep the centre of mass at rest and a relative speed of 500000 m s\(^{-1}\): \(u_A=495049.50495\), \(u_B=-4950.49505\). Circular speed about a fixed \(2\times 10^{32}\,\mathrm{kg}\) mass at that radius is about 539000 m s\(^{-1}\); the two-body relative circular speed is about 541000 m s\(^{-1}\). So this is a mild ellipse (\(e\approx 0.147\)), not a near-radial plunge. A traces an approximately elliptical laboratory path about the stationary centre of mass at \(x\approx 4.55\times 10^{8}\,\mathrm{m}\); it is a 0.990-scaled and translated version of the relative Kepler ellipse. The sampled run need not close exactly. Compare that laboratory track of A with the one-body problem that Orbit integrates at the same mass, radius and relative speed.

python main.py --MB 2e32 --xInitB 0 --yInitB 0 --vInitB 0 --uInitB -4950.49505 --xInitA 4.6e10 --yInitA 0 --vInitA 0 --uInitA 495049.50495

From the Orbit folder, a matched start at the same relative radius and 500000 m s\(^{-1}\) is:

python main.py --xInit 4.6e10 --yInit 0 --vxInit 0 --vyInit 500000 --k 1.33486e22 --dt0 2000 --eps1 0.05 --eps2 0.0001 --maxOrbits 1

Expect about 218 accepted steps and 5.05 days here; the summary prints a Keplerian period of 5.03 days for the pair. A fixed \(2\times 10^{32}\,\mathrm{kg}\) star at the same radius and 500000 m s\(^{-1}\) gives a period of about 5.11 days.

7 · Two knobs, two errors — Advanced

From Beats 5–7, which printed diagnostic follows dt, and which follows eps2? Halve each once and say what you would spend computer time on if you cared about periapsis, or about many orbits.

8 · When the controller wakes up — Advanced

Run --uInitA 1000 --uInitB -1000 at the defaults, then tighten --eps1. What does the default controller miss on that orbit?

Domain of Validity

  • Newtonian point masses in a plane. No finite size, tides, radiation, or relativity.
  • The Keplerian block classifies the starting data, not the integrated path.
  • Energy conservation is a diagnostic of the integrator. A small \(\Delta E\) does not bound the error in period or phase.
  • Very close encounters can hit the timestep floor. Head-on starts will.
  • The printed \(E\) includes centre-of-mass kinetic energy. Classify bound versus unbound in the centre-of-mass frame; the energy plot with --frame com shows that internal energy.
