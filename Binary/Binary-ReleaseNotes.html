Release Status

Version 1.2.2 follows 1.2.0 through two rounds of changes: a Beats-layout Help file with the three maintenance items of the previous notes and a check for missed issues (1.2.1), and a response to independent review by Codex and Grok (1.2.2). A further review by Codex and Grok (Audit22) changed nothing; it reproduced the 239-test suite and confirmed the fixes of the previous round. Grok recommended accepting 1.2.2 and closing the code and Help audit loop. Codex agreed that 1.2.2 is an appropriate PATCH version but recommended fixing OB-1 before the orbital-elements range repair is described as complete, and fixing the two Beat 5 wording items (M-1, M-2) before the student Help is finalized; none of the three is fixed in this release. OB-1 is not reached by the default run or by any command shown in the Help. These notes replace the 1.1.4 notes; the earlier notes are not reproduced.

Open Bugs

  • OB-1 (P3, Codex A22-P3-01). orbital_elements() reports a range failure, or raises ZeroDivisionError, for finite states whose elements are representable, so the command line can integrate successfully and then exit without a summary.
    Reproduction: python main.py --MA 7.49e106 --MB 7.49e106 --xInitA 5e149 --xInitB -5e149 --uInitA 5e99 --uInitB -5e99 --dt 1 --max_steps 1 --no-stop_after_one_orbit exits with status 1 and “Binary: Orbital elements are outside the numerical range.” (expected: the summary, with a hyperbolic orbit of eccentricity about 1.0002×10253).
    Also: the same state with --vInitA 5e99 --vInitB -5e99 (radial) gives the same error (expected: kind radial, eccentricity 1); orbital_elements(7.49e307, 7.49e307, 5e-11, 0, 0, 0.5, -5e-11, 0, 0, -0.5) raises ZeroDivisionError (expected: an elliptic orbit of semi-major axis 5×10−11 m, the reviewer's high-precision value).

Major Improvements in This Release

Version 1.2.1:

  • The Help file now uses the Beats layout: eight Beats (0–7), each with a command, something to read from the printed output or the plot, three tasks and the equations those observations lead to. Governing Equations is now an index, and there is a Printed Summary section with a real default-run excerpt.
  • The signed orbit angle behind the one-revolution stop and the reported number of revolutions is summed with compensation, so long runs no longer accumulate rounding in it.
  • --help no longer shows “(default: True)” beside --no-stop_after_one_orbit.
  • A radial start now prints “Radial trajectory (zero angular momentum): apsides and period are undefined.”; this is the only line of program output that changed for any command tried.

Version 1.2.2:

  • orbital_elements() and the mass fractions in the printed summary no longer fail for some finite inputs near the top of the floating-point range: the sum of two masses near 10308, and a circular period whose cube of the semi-major axis overflows (for example two masses of 5×10199 kg at 10110 m). OB-1 records what still fails. Nothing printed for an input that worked before changed; the 31 commands compared with 1.2.1 differ only in the version and build line.
  • Help: the Printed Summary no longer says an unbound or radial orbit always ends at max_steps (an inward radial start stops early with the close-approach error); Beat 4 states angular momentum and the hodograph test in the centre-of-mass frame; Beat 5 says the two-body problem has an exact conic solution and that Binary integrates it step by step on purpose; energy departure is called one diagnostic, not a measure of total error; the 0.015% and 0.013% figures are explained (unrounded and rounded digits).
  • Help: Experiment 8 is a keyword-argument script with six printed values to check; the five wide tables scroll inside labelled regions on narrow screens.

Test Suite Growth

95 → 217 → 239 automated tests (1.2.0 → 1.2.1 → 1.2.2). The suite is run once from tests/ with RuntimeWarning promoted to an error, with the Help, Release Notes and Sample Outputs Guide in the repository layout beside the modules; all 239 pass under CPython 3.11 in about 30 s, and also under Python 3.10.20 with Matplotlib 3.5.0 and NumPy 1.26.4. Both Audit22 reviewers reproduced 239 tests passing. No uploaded test was removed or loosened. The one expectedFailure that held the release-metadata test while these two documents were out of date has been removed; that test now passes.

New coverage: the compensated angle sum; corrector and step-control edge cases; unequal-mass energies; orbital elements against independent Decimal and Fraction oracles, including the overflow cases of 1.2.2; how each kind of run ends (head-on, outward radial, unbound); and the Help (layout recogniser, every command shown is run, quoted numbers are tied to live runs and to the sentence that uses them, Experiment 8 is executed). 194 hand-made mutants of the program and Help were used to check the tests; 187 are detected, and the seven that are not are the no-change control and six judged equivalent or unreachable.

Known Limitations

  • Educational model of two Newtonian point masses acting only through mutual gravity, not an ephemeris or research orbital-dynamics code. No relativity, gravitational radiation, tides, rotation, finite size, collisions, mass transfer, external fields or third bodies.
  • Point-mass gravity is singular at zero separation: an unresolvable close approach, such as an inward radial start, ends in a numerical-safety error instead of an impact or a softened passage.
  • The Euler-predictor and iterated-trapezoidal-corrector method accumulates error; results should be repeated with smaller dt and stricter tolerances. An orbit far more eccentric than the default is inaccurate at the default eps1 (Experiment 8: a largest sampled energy departure of 25.9%).
  • The one-revolution stop follows the accumulated signed angle of the relative position; it can pass 2π by part of a step and does not prove the trajectory is closed. Radial and unbound runs normally continue to max_steps unless an error stops them earlier.
  • Invariance under a common velocity boost is approximate because the corrector test is applied to each body separately.
  • The printed energy table has eleven interpolated rows; the largest departure can fall between them. (E−E0)/|E0| is undefined or large when E0 is near zero.
  • Finite inputs whose derived displacement, acceleration or energy is outside the double-precision range are rejected rather than approximated.
  • There is no option to save the plot to a file.
  • The Help file loads MathJax from a public CDN; offline, equations appear as untypeset LaTeX.

Known Minor Maintenance Items

  • M-1 (Codex A22-P4-02). Beat 5 says “each body moves on a conic section” without saying “about the centre of mass”; in a boosted frame the plotted path of each body is a drifting conic.
  • M-2 (Codex A22-P4-03). Beat 5 still contains “Row 0.5 is the row at closest approach” two sentences after saying the row falls “at or near” closest approach.
  • M-3 (Codex A22-P4-04, Grok N2). The “60 retries” error in driver_binary.py cannot be reached (the step floor stops the run on the 40th halving); its test reaches it only by replacing _halve_timestep() with a mock.
  • M-4 (Codex A21-P3-06, Grok N1). The summary does not print the largest sampled energy departure or its time; Experiment 8 supplies a script instead.
  • M-5. --help prints floating-point defaults such as 46000000000.0. In physics_binary.py the min(e, 1) cap in the bound branch never acts, and plot_binary.py lists a singular “orbit” output type that the command line never sends.
  • M-6. Help wording tests pin exact phrases, so rewording a pinned sentence means editing its test.
  • M-7. Repository-wide continuous integration and dependency-lock policy remain outside this module; the extreme-value tests should stay focused rather than gain a test for every equivalent permutation.
