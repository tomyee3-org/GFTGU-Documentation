Orbit 1.4.0 Release Notes

Version: 1.4.0
Build: c9fb119d6144
Date: 2026-09-16

Release Status

Version 1.4.0 adds a complete command-line interface and expands the numerical summary with planar Keplerian orbital elements. The Newtonian inverse-square model, adaptive predictor-corrector algorithm, trajectory arrays, and five plot modes retain their previous behavior.

Command-Line Interface

  • Added command-line options for all ten driver inputs: --xInit, --yInit, --vxInit, --vyInit, --k, --dt0, --maxSteps, --eps1, --eps2, and --maxOrbits.
  • Added --output for the five display alternatives: orbit, velocity, position_time, velocity_time, and energy.
  • Documented every option in the main.py module description and in python main.py --help. Omitted options retain the established Mercury-like defaults.
  • Invalid physical or numerical settings now terminate with a concise Orbit: ... message.

Keplerian Elements

The program derives osculating elements from the initial Cartesian state and the selected central gravitational parameter. The summary reports:

  • conic classification: elliptic, parabolic, or hyperbolic;
  • eccentricity;
  • semimajor axis, using the standard negative value for a hyperbola;
  • semilatus rectum and periapsis radius;
  • apoapsis radius and Keplerian period for an ellipse;
  • periapsis longitude and initial true anomaly in the x-y plane when the orbit is not circular.

Inclination and longitude of the ascending node are not included because Orbit is a two-dimensional program. Periapsis direction and true anomaly are marked as undefined for a circular orbit. A parabola has no finite semimajor axis, apoapsis, or period; a hyperbola has no apoapsis or period.

Summary Output

  • All real-valued summary results are formatted to five significant digits. Exact integer counters remain integers.
  • The summary continues to report termination, accepted steps, elapsed simulated time, azimuthal revolutions, angular-step rejections, endpoint refinement trials, fractional and absolute energy drift, fractional and absolute angular-momentum drift, and closure residuals.
  • Closure radius and velocity fields are now printed as n/a when the endpoint is not an integral-revolution closure point, keeping the summary layout complete across run types.
  • A hyperbolic trajectory ending at maxSteps or a deliberately small maxOrbits target reports its final radius and final speed.

Documentation Updates

  • Reworked the Help Parameters section around the command-line option names and added complete runnable examples.
  • Converted parameter-only Suggested Experiments to command-line commands. Exercises that require array analysis or changes to the numerical method remain programming exercises.
  • Expanded the Help output discussion to explain planar elements, undefined quantities, significant-digit formatting, and hyperbolic final-state output.
  • Updated the Sample Outputs Guide with Version 1.4.0 commands and numerical summaries. Existing embedded plots remain applicable because the integrator and plot routines are unchanged.

Regression Coverage

All 75 automated tests pass from the canonical tests/ directory. The suite retains coverage of the force law, adaptive integration, endpoint refinement, singularity protection, conservation diagnostics, plotting, Build-ID calculation, and Python 3.10 syntax. New coverage checks all command-line defaults and forwarding, selector help, five-significant-digit formatting, elliptic/circular/parabolic/hyperbolic elements, hyperbolic final radius and speed, and synchronization of all documentation artifacts.

Known Limitations

  • Orbit models a test particle around a fixed point mass. It is not a general two-body or N-body simulation.
  • The force law is Newtonian. Relativistic effects, finite body sizes, atmospheric drag, radiation pressure, tides, and third-body perturbations are not included.
  • The reported elements are osculating elements calculated from the initial state. Numerical drift diagnostics and closure residuals describe the actual integrated trajectory.
  • Five-significant-digit display does not imply that every run is physically or numerically accurate to five significant digits. Students should use the reported conservation and closure diagnostics and repeat runs with tighter controls.
  • The singularity guard is numerical rather than a physical stellar or planetary surface.

Orbit 1.3.1 Release Notes

Version: 1.3.1
Build: 93380f960f8e
Date: 2026-08-30

Release Status

Version 1.3.1 concludes a kickoff maintenance review followed by four rounds of independent review involving Codex, Copilot, and Gemini. The reviewers examined the Python implementation against Schutz's original Java/Triana Orbit program; verified the Newtonian inverse-square force law, predictor-corrector integration, adaptive timestep control, revolution counting, conservation diagnostics, singularity handling, plotting, Help-file accuracy, Version/Build synchronization, and regression coverage; and tested both the canonical and flattened upload layouts. No release-blocking defect remains.

During the review process, issues involving scale-invariant singularity handling, endpoint event refinement, angular-step aliasing, numerical overflow protection, diagnostic consistency, Help synchronization, and test coverage were identified and corrected. The final Audit4 reviews from both Copilot and Gemini recommend release. The resulting program is robust, scientifically consistent, and appropriate for student use within the scope and limitations described below.

Major Improvements in This Release

  • Reworked singularity handling so that coarse predictor or corrector steps intersecting the numerical guard are retried with a reduced timestep rather than being incorrectly classified as physical singularity events. Accepted-state approach to the guard is now distinguished from trial-step geometry.
  • Replaced the former fixed 1 μm singularity floor with a scale-relative and floating-point-relative guard based on the initial orbital scale and machine precision. This preserves numerical protection while allowing microscopic educational models that were previously excluded.
  • Added an independent angular-step safeguard that limits accepted angular motion before endpoint-angle unwrapping occurs. The safeguard is documented as a conservative numerical protection mechanism rather than a mathematical proof.
  • Replaced endpoint state interpolation with bracketed predictor-corrector event refinement. Final-orbit termination now repeatedly re-integrates from the last accepted state until the requested revolution target is reached within tolerance, avoiding the loss of integrator accuracy associated with state interpolation.
  • Corrected a consistency issue between reported revolution counts and returned trajectory states. Position, velocity, time, and revolution-count diagnostics now correspond to the same integrated endpoint.
  • Added overflow-safe geometry calculations for minimum-segment-radius testing and expanded validation of derived radii, speeds, accelerations, energies, and angular momenta. Finite inputs that produce non-representable derived quantities now fail with explicit diagnostic messages.
  • Improved conservation diagnostics by distinguishing between absolute and fractional drift measures. Fractional energy drift is no longer reported for parabolic-orbit cases where the reference energy is effectively zero, and fractional angular-momentum drift is omitted when the reference angular momentum is effectively zero. Absolute diagnostics remain available in all cases.
  • Added explicit numerical-effort diagnostics for angular-step rejections and endpoint refinement trials. These counters help students understand adaptive-control behavior during numerical experiments and tolerance studies.
  • Restored textbook references to Investigations 4.1 and 4.2, Tables 4.2 and 4.3, and Chapter 6 while preserving compatibility with future documentation updates.
  • Expanded and clarified the Help exercises, including guidance for direct access to returned arrays in EXP-11 and improved treatment of floating-point issues near the escape-velocity threshold in EXP-5.
  • Added a reproducible BUILD_ID across the four executable source modules, with newline-independent hashing, independent verification tests, synchronization across runtime output and Help documentation, and explicit documentation of Build-ID scope.

Test Suite Growth

A 41-test regression suite was created during the kickoff review and expanded through the audit process to 60 automated tests. The suite defines the four executable-core module filenames and uses find_module_dir(start) so that the same test file operates correctly from either the canonical tests/ directory or a flattened upload layout beside the program modules.

The final suite verifies Newtonian acceleration, specific energy and specific angular momentum formulas; rotational invariance and sign conventions; singularity handling and radial infall; microscopic and large-scale models; adaptive timestep behavior and tolerance controls; event refinement and revolution-count consistency; angular safeguards; overflow protection; Build-ID rules; command-line execution; plotting; documentation synchronization; Python 3.10 compatibility; and both supported layouts. All 60 tests pass in both layouts.

Known Limitations

  • Orbit models a test particle moving in the gravitational field of a fixed central mass. The central body does not move, and the program is not a general two-body or N-body solver.
  • The program implements Newtonian gravity only. Relativistic effects, tidal effects, finite body sizes, atmospheric drag, radiation pressure, and non-gravitational perturbations are not included.
  • The angular-step safeguard is a conservative numerical estimate designed to prevent endpoint-angle ambiguity. It is not a rigorous mathematical proof that every accepted trajectory segment remains below a specified angular bound.
  • Closure diagnostics are reported only when the requested termination target corresponds to an integral number of revolutions. Fractional-orbit runs intentionally omit closure residuals.
  • The singularity guard is a numerical protection mechanism rather than a physical stellar or planetary radius. Its value depends on the initial problem scale and floating-point resolution.
  • The Help file loads MathJax from a public CDN. Offline, explanatory text and TeX source remain available, but equations are not typeset.

Known Minor Maintenance Items

  • Several retry limits and iteration limits remain implemented as local constants within the driver rather than centralized module constants. This does not affect correctness but may become a future maintainability improvement.
  • Termination reasons continue to use documented string identifiers rather than enumerated types. The current approach is functional and well tested, but stronger typing could be considered in future maintenance work.
  • Documentation-synchronization tests intentionally verify specific Help-file wording. This provides strong protection against drift but may require updates when wording is revised without changing behavior.
