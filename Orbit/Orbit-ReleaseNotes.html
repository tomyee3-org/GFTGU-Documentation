Release Status

Response to Claude’s Audit41 style addendum, 29 September 2026: Added repository URLs, aligned the Grok badge with the Claude page, enabled sidebar section highlighting, and expanded International Astronomical Union (IAU). Kickoff4 continues the unreleased 1.7.0 audit sequence. The code-changing round is the present 1.7.1 documentation/CLI wording correction; the preceding code-changing round was the 1.7.0 Audit 22 response. Codex's Kickoff4 internal audit is complete and Claude's Audit41 verdict is APPROVE. The Audit41 P3 mixed-line-ending issue in main.py has been corrected by normalizing the file to LF. The numerical solver and figures are unchanged in behavior; the core's version metadata and public --maxOrbits description were the only semantic source changes in Kickoff4. Both active tutorials share the 1.7.1 code and build.

Open Bugs

  • OB-2 (P3; Grok Audit 21 item P3). The detailed Extended-style tutorial quotes results before the student performs some runs; the presentation was retained pending an editorial decision between tutorial styles.
    Reproduction: read Orbit-extended.html Beat 0. Observed: it gives 761 accepted steps and 7.6025e+06 s before the reader has run the command. Expected (reviewer): let the student first discover these values from the run.

Former OB-1 (P3, Codex/Grok Audit 23) is closed: --help, the main.py module description and both active tutorials state the 1e-9 minimum for --maxOrbits. Orbit-original.html is preserved as an archived 1.7.0 Reference Guide and is not an active tutorial.

Audit41's P3 source-formatting issue is closed: main.py now uses LF throughout. It did not affect runtime behavior or the newline-normalized Build ID. OB-2 remains an editorial choice pending manual review of the two tutorial styles.

Major Improvements in This Release

  • Added a styled Short-style terminal tutorial with nine Beats, fifteen embedded activities, a concise parameter table and runnable commands. It works with the same core Python files and Sample Outputs Guide as the Extended-style tutorial.
  • Corrected the public --maxOrbits description and the active Claude guide's input note to the existing minimum of 1e-9 revolutions. Input acceptance and numerical results have not changed.
  • Added a graph-coordinate cursor note near the beginning of each active tutorial.
  • Regenerated all nine Sample Outputs figures using the exact commands shown, checked their headline values, and updated the guide's version, date and image provenance.
  • The test suite now requires both active tutorials in one directory, checks the Grok guide's structure, version, flags and executable commands, and verifies the stated input minimum.

Audit41 response: normalized the mixed CRLF/LF line endings in main.py to LF without altering the normalized source text or Build ID.

Test Suite Growth

  • 1.4.0: 75 tests, 1.5.0: 128, 1.6.0: 144, 1.7.0: 156, 1.7.1: 160 tests.
  • From GFTGU-Programs/Orbit, run MPLBACKEND=Agg python3 -m unittest discover -s tests -q. All 160 tests pass with both active guides present in the sibling repository layout. The package includes both guides; the suite also supports a flattened review layout.
  • The numerical tests retain the previous independent initial-state, event and conservation checks; the four new tests cover the paired tutorials and the input description. The archived Reference Guide is retained for historical reference without current-build synchronization.

Known Limitations

  • Planar Newtonian motion about a fixed point mass; the model has no relativity, drag, tides, central-body finite size or moving primary.
  • The Mercury-like initial state is a teaching case, not an ephemeris. Closure residuals have a meaning only after whole-number revolutions.
  • The equations in the active guides use MathJax from a public CDN for typesetting. The Python program itself works offline.

Known Minor Maintenance Items

  • Four groups of numerical literals in run_orbit() could be named constants. No direct option saves a figure to a file.
  • The physics functions still name the gravitational parameter mu in some error messages. A runtime assertion that the final azimuth matches the target remains optional; tests cover the supported range.
  • The editorial choice between the two active tutorial formats remains pending. The archived Reference Guide retains its historical 1.7.0 stamp and wording.

Major Improvements in This Release

Version 1.7.0 (Audit 22 response):

  • The summary prints final specific energy, the specific energy of the last accepted state.
  • --maxOrbits below 1e-9 is now rejected with an error. Previously a tiny target such as 1e-13 overshot by a factor of 2 and 1e-16 by a factor of 204, and still printed closure residuals.
  • Small --maxOrbits targets are now met to a small fraction of the request. This changes the printed azimuthal revolutions and end state for targets below about 0.16; runs with larger targets, including the default, print the same numbers as before.
  • Closure residuals are printed only when --maxOrbits is a whole number of at least 1.
  • With no accepted step, the shortest and longest accepted step lines both read n/a (no step accepted).
  • The initial-velocity marker on the hodograph is larger and red, with a black edge.

Version 1.6.0 (Audit 21 response):

  • The summary prints acceleration evaluations, shortest accepted step and longest accepted step.
  • The Keplerian block prints specific energy of the starting state.
  • The hodograph plot marks the origin (zero velocity) and the initial velocity.
  • New Beats tutorial Help, Orbit-extended.html, with nine beats and 15 experiments; the Reference Guide Help is retained as Orbit-original.html.

Also new in the unreleased 1.5.0 step:

  • Five-significant-digit output no longer prints six digits at a rounding boundary (for example 0.99999996 now prints as 1.0000, not 1.00000).
  • An invalid --k is reported as k, not mu.
  • The nine numerical limits and factors of the integrator are named constants in driver_orbit.py, and the termination reason is a TerminationReason value with unchanged text.

Test Suite Growth

  • 1.4.0: 75 tests. 1.5.0: 128. 1.6.0: 144. 1.7.0: 156 (149 in the Audit 22 response, plus seven checks of these two documents).
  • Run from the program folder with python -m unittest discover -s tests. In the full repository layout all 156 tests run and pass with no skips. In a flat folder that lacks the documentation files, the tests that read the Release Notes, the Sample Outputs Guide and Orbit-original.html are skipped (13 skips), and the rest pass.
  • New coverage since 1.4.0 includes every command shown in the Help, the numbers the Help quotes, the named constants, small --maxOrbits targets, and the version and build in both companion documents.

Known Limitations

  • Planar Newtonian motion of a test particle about a fixed point mass; no relativity, drag, tides or second body.
  • The Mercury-like defaults are a teaching state, not an ephemeris.
  • Closure residuals are defined only for a whole number of revolutions.
  • The angular-step safeguard is a conservative estimate, not a proof.
  • The equations in the Help are typeset by MathJax and need an internet connection.

Known Minor Maintenance Items

  • Four groups of numerical literals in run_orbit() are not yet named constants.
  • There is no option to save a figure to a file.
  • The physics functions still name the gravitational parameter mu in their error messages.
  • There is no runtime check that the final azimuth matches --maxOrbits; tests cover the accepted range.
  • Orbit-original.html and Orbit-extended.html are both present, and neither is marked as the current Help.
  • Grok Audit 21 items P4 to P6: the spine sentence has three claims, Beat 0 answers its own question, and the Printed Summary reproduces the whole default console.
