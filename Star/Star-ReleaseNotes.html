Known Limitations

  • The physics is one Newtonian polytrope, without stellar energy transport, changing composition, rotation, magnetic fields or general relativity; the default radius and mass resembling the Sun do not make its interior a solar model.
  • Euler integration is first order; a restart doubles the radial step and is not error control. The surface is found by linear interpolation; its zero temperature belongs to this model only.
  • At the gamma = 6/5 boundary there is no finite surface. The stepwise radius becomes unreliable near it, and the Lane–Emden solution is not computed within about 1e-12 of 6/5.
  • The Lane–Emden step-halving uncertainty is an estimate, not a bound. The 1e-10 accuracy check for 0 ≤ n ≤ 4.99 used independent double-precision solutions that are themselves uncertain at about 1e-11. The program warns near the finite-radius boundary.
  • The default μ = 1.285 is an effective parameter rather than the actual composition of the Sun's core. The red-giant and neutron-star experiments are schematic.
  • MathJax in the tutorials needs network access to typeset equations.

Known Minor Maintenance Items

  • The archived Reference Guide documents an older signature and is deliberately not synchronized with active code or the current Build ID.
  • relative_step below 1e-4 is rejected, limiting repeated halving from the default; the build identifier reads unknown if a core file is unreadable.
  • The program has no command-line option to save a plot or printed summary. The choice between tutorial formats remains open pending educator review.

Major Improvements in This Release

Version 1.2.0, build 7d6e2d9d542c (Audit 22 response):

  • lane_emden_surface() accepts relative_step only from 1e-4 to 0.1, and stops with a ValueError if a step cannot advance ξ or the surface is not reached in 1,000,000 steps. In build 8ffe1c52fd03, lane_emden_surface(1.0, 1e-20) never returned.
  • For n < 2 (γ > 1.5) the Lane–Emden integration takes steps in proportion to θ near the surface. At n = 0.113424, ωn was 1.05e-8 from an independent solution and is now about 4e-13 from it. No printed number of any documented command changed, and the values for n ≥ 2 are identical.
  • Both Help files state that the Lane–Emden values were checked against an independent solution to better than 1e-10 for 0 ≤ n ≤ 4.99, that the half-step difference is an estimate and not a bound, and that the warning appears only within about 1.5e-7 of γ = 6/5.

Version 1.2.0, build 8ffe1c52fd03 (Audit 21 response):

  • The Lane–Emden block is headed (numerical reference) instead of (exact). The solution is computed with the normal step and with half of it; the half-step values are printed, and their difference is returned as relative_uncertainty.
  • A line Warning: gamma is so close to 6/5 that these Lane-Emden values are uncertain by about ... follows the Lane–Emden mass when that difference exceeds 1e-7; --gamma 1.200000004 prints it with 4e-06.
  • The index n is printed with up to 12 figures when five would round it to 5. --gamma 1.2000000001 now prints 4.9999999975 instead of 5, and a Lane–Emden radius of 1.0269e+18 m instead of 1.0267e+18 m.
  • Beat 8 of the Beats Help runs --gamma 1.2000000001 and shows the warning line.

Version 1.2.0, build 328c84d14b72 (Kickoff2, the base of 1.2.0; not released separately):

  • New Beats tutorial Help, Star-claude.html, with nine beats, 18 equations and 11 experiments. The Reference Guide Help is kept current as Star-original.html, renamed from Star.html.
  • Every run prints two new blocks after the unchanged radius and mass lines: Numerical grid (radial step, grid points, restarts) and the Lane–Emden radius and mass of the same polytrope with the relative differences of the integrated values. Every line that 1.1.0 printed is unchanged.
  • New public functions polytropic_index(), lane_emden_surface() and lane_emden_solution(); StarResult gains a field gamma.
  • --max_points is limited to 3 to 1,000,000; in 1.1.0, --max_points 100000000 tried to allocate about 4 GB.
  • Extreme accepted inputs end with a message instead of a ZeroDivisionError traceback or a raw (34, 'Numerical result out of range').
  • The Help files no longer give chapter or investigation numbers or link to other programs' Help files.

Known Limitations

  • A teaching model: one Newtonian polytrope, with no energy generation or transport, composition gradients, rotation, magnetic fields or relativity.
  • The default inputs give about the Sun's radius and mass, but not its interior; μ = 1.285 is an effective value.
  • Forward Euler steps are first order; a restart doubles the step and is not error control.
  • The surface is found by linear interpolation, and the temperature there is zero in the model only.
  • Near γ = 6/5 the integrated radius is an artefact; the Lane–Emden solution is not computed within about 1e-12 of 6/5.
  • The Lane–Emden uncertainty is a step-halving estimate; within about 1.5e-7 of 6/5 the printed Lane–Emden values can be wrong in their fourth or fifth figure, and the program warns.
  • The 1e-10 accuracy for 0 ≤ n ≤ 4.99 was checked against double-precision solutions that are themselves uncertain at about 1e-11.
  • The red-giant and neutron-star experiments are schematic.
  • The Java comparison uses a transcription of the Java source, not output from a Java run.
  • The equations in the Help are typeset by MathJax and need an internet connection.

Known Minor Maintenance Items

  • The Reference Guide lists lane_emden_surface(n) without its optional relative_step (Codex, Audit 23).
  • relative_step below 1e-4 is rejected, so the default Lane–Emden step can be halved only three times.
  • The build identifier reads unknown when a core file cannot be read.
  • There is no command-line option to save the figure or the printed summary to a file.
  • Star-claude.html and Star-original.html are both present, and neither is marked as the current Help.
