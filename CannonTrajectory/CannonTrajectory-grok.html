Description

CannonTrajectory is the first numerical-integration program in the suite (Investigation 1.3). A projectile leaves the ground under constant gravity, with no air. Two integrators share one command line: forward Euler and improved Euler (Heun).

The spine of the lesson is one sentence:

Gravity pulls only downward, so the sideways and vertical motions do not talk to each other and the path is an exact parabola; that exactness is the grade for a step-by-step calculation.

What this program is not. No air resistance, wind, spin, curvature or rotation of the Earth, and no change of \(g\) with height. Launch is always from ground level. The printed range, height and flight time are estimates from samples one timestep apart, not the last stored point.
Reading this page. Equations are rendered by MathJax from a public CDN. Without a network connection the raw \(\LaTeX\) remains visible as text. The program itself needs no internet access.

Before the first run

Unpack the program zip so you have a folder named CannonTrajectory that contains main.py. Open a terminal in that folder. You need Python 3.10 or newer with NumPy and Matplotlib. If you do not already have that environment, follow the project-wide GFTGU Python Setup Guide. Then:

python main.py --version
python main.py

The conventional standard gravity \(g=9.80665\,\mathrm{m\,s^{-2}}\) is built in. In the equations, \(v\) is the vertical velocity during flight; the launch speed given to --speed is \(v_0\).

Beat 0 · One launch, two motions

A ball leaves the ground at 100 m s\(^{-1}\), 45° above the horizontal. Nothing acts on it but a constant downward acceleration.

python main.py

Read the four printed lines — sample count, range, maximum height, flight time — and look at the arch. Both axes use the same scale. The last plotted point sits a little below the ground: the program stops at the first sample that has crossed, then estimates the crossing (Beat 5). Before reading on, write down what you expect doubling the launch speed to do to range, height and time.

Horizontal and vertical kinematics — the ODE
\[ \frac{dx}{dt}=u,\quad \frac{du}{dt}=0, \qquad \frac{dh}{dt}=v,\quad \frac{dv}{dt}=-g. \]

Nothing in the first pair mentions \(h\) or \(v\); nothing in the second pair mentions \(x\) or \(u\). That independence is the whole physical content of the model.

Beat 1 · The angle splits the speed

All a launch angle does is share \(v_0\) between the two motions. Try four angles at the same speed.

python main.py --angle_deg 30
python main.py --angle_deg 60
python main.py --angle_deg 0
python main.py --angle_deg 90

Keep Beat 0 beside you. 30° and 60° should land in the same place and climb to very different heights. 0° is already below the ground after one step. 90° comes back down on top of the muzzle; the printed range is a floating-point crumb of \(\cos 90^\circ\), not physics. 45° is the longest of these five. Experiment 1 asks whether any other angle does better.

Launch conditions
\[ x_0=0,\quad h_0=0,\quad u_0=v_0\cos\theta,\quad v_{0y}=v_0\sin\theta. \]

Beat 2 · The exact solution

Constant sideways speed and a vertical speed that changes at a steady rate can be integrated on paper. Predict what doubling \(v_0\) does, then run it.

python main.py --speed 200
python main.py --speed 50

Range and height should scale as \(v_0^2\); flight time as \(v_0\). The default 100 m s\(^{-1}\) at 45° has exact values \(T=2v_{0y}/g=14.4210\,\mathrm{s}\), \(H=v_{0y}^2/(2g)=254.929\,\mathrm{m}\), \(R=v_0^2/g=1019.72\,\mathrm{m}\). The printed default run should match those to the figures shown. That is the grade for every later beat.

Analytic trajectory and the range formula — derived
\[ x(t)=u_0 t,\qquad h(t)=v_{0y}t-\tfrac12 g t^2, \] \[ T=\frac{2v_{0y}}{g},\qquad H=\frac{v_{0y}^2}{2g},\qquad R=\frac{v_0^2\sin 2\theta}{g}. \]

\(\sin 2\theta\) is largest at 45°, and \(\sin 2\theta=\sin(180^\circ-2\theta)\), which is why 30° and 60° share a range. Mass and shape never enter. A real projectile is slowed by the air; this program has none.

Beat 3 · Stepping forward: Euler’s method

The program does not use Beat 2. It advances the state by \(\Delta t\), using the rates at the start of the step. That is forward Euler. Run it coarse.

python main.py --method euler --dt 0.5

Compare with Beat 0. Euler’s ball goes too high, stays up too long and lands too far away. Repeat at --dt 0.2, 0.1, 0.05. Halving the step should roughly halve the range error. Divide each range error by its \(\Delta t\): the quotient sits next to the sideways speed \(u_0\).

Forward Euler — algorithm
\[ \mathbf s_{n+1}=\mathbf s_n+\Delta t\,\mathbf f(\mathbf s_n). \]

For this problem the stored Euler heights lie exactly on a parabola — the exact trajectory of a ball launched with an extra upward speed \(\tfrac12 g\Delta t\). So \(T_E=T+\Delta t\) and \(R_E=R+u_0\Delta t\), before interpolation. That is what “first-order” means here. Fire along the ground with --method euler --angle_deg 0 and Euler still prints a small range: the phantom upward speed keeps the ball up for one step.

Beat 4 · A better step: improved Euler

Euler uses the vertical velocity from the start of the step for the whole step. Improved Euler (Heun) takes a trial step, then advances with the average of the rates at the two ends. Compare the two methods at a coarse \(\Delta t=1\,\mathrm{s}\).

python main.py --dt 1
python main.py --method euler --dt 1

Improved Euler is the default, so the first command needs no --method. The printed height should already be the exact 254.93 m, even though the highest stored sample is a little low — the peak falls between samples (Beat 5). The printed range is short by about a metre. Euler at the same step is tens of metres long.

Heun predictor and corrector — algorithm
\[ \mathbf s^*=\mathbf s_n+\Delta t\,\mathbf f(\mathbf s_n), \qquad \mathbf s_{n+1}=\mathbf s_n+\frac{\Delta t}{2}\bigl[\mathbf f(\mathbf s_n)+\mathbf f(\mathbf s^*)\bigr]. \]

For constant acceleration the height update is exactly \(h_{n+1}=h_n+v_n\Delta t-\tfrac12 g\Delta t^2\). Every stored Heun sample lies on the exact parabola, whatever \(\Delta t\) is. That exactness is special to constant \(g\). For a force that changes along the path, Heun is second-order, not exact.

Beat 5 · Between the samples

The ball lands, and reaches its peak, between two stored points. The printed numbers are interpolations. Look at what the program has to work with when \(\Delta t=1\,\mathrm{s}\).

python main.py --dt 1
python -c "from driver_cannon import run_cannon_trajectory as run; xs, hs = run(dt=1.0); print(xs[-2:], hs[-2:])"

The last stored point is below the ground and past the true range. A straight line between the last two samples crosses \(h=0\) at the printed range and the printed flight time. A parabola through the three samples around the peak is, for Heun, the exact parabola, so the printed height is exact.

Landing by a straight line; peak by a three-point parabola — algorithm
\[ x^*=x_{n-1}+(x_n-x_{n-1})\,\frac{h_{n-1}}{h_{n-1}-h_n}, \qquad T^*=t_{n-1}+\frac{h_{n-1}}{h_{n-1}-h_n}\,\Delta t. \]

A chord of a downward arch lies below the arch, so the printed Heun range and time are a little short unless the landing falls on a sample. That is why 30° and 60° can print ranges that differ in the fifth figure although they share an exact range. The leftover Heun error is interpolation, not the integrator.

Beat 6 · How far to trust a printed number

You will not usually have Beat 2 in your pocket. The practical check is the same one the exact solution makes possible here: change only \(\Delta t\), at least three times, and watch the figures you care about.

python main.py --method euler --dt 0.5
python main.py --method euler --dt 0.1
python main.py --dt 0.5
python main.py --dt 0.1

Euler’s range error tracks \(+u_0\Delta t\); its time error tracks \(+\Delta t\). Heun’s printed height does not move. Heun’s printed range is short by an amount that shrinks faster than \(\Delta t\), and not always by the same factor, because the landing sits a different fraction of the way between samples at each step. If the figures settle into the trend the method predicts, the numerical answer is converging. If they wander, something other than the step is at work. Convergence is not a proof that the model is right. That is Beat 7.

Beat 7 · Where the model and the run stop

The program reports a failed run itself. The model’s limits it cannot report, because it has no setting for them.

python main.py --max_steps 145
python main.py --max_steps 146
python main.py --speed 1000

The first command prints no summary: 145 stored points is one short of a default landing, and the program refuses to hand back an incomplete trajectory. The second command runs. A 1000 m s\(^{-1}\) launch prints a range of about 102 km. Over that distance a flat Earth has already dropped by hundreds of metres and the direction of \(g\) has turned by about a degree. EarthOrbit and Orbit are the programs for that scale. An overflowing state stops with a clear error rather than printing infinity.

Air resistance shortens a real range even at ordinary speeds. Wind, spin, curvature, rotation, and the weakening of gravity with height are all absent. Omitting drag is what makes Beat 2 possible, and Beat 2 is what makes the numerical grades possible.

Parameters

--speed100Launch speed in m s\(^{-1}\). Must be positive.
--angle_deg45Launch angle above the horizontal, 0 through 90.
--dt0.1Fixed timestep in seconds. Must be positive.
--max_steps100000Stored-point ceiling, including launch. At least 2.
--methodimprovedeuler (first-order) or improved (Heun).

Output

Every finished run prints version and build, the number of stored samples, then range, maximum height and flight time, each to five significant figures. A plot window opens; close it to end the program. Range and time are linear interpolations of the ground crossing. Height is a three-point parabola around the highest sample, falling back to that sample if the peak cannot be placed.

Experiments

EXP-1 · First run

Best angle

From Beat 1, 45° beat 30° and 60°. Try 40° and 50°. Does any angle beat 45° in this model? What does the range formula say before you run?

EXP-2 · Beginner

Speed squared

Tabulate range, height and time at 50, 100 and 200 m s\(^{-1}\). Which two scale as \(v_0^2\), and which as \(v_0\)?

EXP-3 · Beginner

Euler’s extra kick

Run --method euler --angle_deg 0 --dt 0.1. Why is the printed range not zero? What extra vertical speed is \(\tfrac12 g\Delta t\)?

EXP-4 · Intermediate

Halve the step

For Euler at 45°, record the range error at \(\Delta t=0.5\), 0.2 and 0.1 s. Does each halving halve the error? What quotient should error\(/\Delta t\) approach?

EXP-5 · Intermediate

Who owns the leftover?

At \(\Delta t=1\,\mathrm{s}\), Heun’s printed height is exact and the printed range is short. Using Beat 5’s last two samples, reproduce the printed range by hand. Whose error is that?

EXP-6 · Intermediate

A ceiling that tells the truth

Find the smallest --max_steps that lets the default launch finish. What does the program do one count below that, and why is that better than a silent short range?

EXP-7 · Advanced

When Heun stops being exact

Heun is exact here because \(g\) is constant. In one sentence, say what would have to change in \(\mathbf f(\mathbf s)\) for the stored samples to leave the analytic parabola.

EXP-8 · Advanced

The model breaks first

At what launch speed does a 45° range become a few per cent of Earth’s radius? Which missing effect do you judge would spoil the number first — drag, or curvature?

Domain of Validity

  • Flat ground, constant vertical \(g\), vacuum, launch from \(h=0\).
  • Valid while the range is a tiny fraction of Earth’s radius (\(\approx 6.4\times 10^6\,\mathrm{m}\)). The default 100 m s\(^{-1}\) launch travels about a kilometre.
  • Euler’s stored path is a shifted parabola. Heun’s stored path is the exact parabola. Printed range and time always carry the interpolation of Beat 5.
  • An unfinished trajectory is refused. Overflow is refused.
