CannonTrajectory 1.3.0 Release Notes

Version: 1.3.0
Build: 8a19fe772044
Date: 2026-09-15

Release Status

Version 1.3.0 adds a complete student-facing command-line interface and improves the numerical summary printed after each run. All five inputs accepted by run_cannon_trajectory() can now be set without editing source code. The physical model, the Euler and improved-Euler update formulas, and the plotted trajectory are unchanged.

What Changed in 1.3.0

  • Added command-line options for every simulation input: --speed, --angle_deg, --dt, --max_steps, and --method.
  • Documented every input in main.py and in python main.py --help. The selector choices are described explicitly: euler uses first-order forward Euler, while improved uses second-order improved Euler (Heun's method).
  • Audited the defaults in driver_cannon.py. All five driver inputs are now represented in main.py; no defaulted simulation parameter is left inaccessible from the command line.
  • Added interpolated_maximum_height(), which fits a parabola to the largest stored height and its two neighbours and returns the vertex. A boundary maximum or non-concave local triple safely falls back to the largest stored height.
  • Added interpolated_flight_time(), which linearly interpolates the final ground crossing using the same two height samples used for the interpolated range.
  • The console now prints interpolated range, parabolically interpolated maximum height, and interpolated flight time to five significant figures.
  • Invalid command-line values are reported as concise CannonTrajectory: ... errors instead of Python tracebacks.
  • Updated the Help file exercises to use command-line examples wherever parameter changes are sufficient. Exercises requiring trajectory overlays or modified integration formulas continue to use Python.

Default Printed Values

For python main.py, whose defaults are --speed 100, --angle_deg 45, --dt 0.1, --max_steps 100000, and --method improved:

  • 146 stored trajectory samples
  • Range (interpolated ground crossing): 1019.7 m
  • Maximum height (parabolic interpolation): 254.93 m
  • Flight time (interpolated ground crossing): 14.421 s

Major Improvements Retained from Earlier Releases

  • Updated the gravitational constant from the textbook-rounded g = 9.8 m/s² to the conventional standard value g = 9.80665 m/s², with corresponding updates to all documented analytic results and examples.
  • Preserved Schutz's original constant-gravity, no-drag projectile model while adding a direct comparison between forward Euler and improved Euler (Heun) integration.
  • Added robust validation for invalid parameter types and values, including nonnumeric inputs, invalid launch angles, invalid timesteps, invalid methods, and insufficient max_steps values.
  • Added controlled handling for extreme finite Real inputs that cannot be represented as Python floating-point values, producing explanatory exceptions instead of uncaught conversion failures.
  • Added numerical overflow and invalid-state detection so trajectories containing non-finite values raise a descriptive FloatingPointError rather than returning corrupted results.
  • Replaced trajectory preallocation with append-only storage, ensuring that max_steps functions as a true safety ceiling rather than an implicit memory-allocation request.
  • Retained Schutz's pedagogically useful first-below-ground-point behavior, allowing students to investigate timestep effects and landing-point interpolation.
  • Version 1.2.0 introduced a printed linearly interpolated landing range and a validated interpolated_landing_range() helper. Version 1.3.0 retains both and extends the summary to height and flight time.
  • Added plot_cannon_overlay(), allowing multiple trajectories to be displayed on one figure for launch-angle comparison experiments while preserving the existing single-trajectory plotting interface.
  • Hardened plotting against malformed overlay input and ensured that partially constructed figures are cleaned up automatically if plotting fails.
  • Expanded and clarified the Help documentation, including improved discussion of integration error versus sampling error, trajectory overlays, interpolation of ground crossings, and exact-ground landing behavior.
  • Added reproducible BUILD_ID generation covering exactly the four executable core modules: physics_cannon.py, driver_cannon.py, main.py, and plot_cannon.py. The Build identifier is synchronized across runtime output, source code, documentation, and regression tests.

Test Suite Growth

The current suite contains 68 automated tests. Version 1.3.0 adds coverage for all five command-line parameters, both documented integration-method choices, the three five-significant-figure summary values, parabolic maximum-height interpolation, and interpolated flight time. The suite defines the four executable module filenames explicitly and uses find_module_dir(start) to locate the nearest directory containing the core modules, allowing the same tests to operate from either the canonical tests/ layout or a flattened upload layout. It also locates the Help file correctly when the build and documentation artifacts are adjacent.

The suite verifies physics constants and analytic solutions; Euler and improved-Euler integration behavior; numerical convergence; trajectory structure and landing behavior; interpolation accuracy; complementary launch angles; speed-squared range scaling; the rounded default range and maximum height; interpolated flight time; command-line parsing and help; parameter validation; overflow detection; large finite-Real edge cases; plotting behavior; overlay plotting; malformed input cleanup; Help-file structure and synchronization; Version/Build consistency; Python 3.10 grammar compatibility; flattened-layout execution; and independent BUILD_ID reproduction.

Known Limitations

  • The model assumes constant gravitational acceleration and neglects air resistance. It is intended for introductory numerical experiments rather than high-accuracy ballistic prediction.
  • The trajectory still terminates at the first sampled point below ground rather than inserting an exact landing sample into the returned arrays. The printed range and flight time interpolate that crossing; the raw final sample remains available for the landing-interpolation exercise.
  • Because height is quadratic in time, linear interpolation at the ground crossing is still approximate. Smaller timesteps reduce that event-location error. Five-significant-figure formatting makes convergence comparisons easier; it is not a claim of five-significant-figure ballistic accuracy.
  • The plotted curve still includes the first below-ground sample even though the printed range and flight time refer to the interpolated crossing.
  • The improved-Euler method reproduces the analytic sampled solution for this special constant-acceleration problem. Its exceptional accuracy here should not be interpreted as representative of all differential-equation systems.
  • The program models launches from ground level only. It does not currently include an adjustable initial height.
  • A normal command-line run displays one trajectory. Multi-trajectory overlays still require a short Python experiment using plot_cannon_overlay().
  • The Help file loads MathJax from a public CDN. When offline, documentation remains readable but mathematical expressions are displayed as raw TeX source rather than rendered equations.

Known Minor Maintenance Items

  • The BUILD_ID intentionally excludes documentation and regression tests. Documentation or test-only updates therefore do not alter the executable build identifier.
  • Help-file synchronization relies on structural regression tests that compare documented defaults, experiment metadata, and Version/Build identifiers against the executable program. Future documentation edits should preserve this synchronization.
  • The overlay plotting interface currently accepts trajectories using the documented (label, xs, hs) format. Future plotting extensions should maintain compatibility with existing experiments and tests.
