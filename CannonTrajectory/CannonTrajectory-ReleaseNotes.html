Release Status

This release reflects two code-changing rounds since the 1.3.0 notes. Kickoff2 (1.3.1, build 8f21955760d2) replaced the classic Help file with a Beats-format tutorial and extended validation of malformed overlay-plot input. Response-to-Audit21 (1.3.1, build 983dee8256ef) corrected two overstatements in Beats 5 and 6, extended the overlay-item and finite-result validation, improved Help accessibility, and hardened one test. A third round, Audit22, reviewed the Response-to-Audit21 package and requested no code change; it is mentioned here only because it is review-only. Codex's Audit22 verdict: "careful and substantially correct," with two P3 items still open (below) and two P4 items noted separately. Grok's Audit22 verdict: accept 1.3.1 / 983dee8256ef and close the code/Help audit loop on this package. Neither reviewer's recommendation is a hold.

Open Bugs

Every reviewer-reported defect of severity P1–P3 still open at release. No causes or fixes are given here; see the cited finding for detail.

  • OB-1 (P3, Codex Audit22 P3-01). The finite-result guard added in Response-to-Audit21 does not catch a plain Python float overflow, so two interpolation helpers can still produce a non-finite or an uncaught-exception result from finite inputs. Reproduction: interpolated_flight_time([0.0, 1.0, 0.0, -1.0], 1e308) — observed: returns inf; expected: FloatingPointError, as already raised for the other non-finite cases the guard covers. Also interpolated_maximum_height([-1e308, 1e308, 0.0]) — observed: raises an undocumented OverflowError; expected: a documented, caught exception.
  • OB-2 (P3, Codex Audit22 P3-02). Beat 6's refinement-check paragraph asks whether "the errors shrink" by the method's predicted factor, although the paragraph's own premise is that the exact answer is normally unknown, and it names "rounding error" as the one cause of a failure to settle. Reproduction: read CannonTrajectory.html, Beat 6, the paragraph following the two convergence tables — observed: asks the student to judge an unknowable quantity ("the errors") and offers one specific cause for non-convergence; expected: guidance based on successive differences between resolutions, with a failure to settle left undiagnosed as to cause.

Major Improvements in This Release

  • Replaced the classic Help file with a Beats-format tutorial (Beats 0 through 7), matching the format already used for GravitationalLensing and BlackHoleShadow.
  • plot_cannon_overlay()'s item validation was rewritten: every malformed item now raises one ValueError naming the expected (label, xs, hs) triple. Strings, bytes objects, mappings and sets are refused explicitly, so a three-character string, a bytes object, or a three-key dictionary or three-member set is never silently accepted as a triple.
  • interpolated_landing_range() and interpolated_flight_time() now wrap their arithmetic in a finite-result guard and raise FloatingPointError, naming which quantity is not finite, for the non-finite cases the guard catches (one remaining gap is Open Bug OB-1).
  • Beat 5 of the Help now states the exact landing-interpolation-error formula, alongside the earlier leading-order approximation, and marks the approximation and its bound as approximate rather than strict. Beat 6's refinement-check guidance no longer claims that a single check "always works," and states explicitly what the check does and does not show.
  • Accessibility: small gold-coloured text now meets WCAG AA contrast, a skip-to-content link was added, and a footer link no longer relies on colour alone to be distinguishable.
  • No printed or plotted numeric result of a valid run changed in either round; the only change to program output is the version/build banner line.

Test Suite Growth

The suite grew from 68 automated tests at 1.3.0 to 135 tests in Kickoff2 (1.3.1, build 8f21955760d2) and to 145 tests in Response-to-Audit21 (1.3.1, build 983dee8256ef). No test was removed, skipped, or weakened in either round. Kickoff2 added coverage for the Beats-format Help file (structure, cross-references, and ledgers of quoted numbers and words) and for the rewritten overlay-item validation. Response-to-Audit21 added ten tests: independent oracles for the two new Beat 5 equations, a numerical counterexample, wording guards on three revised passages, two accessibility checks, and a finite-result guard test.

The suite is run once from tests/, with RuntimeWarning promoted to an error: cd tests && MPLBACKEND=Agg python3 -W error::RuntimeWarning -m unittest test_physics_cannon. The Response-to-Audit21 package passed 145/145 on a clean extraction under Python 3.11.15, and again under Python 3.10.20 (the stated minimum), and 90/90 with 3 skipped under a classic, pre-Beats Help layout. Codex and Grok each independently ran the same command once against the same package and reported 145/145, OK.

Known Limitations

  • The model assumes constant gravitational acceleration and neglects air resistance. It is intended for introductory numerical experiments rather than high-accuracy ballistic prediction.
  • The trajectory still terminates at the first sampled point below ground rather than inserting an exact landing sample into the returned arrays. The printed range and flight time interpolate that crossing; the raw final sample remains available for the landing-interpolation exercise.
  • Because height is quadratic in time, linear interpolation at the ground crossing is still approximate. Smaller timesteps reduce that event-location error. Five-significant-figure formatting makes convergence comparisons easier; it is not a claim of five-significant-figure ballistic accuracy.
  • The displayed leading-order error formula for the interpolated range is an approximation, and its "at most about" figure can be exceeded slightly (by up to about 0.23% for flights of at least ten steps, and by more for shorter flights); the exact expression is given beside it.
  • The plotted curve still includes the first below-ground sample even though the printed range and flight time refer to the interpolated crossing.
  • The improved-Euler method reproduces the analytic sampled solution for this special constant-acceleration problem; its exceptional accuracy here should not be interpreted as representative of all differential-equation systems.
  • The program models launches from ground level only. It does not currently include an adjustable initial height.
  • A normal command-line run displays one trajectory. Multi-trajectory overlays still require a short Python experiment using plot_cannon_overlay().
  • The Help file loads MathJax from a public CDN. When offline, its prose and raw equation source remain available, but equations appear as untypeset LaTeX rather than rendered equations.

Known Minor Maintenance Items

  • (P4, Codex Audit22 P4-03) The exact-error equation label and the equations-index entry for it do not state that the formula is specific to the improved-Euler samples on the exact parabola; read alone, they could be misunderstood as covering forward Euler's error too.
  • (P4, Codex Audit22 P4-04) The suite's two generated prose ledgers (a per-number and a per-word context snapshot of the Help) overlap with the independent semantic tests added in Response-to-Audit21. Codex recommends eventually replacing them with smaller per-section digests once the Beats text stabilizes; Grok recommends keeping them as originally designed. The two recommendations disagree and neither has been acted on.
  • (P4, Grok Audit22 N1) Beat 5 now carries two unnumbered derived equations (the exact interpolation-error expression and its leading-order approximation), which is more equation-dense than before; both were required by the Audit21 finding that led to this release.
  • The BUILD_ID intentionally excludes documentation and regression tests. Documentation- or test-only updates therefore do not alter the executable build identifier.
  • Help-file synchronization relies on structural regression tests that compare documented defaults, experiment metadata, and Version/Build identifiers against the executable program. Future documentation edits should preserve this synchronization.
  • The overlay plotting interface accepts trajectories using the documented (label, xs, hs) triple form; strings, bytes objects, mappings and sets are now refused explicitly rather than silently misinterpreted. Future plotting extensions should maintain compatibility with existing experiments and tests.
