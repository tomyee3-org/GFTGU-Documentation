Overview

MercPert explores the planar circular restricted three-body problem. Two massive bodies move on prescribed circular orbits about their common centre of mass, while a negligible-mass test particle called “Mercury” moves under their combined Newtonian gravity.

The default primary is Sun-like. The default companion has a mass of \(0.1\,M_\odot\), about 100 Jupiter masses; despite the historical “Jupiter” label, an object this massive is above the roughly \(0.08\,M_\odot\) hydrogen-burning threshold and is therefore in the low-mass stellar regime. The exaggerated companion mass makes strong scattering and orbital instability easy to see.

One of the central questions explored by MercPert is how a massive companion can disturb or remove smaller bodies from nearby regions of a planetary system. By varying the starting orbit, students can investigate which regions remain stable, which lead to repeated close encounters or ejection, and how far from a binary system long-lived planetary orbits can exist. This test-particle model captures the gravitational part of the “cleaning out” process discussed in Chapter 13, while deliberately leaving out the gas physics of a protoplanetary disk.

What the model demonstrates: MercPert is useful for gravitational perturbations, close encounters, ejection, resonances, circumbinary motion, and stability boundaries. It does not model gas, disk hydrodynamics, migration, pressure, shocks, or planet formation.

Quick Start

Requirements

Python 3.10 or later with matplotlib:

pip install matplotlib

Running the Program

cd GFTGU-Programs/MercPert
python main.py

The default binary contains a \(1\,M_\odot\) Sun and a \(0.1\,M_\odot\) companion separated by \(0.7\,\mathrm{AU}\). Mercury's input initial state is specified relative to the Sun: it begins \(0.3\,\mathrm{AU}\) from the Sun with transverse relative speed \(59{,}220\,\mathrm{m\,s^{-1}}\). The program converts that state to barycentric inertial coordinates before integration.

By default, the calculation allows up to 10,000 accepted steps. This gives a clean baseline run; longer integrations are useful when searching for strong encounters. The calculation stops earlier if Mercury enters the nominal solar radius, or if a positive companion_collision_radius has been supplied and Mercury reaches that boundary. The final trajectory is plotted in the barycentric inertial frame.

Customising the Simulation

Normal experiments require editing only main.py:

  • BinarySystemParams — the two masses and their separation
  • MercuryInitialConditions — Sun-relative starting position and velocity
  • MercPertRunParams — timestep, step limit, tolerances, and optional collision radii
  • plot controls — metres or AU, annotation corner, and optional Jacobi diagnostic

Program Files

main.py
Configuration & Entry Point

Contains the binary parameters, Mercury's Sun-relative initial conditions, numerical controls, collision radii, and plotting options.

physics_mercpert.py
Physics

Defines the nominal astronomical constants, prescribed circular binary motion, conversion from Sun-relative to barycentric initial conditions, Mercury's Newtonian acceleration, distances to the two primaries, and the Jacobi constant.

driver_mercpert.py
Integration

Advances Mercury with an Euler predictor and iterated trapezoidal corrector. Vector-based accuracy tests control timestep rejection; non-converged steps are retried with a smaller timestep. The returned data include positions, velocities, timestep history, and Jacobi constant.

plot_mercpert.py
Plots

Produces the orbit plot and an optional fractional Jacobi-drift plot. The prescribed Sun and companion tracks are dashed and limited to one binary period when the integration runs longer; Mercury is plotted as a solid curve for the full calculation. Filled circles mark the three starting positions, and a black × is reserved for a detected collision. The annotation explicitly identifies the entered Mercury state as relative to the Sun.

Three-Body Setup

MercPert uses the circular restricted three-body approximation. The Sun and companion have finite masses but follow an analytically prescribed circular orbit. Mercury has negligible mass and therefore does not affect either massive body.

Coordinate convention: The integration and plotted trajectories use a barycentric inertial frame whose origin is the Sun–companion centre of mass. However, Mercury's four input values in MercuryInitialConditions are deliberately specified relative to the Sun. The program converts them to the barycentric inertial frame at \(t=0\).

Binary Motion

If the binary separation is \(d\), the common angular velocity is

(1) \[ \omega=\sqrt{\frac{G(M_\odot+M_p)}{d^3}}. \]

The barycentric orbital radii are

(2) \[ r_\odot=\frac{M_p}{M_\odot+M_p}d, \qquad r_p=\frac{M_\odot}{M_\odot+M_p}d. \]

At \(t=0\) the Sun is on the negative \(x\)-axis and the companion is on the positive \(x\)-axis. Their counter-clockwise circular motion is

(3) \[ \mathbf r_\odot(t)= -r_\odot(\cos\omega t,\sin\omega t), \qquad \mathbf r_p(t)= +r_p(\cos\omega t,\sin\omega t). \]

Mercury's Equation of Motion

Mercury experiences a Newtonian gravitational acceleration from both binary members simultaneously. Let \(\mathbf{r} = (x, y)\) be Mercury's position, and define the displacement vectors from Mercury to each binary body:

(4) \[ \boldsymbol{\Delta}_\odot \;=\; \mathbf{r}_\odot(t) - \mathbf{r}, \qquad \boldsymbol{\Delta}_p \;=\; \mathbf{r}_p(t) - \mathbf{r} \]

with scalar separations \(s_\odot = |\boldsymbol{\Delta}_\odot|\) and \(s_p = |\boldsymbol{\Delta}_p|\). Mercury's total acceleration is the vector sum of the two gravitational pulls:

(5) \[ \ddot{\mathbf{r}} \;=\; \frac{G\,M_\odot}{s_\odot^3}\,\boldsymbol{\Delta}_\odot \;+\; \frac{G\,M_p}{s_p^3}\,\boldsymbol{\Delta}_p \]

In component form, separating the \(x\)- and \(y\)-directions, the mercury_acceleration(t, x, y, binary_params) function returns the pair \((a_x, a_y)\) for use at every stage of the predictor–corrector loop.

Time-dependent forcing: The two massive bodies move, so Mercury's acceleration depends explicitly on time as well as position. The corrector must therefore evaluate the acceleration at \(t + \Delta t\), using the primaries' positions at that later time.

Initial Conditions, Collisions & the Jacobi Constant

Sun-Relative Initial Conditions

The values x_init, y_init, vx_init, and vy_init describe Mercury relative to the Sun. At \(t=0\) the program adds the Sun's barycentric position and velocity to obtain the inertial state used by the integrator.

For comparison, a circular orbit around an isolated solar-mass star at radius \(r_0\) would require

(6) \[ v_c=\sqrt{\frac{GM_\odot}{r_0}}. \]

At \(r_0=0.3\,\mathrm{AU}\), this is about \(54.4\,\mathrm{km\,s^{-1}}\). The default \(59.22\,\mathrm{km\,s^{-1}}\) is intentionally different, and the companion further changes the motion.

Finite-Radius Stopping Surfaces

Point-mass gravity itself has no stellar surface. To prevent an orbit from passing through a Sun-like primary without a stopping condition, the default run sets sun_collision_radius = R_SUN, the nominal solar radius. Before an accepted endpoint is committed, the program checks the entire accepted Mercury segment against the Sun's moving finite-radius boundary. This can detect a crossing even when both timestep endpoints lie outside the star. At the first detected crossing, integration stops and the collision point is marked with a black ×.

companion_collision_radius defaults to zero because the companion can represent very different kinds of objects. Give it a physically appropriate positive radius if a particular experiment needs collision stopping there. These radii are numerical termination surfaces, not models of impacts, tidal disruption, accretion, or other physics after contact. Likewise, R_SUN is appropriate only for a Sun-like primary; change or disable it when the primary represents a different kind of object.

Jacobi Constant

Ordinary inertial-frame mechanical energy of Mercury is not conserved because the gravitational potential rotates with the binary. The circular restricted three-body problem does, however, possess the conserved Jacobi constant. In barycentric coordinates,

(7) \[ C= \omega^2(x^2+y^2) +2\!\left(\frac{GM_\odot}{r_\odot} +\frac{GM_p}{r_p}\right) -|\mathbf v_{\rm rot}|^2, \] \[ \mathbf v_{\rm rot} =\mathbf v_{\rm inertial} -\boldsymbol{\omega}\times\mathbf r. \]

In the ideal circular restricted three-body model, \(C\) is exactly conserved because the gravitational potential is stationary in the frame rotating with the binary. Any drift in the computed value is therefore numerical rather than physical. run_mercpert() records \(C\) at every accepted state, and the optional Jacobi-drift plot provides a quantitative numerical-accuracy diagnostic even when the orbit itself looks irregular.

Predictor–Corrector

Each attempted step begins with an Euler predictor. The acceleration is evaluated at the predicted endpoint \(t+\Delta t\), which is essential because the binary potential explicitly changes with time.

Steps that pass the preliminary acceleration-change test are refined with an iterated trapezoidal corrector:

(8) \[ \mathbf v^{n+1} =\mathbf v^n+ \frac{\mathbf a^n+\mathbf a^{n+1}}{2}\Delta t, \] \[ \mathbf r^{n+1} =\mathbf r^n+ \frac{\mathbf v^n+\mathbf v^{n+1}}{2}\Delta t. \]

The endpoint acceleration is recomputed from the refined endpoint and the corrector is iterated. Convergence is tested using the relative change in the velocity vector, avoiding artificial singular behaviour when an individual Cartesian component crosses zero.

If ten iterations are insufficient to meet eps2, the step is rejected, the working timestep is halved, and the same step is attempted again.

Adaptive Timestep

The preliminary timestep gate measures the relative vector change in acceleration between the start of the step and the Euler-predicted endpoint:

(9) \[ \Delta_a= \frac{\|\mathbf a_{\rm pred}-\mathbf a_n\|} {\max(\|\mathbf a_{\rm pred}\|,\|\mathbf a_n\|)}. \]

If \(\Delta_a>\varepsilon_1\), the attempt is rejected and the working timestep is halved. After a successful step the timestep is allowed to grow by 10% toward the user-specified maximum dt. This prevents one close encounter from forcing an unnecessarily tiny timestep for the entire remainder of a long calculation.

Convergence Criteria

ParameterDefaultRole
eps10.05 Maximum relative acceleration-vector change allowed by the predictor gate.
eps20.0001 Required relative convergence of successive corrected velocity vectors.

Smaller values generally increase numerical accuracy at greater computational cost. Because some restricted three-body trajectories are sensitive to initial conditions, long-term point-by-point agreement is not by itself a reliable accuracy test. Compare finite-time trajectories and, especially, monitor the Jacobi-constant drift.

Output

plot_orbits() displays the calculation in the barycentric inertial frame with equal x/y scale. The dashed red and dashed green curves are the prescribed Sun and companion reference orbits. If the calculation lasts longer than one binary period, those reference tracks are limited to one complete revolution so repeated dashed segments do not overplot and distort one another. The solid blue curve is Mercury's trajectory for the full integration.

Small filled circles mark the Sun, companion, and Mercury positions at \(t=0\). Ordinary run endpoints are not specially marked. A black × appears only when a configured finite-radius collision terminates the calculation. The legend therefore labels the curves “Sun's orbit,” “Companion's orbit,” and “Mercury.”

MercPertOutput contains time, both primary trajectories, Mercury position and velocity, accepted timestep history, and the Jacobi constant. The initial sample is included, followed by one sample after each accepted step; a run that reaches max_steps therefore returns max_steps + 1 samples.

Set show_jacobi_diagnostic = True in main.py to display fractional Jacobi-constant drift versus time. Positions may be displayed in metres or AU.

Example Gallery

These examples use the Sun-relative initial-condition convention described above. The dashed red and green curves show the prescribed reference orbits of the two massive bodies, while Mercury's calculated trajectory is solid blue. Unless a collision is explicitly marked, an intersection of two plotted curves does not imply that the corresponding bodies occupied that point at the same time.

Perturbed bound orbit. With Mercury starting 0.3 AU from the Sun at 56 km/s, the companion drives conspicuous apsidal precession. The orbit remains bounded, but it no longer closes as a simple Kepler ellipse.
Large regular rosette. A faster start at 1 AU produces an extended, orderly multi-lobed trajectory. Strong perturbation does not necessarily imply immediate instability or chaotic-looking motion.
Collision with the Sun. After several close passages, Mercury reaches the nominal solar radius. The black × marks the first detected crossing of the Sun's moving finite-radius boundary, where the integration terminates.
Retrograde motion. In the scenario illustrated here, Mercury's chaotic motions include short loops where Mercury moves in a retrograde sense.
Ejection. After several strongly perturbed revolutions, a gravitational encounter transfers Mercury onto a much larger outward trajectory. This provides a clear contrast with continued bound motion and collision.

Suggested Experiments

The experiments are arranged in approximate order of difficulty, from introductory parameter changes to an advanced investigation near \(L_1\). Keep a record of the parameters used for each run so that your comparisons can be reproduced.

1 · A Quieter Baseline Orbit (Introductory)

At \(0.3\,\mathrm{AU}\) from a solar-mass star, the isolated circular speed is about \(54.4\,\mathrm{km\,s^{-1}}\). Try that Sun-relative velocity and compare its perturbations with the default \(59.22\,\mathrm{km\,s^{-1}}\).

2 · Companion-Mass Sequence (Introductory)

Reduce m_planet_solar from 0.1 toward a genuine giant-planet mass and observe how the stability region changes. Jupiter itself is about \(9.5\times10^{-4}\,M_\odot\), giving a useful lower-end reference. The default 0.1-solar-mass companion is deliberately extreme and belongs to the low-mass stellar regime.

3 · Retrograde Orbits (Introductory–Intermediate)

Reverse the sign of Mercury's Sun-relative transverse velocity and compare the stability of retrograde trajectories with otherwise identical prograde trajectories. Use the same integration length and accuracy settings for each pair.

4 · Extend the Default Run Toward a Close Encounter (Intermediate)

Run the 10,000-step defaults first as a baseline. Then increase max_steps gradually — for example to 40,000, 60,000, and 100,000 — and watch for the onset of stronger perturbations and close encounters. Also try small changes in x_init or vy_init. Compare the orbit shapes and the maximum fractional Jacobi drift. Very close encounters are numerically demanding, so a large drift is a signal to repeat the experiment with tighter accuracy settings; strongly different long-term paths by themselves do not prove numerical failure.

5 · Numerical Convergence (Intermediate)

Repeat the same physical setup with smaller dt and tighter eps1/eps2; for example, try eps1 = 0.01 and eps2 = 1e-5. To compare the same physical interval after changing dt, adjust max_steps as needed and verify the final times. Compare the trajectories over that common interval and compare the maximum fractional Jacobi drift. Set show_jacobi_diagnostic = True if you also want the drift plot. The Jacobi diagnostic is especially useful when later portions of two sensitive trajectories diverge visibly.

6 · Map a Finite-Time Stability Boundary (Advanced)

Hold the binary fixed and try a sequence of Mercury starting radii. For a stated integration time, classify each trajectory by explicit criteria: continued bounded motion, collision, or escape beyond a distance you choose in advance. Estimate where the transition occurs. A handful of carefully chosen manual trials is enough for a first map, but do not call the result an absolute stability limit: the classification depends on the integration duration, and sensitive boundaries need not be perfectly sharp.

7 · Equal-Mass Binary and Circumbinary Orbits (Advanced)

Set both massive bodies to \(1\,M_\odot\) and choose a separation near 1 AU. Search for long-lived orbits far outside the binary as well as unstable trajectories between the two stars. For a fixed integration duration, compare the smallest long-lived circumbinary orbit you can find with the binary separation. Explain why the experiment establishes finite-time survival rather than permanent stability.

8 · Roche-Lobe / L1 Test-Particle Experiment (Capstone)

For an unequal-mass binary, place Mercury at different starting points on the line between the two bodies. Compute the binary angular velocity \(\omega\), set y_init = 0 and vx_init = 0, and assign the Sun-relative velocity required for local co-rotation, vy_init = omega * x_init. Explore the dividing region between trajectories that remain associated with one primary and those transferred toward the other. This is a test-particle analogue of motion near the inner Lagrange point \(L_1\), not a complete model of gas transfer: real gas also develops pressure, shocks, dissipation, and radiation. If the primary is changed from a Sun-like star to a compact object such as a black hole, set sun_collision_radius to zero or to a physically appropriate stopping radius rather than leaving it at R_SUN.

Restoring Default Parameter Values

If you edit main.py or another program file while experimenting, you can restore the original program files using any of the following methods:

  • Same session: Press Ctrl+Z (Windows) or Cmd+Z (macOS) repeatedly in your editor to undo your edits.
  • If you are using PyCharm: Right-click the edited file in the Project panel → Local History → Show History → select a version from before your changes → click Revert.
  • Full reset: Re-download the ZIP from github.com/tomyee3-org/GFTGU-Programs and replace this program's folder with the fresh copy.

For additional ways to restore program files, see the corresponding recovery instructions in the GFTGU Python Setup Guide.
