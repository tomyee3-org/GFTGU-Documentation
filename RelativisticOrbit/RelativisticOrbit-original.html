Overview

RelativisticOrbit integrates the equatorial trajectory of a negligible-mass test particle around a one-solar-mass, non-rotating, spherically symmetric source. In model="schwarzschild" the program uses an exact Newtonian-looking rewriting of the spatial Schwarzschild geodesic equations when the independent variable is the particle's own proper time \(\tau\). A "newtonian" mode is provided for direct comparison.

The displayed curve uses \(x=r\cos\phi,\ y=r\sin\phi\), where \(r\) is Schwarzschild areal radius and \(\phi\) is azimuth. These are convenient diagram coordinates, not global Cartesian coordinates of a flat spatial geometry.

Relativistic bound orbits generally precess rather than close. The program records periapsides automatically, estimates the mean apsidal advance, and reports numerical drift in the conserved specific angular momentum and in the effective energy integral of the equation being integrated.

Free fall: The quantity called “acceleration” in the code is \(d^2(x,y)/d\tau^2\), a coordinate second derivative used to integrate the orbital diagram. A freely falling test particle has zero physical proper acceleration.

Quick Start

Requirements

Python 3.10 or later with matplotlib.

python -m pip install matplotlib

Running

cd GFTGU-Programs/RelativisticOrbit
python main.py
python main.py --model newtonian --max_orbits 3 --max_steps 7000
python main.py --u_init 1.044e8 --show_periapsides --max_steps 12000

Run python main.py --help for descriptions and defaults. Set each input as --name value; for example python main.py --x_init 15000 --u_init 1.2e8 --dt 2e-6. Omit flags to use the shipped parameters. --no-show_isco hides the ISCO circle; --show_periapsides displays radial minima.

The default starts at \(r=1.5\times10^4\) m with \(dy/d\tau=1.2\times10^8\) m/s. Here \(dy/d\tau\) is a derivative with respect to the particle's proper time; it is not the local physical speed measured by a stationary observer.

After the run, the console reports why the integration stopped, accepted steps, accumulated azimuthal revolutions, detected periapsides, and conservation drift. If periapsides are found, it reports the smallest and largest periapsis radius, and if at least two are found, the mean periapsis advance per radial period. It then prints a block headed predicted from the constants of motion, worked out from x_init and u_init without integrating: the circular value of \(dy/d\tau\) at the starting radius, whether the orbit is bound, circular, plunges or escapes, its periapsis and apoapsis radii, its exact apsidal advance and, in Schwarzschild mode, the weak-field value \(6\pi GM/(c^2p)\).

Stopping limits: max_steps is a hard safety cap. A run can therefore stop at max_steps before it reaches max_orbits; this is normal when the requested number of revolutions requires more accepted steps. Increase max_steps if you want the integration to continue longer (for example, --max_steps 12000).

Main user controls

  • --x_init — starting areal radius on the +x diagram axis
  • --u_init — initial \(dy/d\tau\)
  • --dt — maximum proper-time integration step
  • --max_steps — maximum accepted steps
  • --max_orbits — maximum accumulated azimuthal revolutions
  • --eps1, --eps2 — timestep and corrector tolerances
  • --model — "schwarzschild" or "newtonian"
  • --show_isco / --no-show_isco — show/hide the true Schwarzschild ISCO circle
  • --show_periapsides / --no-show_periapsides — mark automatically detected periapsides

Program Files

main.py
Entry Point & Configuration

Holds the user-editable initial conditions, numerical tolerances, Schwarzschild/Newtonian switch, and plotting options. It prints the run summary, the Schwarzschild horizon and ISCO radii (five significant figures), precession/conservation diagnostics, and the orbit predicted from the constants of motion.

physics_relativistic_orbit.py
Physics Engine

Defines the nominal solar gravitational parameter, exact SI speed of light, Schwarzschild horizon/ISCO/photon-orbit radii, the orbital acceleration, circular-orbit proper-time speed, conserved-quantity diagnostic functions, and predict_orbit(), which finds the orbit's turning points and its exact apsidal advance from the constants of motion.

driver_relativistic_orbit.py
Adaptive Integrator

Validates inputs, advances the orbit with an iterated predictor-corrector, rejects unconverged steps, allows timestep recovery, unwraps azimuth for revolution counting, interpolates the first horizon crossing, detects periapsides, and records the termination reason.

plot_relativistic_orbit.py
Plotting

Draws the orbital diagram with equal spatial scales. The horizon is always shown at its true coordinate radius; a separate marker denotes the central mass. The ISCO and detected periapsides are optional.

Schwarzschild Geometry

Outside a non-rotating spherical mass, the vacuum geometry is the Schwarzschild spacetime. For the one-solar-mass source used here,

\[ r_s=\frac{2GM_\odot}{c^2}\approx 2.953\times10^3\ {\rm m}. \]

The program uses Schwarzschild areal radius \(r\): a sphere at coordinate radius \(r\) has area \(4\pi r^2\). The orbital diagram then maps \(r,\phi\) to \(x=r\cos\phi,\ y=r\sin\phi\) for visualization.

Schwarzschild coordinate time is not the independent variable of this program. The integration advances the particle's proper time \(\tau\).

General-Relativistic Effective Acceleration

For equatorial timelike Schwarzschild geodesics, the spatial orbit can be written in the Newtonian-looking proper-time form

\[ \frac{d^2\mathbf r}{d\tau^2} = -\frac{GM}{r^3} \left(1+\frac{3h^2}{c^2r^2}\right)\mathbf r, \]

where \(h=r^2d\phi/d\tau\) is the conserved specific angular momentum. The additional \(1/r^4\) radial-force term produces apsidal precession. In weak fields it is often discussed as the leading relativistic correction to Newtonian motion, but the equation used here is not merely a truncated post-Newtonian force law: with proper time as parameter it is an exact rewriting of the Schwarzschild spatial geodesic equation.

Coordinate acceleration: \(d^2\mathbf r/d\tau^2\) should not be confused with an accelerometer reading. The test particle is in free fall and has zero proper acceleration.

Angular-Momentum Constants

The initial conditions are \(x=x_0,\ y=0,\ dx/d\tau=0,\ dy/d\tau=u_0\). Therefore the conserved specific angular momentum is

\[ h=x_0u_0. \]

Let \(h=r^2d\phi/d\tau\). In the notation \(K=h/2\) and \(Q=12K^2/c^2\), one has \(Q=3h^2/c^2\).

The driver independently recomputes \(h=x\,dy/d\tau-y\,dx/d\tau\) along the numerical trajectory and reports its maximum fractional drift as an accuracy diagnostic.

Orbital Precession

A bound Schwarzschild orbit generally has two different periods: the azimuth can advance by \(2\pi\) before the particle has returned from one periapsis to the next. The angular excess between successive periapsides is the apsidal advance.

RelativisticOrbit automatically looks for local minima of \(r=\sqrt{x^2+y^2}\). If two or more periapsides are present, the console reports

\[ \Delta\phi_{\rm advance} = |\phi_{p,n+1}-\phi_{p,n}|-2\pi . \]

In the weak-field limit this can be compared with the familiar Schwarzschild approximation

\[ \Delta\phi \approx \frac{6\pi GM}{a(1-e^2)c^2} \]

for an orbit of semimajor axis \(a\) and eccentricity \(e\).

Printed advance versus the weak-field formula: the measured console value is a diagnostic of the integrated trajectory. The console prints the exact advance of the orbit being integrated, and the weak-field value, separately under predicted from the constants of motion; the difference between the measured and exact values is numerical error. In the Mercury-scale weak-field regime that analytic signal is smaller than the apsidal error typical of this educational integrator. See exercise 10.
Two different counters: max_orbits limits accumulated azimuthal revolutions. The periapsis detector measures radial periods. In a precessing orbit these are not identical.

Event Horizon, Circular Orbits, and the ISCO

For a Schwarzschild source, \(r_s=2GM/c^2\) is the horizon and \(r_{\rm ISCO}=6GM/c^2=3r_s\approx8.860\times10^3\ {\rm m}\) is the innermost stable timelike circular orbit.

Timelike circular geodesics also exist in the interval \(3GM/c^2<r<6GM/c^2\), but they are unstable. No timelike circular geodesic exists at or below the photon-orbit radius \(3GM/c^2\approx4.430\times10^3\ {\rm m}\).

For this program's proper-time initial derivative, the exact circular value is

\[ u_{\rm circular} = \sqrt{\frac{GM}{r-3GM/c^2}}, \qquad r>3GM/c^2. \]

This quantity is \(dy/d\tau\), not a locally measured physical speed, so it is not constrained to remain below \(c\). Its divergence as \(r\rightarrow3GM/c^2\) reflects the fact that a timelike circular geodesic cannot reach the photon orbit.

A geodesic inside the ISCO does not automatically “decay.” This program contains no radiation reaction. Depending on its constants of motion, a particle can plunge, execute several near-circular whirls before plunging, or pass to periapsis inside the ISCO and return outward.

The driver detects the first intersection of an accepted path segment with the true horizon circle and stops there. Position, velocity, and time at that event are estimated by linear interpolation along the last accepted segment, so an excessively large timestep can make the event record less precise. Because the interpolated endpoint is not itself an accepted solution state, it is excluded from the reported conservation- drift maxima. The plot never enlarges the horizon merely to make it visible; a separate central marker identifies the origin in weak-field plots.

Predictor–Corrector

Each attempted proper-time step begins with a constant-acceleration predictor for position and velocity. If the acceleration-change test passes, an iterated trapezoidal corrector refines both:

\[ \mathbf v^{n+1} = \mathbf v^n+\frac{\mathbf a^n+\mathbf a^{n+1}}{2}\Delta\tau, \qquad \mathbf r^{n+1} = \mathbf r^n+\frac{\mathbf v^n+\mathbf v^{n+1}}{2}\Delta\tau . \]

The endpoint acceleration is recomputed from each refined position. Corrector iteration is capped at ten passes. If it has not converged by then, the entire attempted step is rejected, the timestep is halved, and the step is retried.

Adaptive Timestep

The predictor's acceleration vector is compared with the start-of-step acceleration using the rotationally invariant Euclidean norm,

\[ \delta_a= \frac{\|\tilde{\mathbf a}-\mathbf a^n\|} {\max(\|\tilde{\mathbf a}\|,\|\mathbf a^n\|)}. \]

If \(\delta_a>\varepsilon_1\), the attempted step is discarded and \(\Delta\tau\) is halved. After a successful step, the working timestep grows by 10% toward the user's dt, which acts as the maximum allowed timestep. Thus a short close passage does not permanently force the rest of the run to use its smallest timestep.

A retry limit prevents pathological initial conditions from causing endless timestep halving.

Revolution Counting

The driver computes \(\phi=\operatorname{atan2}(y,x)\), unwraps the change in azimuth at every accepted step, and accumulates the signed angular travel.

\[ N_{\rm rev}=\frac{|\Delta\phi_{\rm accumulated}|}{2\pi}. \]

This method counts accumulated azimuthal travel directly, so it works for precessing orbits and for either direction of motion. Integration stops when the accumulated revolution count reaches max_orbits, unless the horizon or max_steps is reached first. Because the condition is tested after each accepted step, the reported count can exceed the requested limit by a small fraction of one step.

Convergence and Numerical Diagnostics

QuantityDefaultRole
eps10.05Maximum fractional acceleration-vector change allowed by the predictor gate.
eps21e-4Required fractional convergence of successive corrected velocity vectors.

The program requires \(0<\varepsilon_2<\varepsilon_1<1\). An unconverged corrector step is rejected: the timestep is halved and the step is retried.

Two conserved quantities provide additional checks. The driver reports maximum fractional drift in \(h=x\,dy/d\tau-y\,dx/d\tau\) and in the effective energy integral

\[ \mathcal E_{\rm eff} = \frac12\left[\left(\frac{dx}{d\tau}\right)^2+ \left(\frac{dy}{d\tau}\right)^2\right] -\frac{GM}{r} -\frac{GMh^2}{c^2r^3} \]

for Schwarzschild mode. In Newtonian mode the final \(-GMh^2/(c^2r^3)\) term is omitted. These are diagnostics of the integrated orbital equation; \(\mathcal E_{\rm eff}\) should not be mistaken for a local observer's measured kinetic-plus-potential energy.

A fractional drift is undefined when the initial conserved value is exactly zero. In that exceptional case the program reports zero if the numerical value remains exactly zero and infinity if it does not.

Suggested Scenarios

How to use these exercises: work roughly from top to bottom; the sequence moves from simple observation to progressively more demanding strong-field experiments. Here periapsis means the closest approach in a radial cycle. The plotted \(x,y\) values are diagram coordinates built from Schwarzschild areal radius and azimuth, not global flat-space Cartesian coordinates. Run the commands below from the program folder; some experiments require inspecting returned arrays or calculating a physical speed with the physics module in addition to choosing command-line inputs.
Choosing a starting timestep: for a near-circular orbit, a useful first estimate for \(N\) samples per revolution is \[ \Delta\tau \sim \frac{2\pi r}{uN}. \] Adaptive stepping will reduce this automatically where the dynamics require finer resolution. Very large dt or extreme initial derivatives can force repeated timestep rejection or make diagnostics less accurate.
1. Default Strong-Field Rosette — Introductory
python main.py --show_periapsides
Run the supplied defaults. Then set --show_periapsides. Do successive periapsides occur at the same angle? Compare their rotation with the printed mean apsidal advance. Also note whether the run stops at max_steps or max_orbits.
2. Regularity of the Rosette — Introductory
python main.py --max_steps 6000 --show_periapsides
The command marks periapsides visually. Their numerical radii are in result.periapsis_radius and need a short script or an interactive Python session to inspect. Inspect result.periapsis_radius for a bound precessing run. Verify that successive minimum radii remain nearly the same, within the numerical resolution of the calculation. The orbit changes orientation even though its radial pattern remains regular.
3. GR vs. Newtonian — Introductory
python main.py --model schwarzschild --max_orbits 3 --max_steps 7000
python main.py --model newtonian --max_orbits 3 --max_steps 7000
Run identical initial conditions twice, changing only model="schwarzschild" to "newtonian". The Newtonian bound orbit should be nearly closed, while the Schwarzschild orbit precesses. What changes in the orbit, and what remains the same about the initial data?
4. Fall In or Escape — Introductory
python main.py --u_init 1.044e8 --dt 1e-7 --eps1 0.005 --eps2 1e-6 --max_steps 12000
python main.py --u_init 1.8e8 --max_steps 12000
Starting from the default data, reduce u_init until the orbit crosses the horizon, then increase it until the particle escapes rather than remaining bound. Use modest changes first, then narrow the transition. A plunge is labeled horizon; the program has no separate escape detector, so an outward-moving escape trajectory normally runs until max_steps. Confirm escape by increasing max_steps and checking that the radius continues to grow.
5. Circular Geodesics — Intermediate
python main.py --x_init 11813.0003044 --u_init 134071263.04595 --max_orbits 4 --max_steps 8000
python main.py --x_init 7383.12519025 --u_init 212197265.2804 --dt 1e-7 --max_steps 8000
The first command uses the circular derivative for an 8GM/c² orbit, evaluated with circular_proper_time_speed(r). The second is a slightly perturbed orbit at 5GM/c². For other radii, calculate circular_proper_time_speed(r) from the physics module. Compare a stable circular orbit above \(6GM/c^2\) with an unstable circular orbit between \(3GM/c^2\) and \(6GM/c^2\). For the unstable case, multiply the exact circular value by about 1.001 and follow the departure over many steps. Try perturbations on both sides of the exact value.
6. Numerical Convergence — Intermediate
python main.py --show_periapsides --max_steps 6000
python main.py --dt 1e-6 --eps1 0.02 --eps2 1e-5 --show_periapsides --max_steps 12000
Tighten eps1 and eps2 and/or reduce dt. Compare the measured apsidal advance and the reported angular-momentum and effective-energy drift. A trustworthy physical result should settle toward a stable value as the numerical controls are tightened.
7. Inside the ISCO — Intermediate
python main.py --x_init 20000 --u_init 8e7 --show_periapsides --max_steps 8000
Search for an eccentric orbit whose periapsis lies inside \(6GM/c^2\) but which still returns outward. A useful strategy is to start at 20000 m with the command above and vary --u_init in small increments. This example returns from a periapsis of about 7565 m, inside the ISCO (the printed prediction gives 7564.95 m); at the default step size the integrated periapsides lie near 7476 m, about 89 m too deep, and they move to the predicted value when --dt, --eps1 and --eps2 are reduced (for example --dt 2e-7 --eps1 0.01 --eps2 1e-6 --max_steps 20000). Use result.periapsis_radius to check how far inward the orbit actually reached. This shows why crossing the ISCO does not by itself imply immediate plunge.
8. Toward the Photon Orbit — Advanced
python main.py --x_init 5000 --u_init 2e8 --dt 1e-7 --max_steps 10000
Explore bound or near-capture trajectories with closest approach moving toward \(3GM/c^2\) from above. Watch how much azimuth can accumulate during a close passage. Timelike circular geodesics cease to exist at and below \(3GM/c^2\), so this experiment becomes increasingly sensitive as that radius is approached.
9. Zoom-Whirl / Plunge — Advanced
python main.py --u_init 1.044e8 --dt 1e-7 --eps1 0.005 --eps2 1e-6 --max_steps 12000 --show_periapsides
Tune u_init near the boundary between capture (plunge) and a bound or escaping orbit. Some trajectories execute several near-circular whirls before crossing the horizon. Expect fine tuning: narrow the interval in u_init gradually and keep an eye on the conservation diagnostics.
10. Weak-Field Precession — Advanced
python main.py --x_init 1e6 --u_init 1.153e7 --dt 1e-4 --max_steps 20000 --show_periapsides
python main.py --model newtonian --x_init 1e6 --u_init 1.153e7 --dt 1e-4 --max_steps 20000 --show_periapsides
The two commands give a first qualitative comparison; matching precise orbital elements or measuring Mercury-scale advance requires additional numerical analysis. Move the starting radius outward and choose a correspondingly weaker bound orbit. Verify qualitatively that Schwarzschild precession becomes smaller as the field weakens. The goal of this exercise is that trend, not a numerical recovery of Mercury's 43 arcsec/century. Mercury's relativistic advance is only about \(5\times10^{-7}\) rad per orbit. The educational adaptive predictor-corrector used here was not designed as a weak-field precession meter. On a Mercury-scale run the printed mean periapsis advance is often larger than that analytic signal and can even have the wrong sign. A Newtonian control at the same elements is the necessary check: if that control also reports a comparable "advance," the number is integrator wander (timestep truncation, periapsis sampling on a discrete trajectory), not general relativity.

Schwarzschild vs. Newtonian

The two modes use the same initial diagram coordinates and proper-time derivative values. Newtonian mode removes the relativistic \(3h^2/(c^2r^2)\) force factor:

\[ \mathbf a_{\rm N}=-\frac{GM}{r^3}\mathbf r, \qquad \mathbf a_{\rm Schw}= -\frac{GM}{r^3} \left(1+\frac{3h^2}{c^2r^2}\right)\mathbf r . \]

This switch is intended as a controlled numerical experiment. In the Newtonian model there is no physical Schwarzschild horizon or ISCO, so those reference circles and their summary radii are omitted. In Schwarzschild mode the printed summary reports both radii in metres to five significant figures, regardless of whether the ISCO plot circle is hidden.
