Release Status

The two latest code-changing rounds remain the Audit 22 response (1.4.0) and the Audit41 circular-speed boundary correction (1.5.0). RO1 is covered: the Help explains that Schwarzschild exterior geodesics also apply outside an idealized spherical, non-rotating star, distinguishes impact on a material surface from horizon crossing, and states that the module has no stellar-radius or surface-impact option.

Major Improvements in This Release

  • The merged Help replaces the separate active short and extended tutorials. It uses the common Help File title, Gravity from the Ground Up badge, plot tip, license and footer, with nine Beats and twelve Suggested Experiments.
  • The description now explicitly covers the Schwarzschild exterior of a spherical star and the absence of material-surface stopping in this program (RO1).
  • Beat 0 displays the baseline settings; later comparisons spell out the defaults being changed or make the comparison run's settings explicit. These command edits retain the original numerical inputs.
  • A compact Reading the output section distinguishes integration termination from predicted orbit type, sampled periapsides from ideal turning points, and exact advance from its weak-field approximation.
  • The Beats retain their measured and predicted comparisons, full-precision circular input, ISCO qualification for eccentric paths, true and numerically false plunges, convergence checks, Mercury-resolution warning and rejected inside-horizon input. Beat-to-experiment links and the parameter reference remain.
  • The detailed extended tutorial's equation derivations, algorithm and program-file sections were condensed into the merged Help's explanations; they are no longer separate active Help pages.
  • The Sample Outputs Guide now accompanies RelativisticOrbit.html, uses current Beat commands and headings, and embeds nine fresh plots from the unchanged released build. Its circular-orbit comparison explicitly identifies the predicted advance as the small-radial-disturbance limit.

The existing 1.5.0 code improvement remains the exact floating-point-input domain check in circular_proper_time_speed(), including the rounded photon-orbit constant and its adjacent representable radius. No console or graphical program output changed in this documentation update.

Known Limitations

  • One equatorial test particle and a fixed, non-rotating, one-solar-mass source; no spin, radiation reaction or back-reaction.
  • No stellar-radius or material-surface impact option. Applying the vacuum exterior model to a star requires remaining outside its surface.
  • The plot uses areal radius and azimuth as flat polar diagram coordinates. --u_init is a proper-time coordinate rate, not a locally measured speed.
  • Periapsides are sampled at accepted steps. Mercury-scale advance is predicted but cannot be resolved at the documented integration settings.
  • Default steps can produce a false plunge near the bound/plunge boundary. Drift maxima omit the interpolated horizon endpoint, and a turn-count stop can overshoot by part of a step.
  • No escape detector; an escaping trajectory stops at a step or turn limit. Help equations require online MathJax; the Python program runs offline.

Major Improvements in This Release

Version 1.4.0 (Audit 22 response, and a Help correction after Audit 23):

  • The Beats Help now says that the circular dy/dtau line is rounded to six significant figures and that a circular start needs the full value (Codex Audit 23 item 1); Experiment 6 prints each radius and circular speed in full. The program and its build are unchanged.
  • A start is predicted to be circular only when --u_init is within a few units in its last digit of the circular speed; any larger change of speed now gets its true prediction (for example plunge or bound), and circles close to, but not at, 6GM/c2 are no longer called the ISCO.
  • circular_proper_time_speed() is accurate to rounding close to 3GM/c2.
  • The Beat 4 command and Exercise 5 of RelativisticOrbit-original.html use the full circular speed 134071263.04595919; the former 14-digit value 134071263.04595 now prints motion : bound instead of circular (stable).
  • New public constants CIRCULAR_ULPS (8) and ISCO_ULPS (4) replace CIRCULAR_TOLERANCE and ISCO_TOLERANCE of 1.3.0.

Version 1.3.0 (Audit 21 response):

  • A start exactly on the ISCO circle prints motion : circular (marginally stable), with no advance line; it previously printed plunge.
  • weak_field_advance() gives finite values for very large radii (it returned 0 or NaN), and a turning point too large to represent prints motion : not predicted (...) instead of stopping with a traceback.

Version 1.2.0 (Kickoff2, not released separately):

  • Every run prints a periapsis radius line and a block predicted from the constants of motion: the circular dy/dtau at the starting radius, the kind of orbit with its turning points, the exact apsidal advance and the weak-field value 6πGM/(c2p). The previously printed lines are unchanged.
  • New public function predict_orbit(); result objects are frozen, with tuples in place of lists; the parser is available as build_parser().
  • New Beats tutorial Help, RelativisticOrbit-extended.html, with nine beats and 12 experiments; the Reference Guide Help is retained, kept current, as RelativisticOrbit-original.html. Its Exercise 7 now gives the periapsis as about 7565 m (7476 m at the default step), and both Exercise 10 commands use --max_steps 20000 so that the Newtonian control prints an advance.

Known Limitations

  • A single test particle around a fixed, non-rotating mass of one solar mass; no spin, radiation reaction or back-reaction.
  • The x-y plot draws areal radius and angle as flat polar coordinates; --u_init is a proper-time rate, not a measured speed.
  • The measured apsidal advance comes from periapsides at accepted steps; a Mercury-scale advance can be predicted but not measured.
  • Close to the hole the default step is coarse; near the plunge boundary the integrated fate can differ from the prediction (--u_init 1.045e8 crosses the horizon at the default settings).
  • There is no escape detector; an escaping run stops at --max_steps.
  • The turn count can overshoot --max_orbits by a fraction of one step.
  • The horizon end point is linearly interpolated and is left out of the drift maxima.
  • predict_orbit() treats a start within 8 units in the last digit of the circular speed as circular, and a circle within 4 units in the last digit of 6GM/c2 as the ISCO.
  • The equations in the Help are typeset by MathJax and need an internet connection.

Known Minor Maintenance Items

  • MathJax is not bundled for offline use.
  • The current Help sidebar labels Beat 2 “Read the prediction first”, while its heading says “The advance, predicted exactly”. The supplied Help is unchanged in this package.
  • The build identifier reads unpackaged when the physics module is loaded without the other core files.
  • RelativisticOrbit-original.html and RelativisticOrbit-extended.html are both present, and neither is marked as the current Help.
  • There is no option to save a figure or the orbit data to a file.
  • The DOP853 oracle can be regenerated only where SciPy is installed.
