Release Status

Version 1.0.3 concludes a kickoff maintenance review followed by three rounds of independent review involving Codex, Copilot, and Gemini. The reviewers compared the Python implementation with Schutz's original Java source, verified the Schwarzschild and Newtonian equations, numerical behavior, validation and error handling, Help-file accuracy, Version/Build synchronization, and regression coverage. No release-blocking defect remains. The program is approved as a release candidate and is sufficiently robust and accurate for student use within the tutorial scope and limitations described below.

Major Improvements in This Release

  • Verified that the Schwarzschild mode correctly implements Schutz's proper-time equation, including the equivalence of Schutz's K and Q notation to the program's specific angular momentum h.
  • Made main.py safe to import without automatically running a simulation or opening a plot, while retaining student-editable parameters and normal script behavior.
  • Added consistent validation for Boolean, non-real, non-finite, out-of-range, singular, overflow-prone, and underflow-prone inputs in both the public physics functions and simulation driver.
  • Added explanatory errors for corrector exhaustion and for timesteps too small to advance floating-point proper time.
  • Corrected zero-reference conservation-drift handling so an unchanged zero invariant reports zero and a changed zero reference reports an undefined relative error rather than a dimensionally incorrect absolute difference.
  • Improved horizon-event handling by interpolating position, velocity, and proper time at the true Schwarzschild horizon and excluding that interpolated event record from accepted-state conservation-drift maxima.
  • Added independent SciPy DOP853 endpoint and apsidal-advance reference values, second-order Newtonian convergence testing, adaptive rejection/recovery tests, and near-photon-orbit boundary coverage.
  • Corrected the Help file's revolution-count equation, termination description, historical implementation wording, characteristic-radius values, horizon-event semantics, and Python requirement.
  • Documented and regression-tested the requirement for Python 3.10 or later, matching the syntax used by the delivered source.
  • Added BUILD_ID provenance across the four core program modules and synchronized it with the Help file and runtime output.

Test Suite Growth

A new 43-test regression suite was created at kickoff and expanded to 61 automated tests during the audit process. An additional 80-case deterministic adversarial sweep varied both physical models, starting radius, direction and magnitude of transverse velocity, and timestep.

The final suite verifies equations, constants, characteristic radii, circular-orbit conditions, effective energy, input validation, numerical safety guards, adaptive predictor-corrector behavior, horizon events, orbit counting, periapsis detection, conservation diagnostics, convergence order, independent strong-field numerical oracles, plotting, command-line behavior, Help structure and scientific content, Python-version compatibility, and Build-ID reproduction. All 61 tests pass in both the canonical tests/ layout and a flattened upload layout. All 80 adversarial cases completed through documented termination paths with finite, equal-length, strictly time-ordered state arrays.

Known Limitations

  • Intended for education and conceptual exploration rather than precision orbit prediction or research-grade relativistic dynamics.
  • The model treats a negligible-mass test particle around a one-solar-mass, non-rotating Schwarzschild source. It does not include black-hole spin, radiation reaction, or back-reaction by the orbiting body.
  • The classroom defaults preserve Schutz's original parameters and normally reach the 6,000-step safety limit after approximately 9.285 azimuthal turns, before the nominal ten-orbit limit.
  • The accepted-step predictor-corrector method accumulates phase error under the deliberately loose classroom defaults. Quantitative work should repeat the calculation with smaller timesteps and tighter tolerances.
  • The max_orbits stopping point can overshoot its target by a small fraction of one accepted step.
  • Periapsides are estimated from local minima among accepted integration points rather than from dense-output event solutions.
  • The final horizon record is obtained by linear interpolation along the last accepted segment. It is retained for plotting and termination reporting but is not treated as an accepted solution state in conservation-drift maxima.
  • There is no separate escape-event classifier. An apparently escaping orbit normally terminates at max_steps; continued outward radial growth should be checked after increasing that limit.
  • The Help file loads MathJax from a public CDN. Offline, its prose and raw equation source remain available, but equations appear as untypeset LaTeX.

Known Minor Maintenance Items

  • The source and tests parse under the Python 3.10 grammar, but the final audit environment ran Python 3.12.13. Executing the complete suite on an actual Python 3.10 interpreter remains a desirable non-blocking release check.
  • A future documentation-wide overhaul may bundle MathJax locally if fully typeset offline Help becomes a distribution requirement.
  • The independent DOP853 oracle values and generation settings are preserved in the regression suite, but the separate oracle-generation script is not part of this release.
